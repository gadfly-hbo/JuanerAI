## 2. 真正改变的可见含义

| 原位置 | 本次必要调整 | 不能被理解为 |
| --- | --- | --- |
| 数字／结论／建议三项状态 | 数字核验保持原范围；结论／建议明确为“审查判断”。四判断标签仍为有支持／有条件支持／证据不足／存在冲突 | 一次“有支持”让整份报告或任意语义认证通过 |
| 报告、依据、导出与人的下一步 | 紧邻状态显示“基于当前证据的模型审查判断，不是全面认证；已知冲突和未满足条件仍限制选择” | 有免责声明即可发布已知错误、改掉数字partial，或用户须自己补齐报告 |
| 原稿附加动作审核情境 | 更名为“附加动作被审查识别（合成）”，说明预写情境中确已发现并修订，不代表共同误判时宿主必然排除 | 本静态稿已具备自动理解／阻断任何附加行动的机制 |
| 原型／F107历史详情 | 只读显示原审查曾返回支持、外部验收仍为FAIL，以及原稿／受控形成对象的区别；无当前采用入口 | 改保证后旧FAIL已改PASS，或本页新增了自动检测器 |
| 名称／引用说明 | 用已有详情展示带来源的原文，明确其是数据不是支持动作；实现应统一分离来源文字与建议语句 | 引号／转义能确定性净化中文语义，或名字文字可赋予业务权限 |

建议常驻短文案：**“结论与建议是基于当前证据的模型审查判断，不代表全面认证。未解决的已知冲突、条件或交付缺口仍会限制选择。”**

“不承诺零漏判”只在按需说明展开，不用长免责声明淹没报告。普通用户不需理解H/Q/R编号、FD编号或原型结构；保留原报告的具体内容、依据和行动选项。不能将全部建议退回警告或逐条人工审批。

## 3. 状态与操作仍须真实影响结果

- 正常完整任务：保留正式观察、解释及完整建议；有支持是有依据的有限判断，可按既有条件进入人的选择，不是自动业务执行。
- 有条件支持：具体未知紧邻建议；只问必要一题，已知条件不重问。回答先使相关项需重审，重审后再改变选择资格；已答未知不重复追问。
- 必需内容缺失／已知冲突：持续显示具体“尚未完整交付／存在冲突”，保留有效事实，受影响选项禁用。报告内容确认不能消除缺口，不能拿来源原稿补交付。
- 失败／停止／UNKNOWN／过期：不赋四类已完成判断，不沿旧支持放行新正文；草稿和已保存成果保持，先读回或按合同显式恢复。
- 编辑、引用或范围变化：沿原主稿／版本／冲突规则；改变含义需重审，纯布局切换不重跑。不增加“跳过审查”“忽略冲突”或通用强制采用按钮。
- 发现漏判：保留原版与审查，展示问题来源及受影响项，按已有修订／重审处理；不能继续展示为毫无争议的已核实建议，也不把用户质疑自动当成新事实。
- Report Studio：制作／关联／导出不补语义资格，不接管原正式报告缺项；当前例仍无真实产物，不能造文件冒充已交付。

## 4. 本次用户审核路线

1. 默认B完整报告：看具体核对建议与全部条件／费用／风险／备选／停止／观察仍在；“审查判断”不抢主内容，不把报告变为免责页。
2. 查看“保证边界说明”和“F107历史漏判”：区分审后追加的技术旁路与受审全文被误判的质量失败，确认旧FAIL保留。对照正式导出预览及人的下一步，含义一致。
3. 切“附加动作被审查识别（合成）”：看被识别修订的预写情境，不把它当共同漏判必然拦截能力。
4. 切“必需内容缺失”“审查失败”“内容变化需重审”；检查受影响选择仍禁用、原事实保留。条件情境回答能／不能／未知，行为沿旧合同。
5. 打开“名称与引用边界”：外部原句在来源数据身份下只读展示，不在当前建议正文拼接，也没有给这条历史反例一个已修复标记。
6. 切对话／成果／依据、快／专业和六阶段；编审、引用、保存失败／UNKNOWN、冲突与旧确认失效仍沿原工作台。无需再次审核所有未改布局或重开旧产品批准。

本次新增说明与007审核任务均为合成／历史预演，不请求模型、文件、服务、持久存储、真实导出或正式提交；007导出按钮只展示预览。复用壳层里的旧独立样例仍可能生成标为合成的浏览器本地下载，不是后端保存或真实交付。任意输入不会被本稿自动判为语义正确，F107详情也不是本页真实检测结果。原生产验收必须实际发生，不以本稿替代。
