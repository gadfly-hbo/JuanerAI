## 3. 模型怎样提出完整内容：候选接口及其不足

### 3.1 事实权威输入与MODEL职责分开

候选输入应复用现有形成请求中已实际提供的材料，不新增Runtime：

```
TaskContext
  current question + explicit version/analysis-only intent + original requirement provenance
  adopted definition + Context/Binding + actual IR + current scope
HostEvidence
  checked fact IDs: exact value/unit/period/category/proof and applicability
  material receipts: source identity/imported range; current missing source stays absent
  attributed USER conditions: subject, scope, state, source and revision
  allowed material/tool/action boundaries; evidence gaps
ModelMaterial
  immutable original draft; historical MODEL material separately identified
```

计算/独立核验只为实际数值和范围背书；USER陈述是有归属输入，不能当独立导入回执或计算事实。当前宿主对自由USER文字的提取也不是天然权威：`judgmentPremises`包含有限语言识别，`mapping=recognized`不能外推为任意中文理解正确。无法映射时保留UNKNOWN，不能让另一个MODEL自报“已识别”补成事实。

MODEL应实际提出：有限观察与解释、理由/适用限制；若原任务要求建议，则提出具体主行动、主体/对象/目的、依据、实际条件/资源/费用用途、风险、备选、停止和观察安排。它可以不提出可靠方案，但必须报告缺失，宿主不能代填。

### 3.2 自然正文接口：具体但不足以收口

下面是**手工设计样例，不是原MODEL产物**。`H-*`只是示意引用名，不是新的真实ID或冻结schema：

```
proposal:
  observation:
    text: 模型写出的当前资料有限观察
    evidence: H-orders-summary, H-refunds-summary
  explanation:
    text: 模型解释分别汇总为何不足以得到净额/利润/原因、还缺什么归属证据
    support: 当前IR、未形成跨表归属证据、成本/原因证据缺口
  option:
    action: 核对所选退款与订单归属
    actor: H-category-A-owner
    objects: H-selected-orders, H-selected-refunds
    purpose: 收集可追溯归属匹配证据
    authority: H-matching-permission
    resources: H-future-three-days + H-two-hours
    cost: H-cost-ceiling，use=ceiling，禁止解释成已花费或收益
    rationale/risk/alternative/stop/observe: 各自模型完整正文及对应关系
  presentation:
    摘要、正文、卡片标题/解释、图表说明、Expected可引用的内容清单
  missing: 模型未能提出的原要求项
```

以原B为例，模型需要实际表达的是：两文件各自汇总；未建立归属所以不能直接认证净额、利润或原因；由品类A运营负责人用所选两份资料核对归属、保留匹配证据；本样例未来3天内2小时、≤200元已给且满足；把描述误当原因/无法匹配是风险；可暂缓；无法匹配或需新资料时停止补证；用可追溯匹配记录观察完成。不是只输出9个非空字段或“当前给定条件”。

缺失action/risk/alternative/stop/observe时，按原要求形成具体交付缺口，保留独立有效观察；不能从method、旧成功或用户愿望补句。原有一次合并内容修订可以由MODEL补足，并对应重审；用完仍缺则不完整。

但字段存在不等于内容满足。若`risk.text`中夹带新行动，或只写“已充分考虑风险”，宿主只能确定非空，仍依赖语义判断。上面的接口即使审查收到每个字，也不能在指定的共同漏检情形中阻断F107，因此**不推荐作为本次收口实现**。

### 3.3 最接近结构性阻断的表达树：具体研究对象，尚非可信实施方案

需要尝试的根本变化应是：正式业务内容本身由MODEL提交为完整组合表达，不再把自然正文作为业务含义的另一套权威。表达不只是`method: attribution`标签，而是主体、动作、对象、目标、前提和每项约束都明确的提案；宿主只呈现MODEL已经提出的这些含义。

设计层的候选组合可以包括：

| 可组合内容 | 必须由MODEL提供/选择 | 宿主允许检查/呈现；不补出的内容 |
| --- | --- | --- |
| 数值观察与比较 | 实际引用、比较关系、观察范围、重点与组织 | 引用实际计算结果；同口径/同范围比较；新差额若不在真实计算中不能文字现算 |
| 有限解释 | 解释关系、理由、反证与限制及它们依赖的证据 | 检查关系涉及的事实/范围；不能凭“有限解释”类型就认证自由解释 |
| 实际建议 | 完整动作/主体/对象/目的/依据/条件/资源/费用用途 | 现有方法和材料权限、USER条件、当前未满足项；不由一个动作名自动拼出整个建议 |
| 风险/备选/停止/观察 | 具体可能失败、相应后果、替代提案、触发条件、观察对象/安排 | 按所提关系保留；没有输入不能默认产生“无法匹配则停止”等业务安排 |
| 自然表达组织 | 主题、先后、并列/因果限制/条件连接、详略、合适称谓 | 仅在已定义“不新增业务含义”的呈现规则内组织；没有审后自由润色出口 |

例如一个完整B提案在语义上需要以下组合，**这仍是设计推演，不是可运行代码**：

```
Observation(Refs(the six separate checked summaries), Scope(current selected material))
Explanation(Relation(separate summaries, attribution not established),
            Limitation(no supported net/profit/cause inference))
Option(
  Proposal(actor_ref, action=match, objects=[order_ref, refund_ref],
           goal=traceable_attribution_evidence),
  Basis(explanation_ref),
  Conditions(authority_ref, availability_ref),
  Resources(window_ref, hours_ref), Cost(ceiling_ref, use=upper_bound),
  Risk(Possible(misinterpretation_of_descriptive_result), consequence_ref),
  Risk(Possible(unmatched_records), consequence_ref),
  Alternative(defer_without_action),
  StopWhen(unmatched_records OR extra_material_required, followup=seek_evidence),
  Observe(matching_records, completion_evidence, within_window_ref)
)
```

这里没有预设200、B06、促销关键词，也没有把全部分析限为归属核对。A应由同一观察/比较/解释/限制组合表达，不要求Option；口径、期间和品类来自真实资产/IR。MODEL若只交一个`match`标签，缺actor、objects、goal或其余必要内容，仍是缺失。若原稿没有主行动，形成阶段不能靠宿主或默认Option补出；需原有一次MODEL修订实际提出完整提案。

**结构性保证的必要条件不是“表达树”这个名字，而是：**所有正式业务文字都必须由树中可解释的业务内容产生；树没有任意`text/other/reason/owner statement`叶子，未知业务谓词/无法约束的附加文本不能转为正式资格；源文件名/人的姓名只能作为有归属的名称或引用，不被当成新的谓词。名称转义只防止HTML注入，不能证明语义；不能将源名称中的指令带成建议。

要避免108错误，呈现须能证明：每一个业务断言、模态（可选/已发生/预计）、否定、条件、主体/对象、数值用途都来自MODEL提交且经相应用途校验的关系。宿主可添加标题、编号、标点、布局、已知数值/来源状态显示；不能添加“因为归属未确认”“需停止补证”“可在三天完成”等MODEL没提出的业务理由或承诺。

**本评估没有给出满足这一要求的完整自然中文组合规则。** 如果在最后把`rationale`等留为字符串，问题退回3.2；如果把每类关系翻成整段固定业务句子，退回108；如果规则只能表达固定的两来源核对，又丢失A与原B的具体解释。把操作符改得更抽象不会自动解决这些问题。不能以schema/词汇表存在就宣称覆盖或“不是模板”。

真正区别于句库的证据应是：同一组合机制实际表达原A的总体/品类/两期/口径限制以及原B完整建议；内容由MODEL逐关系提出，改变输入关系会相应改变表达，遗漏不会被补回；不同自然组织保持相同业务含义。**当前没有该机制或对应证据，所以本路线目前只是一份具体可证伪的研究对象，不是可启动实施的首选方案。**
