# 可点击 UI Contract v0.1 · 当前浏览器工作台

**候选，用户 UI Gate PENDING。** 权威和范围以 [方案](proposal-v0.1.md)为准；本合同与原型不授权开发。原型所有数字、对话、状态与版本是合成样例。页面不能被当成真正的模型、计算、权限、持久化或业务采用证据。

## 1. 稳定外壳与视图

U01 首页：左侧 JuanerAI 文字品牌＋标语、新建分析、当前项目、最近任务、资料／项目口径、设置。中间单一问题输入框＋资料按钮，三种起步方式，两个合成示例。正式产品首页不放开发者审核工具，原型审核条明确独立。

U02 任务对话：顶部面包屑、同任务快速／专业开关；任务标题、范围、时间／版本、实际状态；主导航“对话／成果／依据”。正文问题→方案→已核验发现→待判断点→追问，输入器随工作区，不遮挡最后一条内容。一个右侧检查器，证据／口径与资产／过程三组；“资料、方案”作为相应组内子页，不删除旧五分类。

U03 成果：概览／数据结果／报告编审子页；主成果与约320px同任务助手并列。助手就是原任务对话的紧凑视图，草稿、引用和发送历史同源；不是第二会话。宽度不足时检查器按需叠层、助手落到主成果下方，保持单列可读，不把三个面板同时挤在屏幕内。

U04 依据：完整证据目录与定位，资料／范围、口径／版本、计算／IR、独立核验、假设／限制、协作来源、报告段落可跳转。已核验数值不提升为因果支持。Change007语义结论只在其独立能力实际接通后按批准合同渲染，本稿不发明新判定引擎。

U05 专业模式：同任务显示六阶段导航，阶段内容不是装饰。新建分析＝需求／框架／前后差异；数据准备＝资料预览与权限、口径、适用性；本地处理＝执行方案、计算与核验、真实状态；循证分析＝假设、逐数字依据、助手／协作；报告＝同一主稿编审；执行反馈＝原适用正式业务评审、决定／Owner／观察安排及未行动提示。快速模式不改变六阶段背后的能力／状态；选择阶段仅改变当前阅读面。

## 2. 页面状态矩阵

| 状态 | 可见内容／允许操作 | 禁止与回退 |
|---|---|---|
| 无任务／空资料 | 新建、理需求、自己写、资料入口，明确本机存储范围 | 不显示虚假成功分析 |
| 需求草稿／待确认 | 业务目标、范围、待补、方法、证据、预演；保存／修改／确认 | 预演标非事实，未确认不可开始 |
| 运行／等待 | 实际事件、当前授权与消耗、等待原因；读现有结果与停止 | 不估造完成百分比，不暗中继续等待外的新授权 |
| partial／证据不足 | 保留已保存结果及具体缺口，可引用适用结果／编审／确认限定内容 | 不升为完整完成／原因成立；未核验材料不可进锁定事实 |
| 已保存 | 当前内容与来源、报告、旧分析认可、适用正式评审 | 报告确认不替代正式评审 |
| 停止请求已收／停止中 | 显示“正在停止，尚未确认结束”；保留读取 | 不能显示已停止或放行冲突执行 |
| 已停止 | 显示已停及保留结果；有权限且适用时显式继续 | 不自动恢复；累计额度不重置 |
| 失败 | 已知失败原因、保留草稿／结果、可辨可重试项 | 不将错误吞为成功、不无限重试 |
| UNKNOWN／网络中断 | 明确请求结果尚未确定、先读回保存状态；本地草稿保留 | 禁止盲目再次执行、重复保存／确认 |
| 只读／控制权冲突 | 读可访问内容、解释只读与请求控制权入口 | 不因打开页面自动抢占；无强制覆盖 |
| 历史／版本冲突 | 旧版只读、指向新版本；并列本地草稿与新稿 | 不静默重绑定引用／建议／确认 |

原型通过审核场景条显式切换状态；不把此条作为生产控件。真实错误文本应面向任务影响，不泄露凭据或内部堆栈。

## 3. 选区引用详细规则（U06）

数据结果表每行有带名称的勾选框，可“引用已选行”；表头明确这是已核验结果行，不是全量原始资料。引用卡显示选择的行、任务版本／快照及范围，附“定位”“移除”；本次原型稳定行ID为 S01–S04，不按排序位置绑定。支持倒序后验证同一ID未换行。原始资料预览标前10行／全量另算；无稳定行身份时解释不可引用。

文本可鼠标／键盘选择当前段文字后点“引用选中文本”；不支持的浏览器可用“引用此段”完成同等操作。跨段或>1500字明确拒绝，不自动截断。事实段只引用；可编辑解释段可引用／请求段落改写。引用不是自动上传／发送许可。

同一任务切视图、阶段、模式保留卡片和输入；切换另一任务不带卡，返回原任务可继续。版本改变后卡显示过期且禁发送；“重新选择”需回到新来源。权限失效显示不可访问，不露出原正文。发送前明确标识数据用途与既有权限；缺权限时走原授权，不静默补齐。本期不做跨任务引用集合或通用知识库。

## 4. 报告编审（U07）

报告固定结构：标题／范围与来源版本；已核验事实和结果表；解释与建议；核验情况和必要限制。事实区域有文字“计算事实 · 只读”，解释区域有“用户可编审表达”，全部在同一主稿，不并列两份“当前报告”。

手工编辑→未保存提示→保存→新版主稿；保存错误保留编辑文本，不冒充已保存。AI改写入口只提交目标解释段及必要已授权上下文；返回后“原文／建议”比较，用户应用或放弃。采用修改加一个内容版本；无变化不加。生成后目标段／分析／报告发生变化时显示“建议已过期，未应用”，只能放弃或重新发起。

原型“生成合成改写”不是实际AI；不定时伪装推理，仅在点击后显示固定建议。审核器可“模拟另一端保存”检查冲突；此按钮不出现在生产。保存失败／UNKNOWN可在异常场景中演示，真实产品的写入幂等与读取机械细节留工程决定。

并发审核路线：生成合成建议→手动改编辑框但不保存→“合成：另一端已保存新版”。本地未保存稿与当前保存稿并列，明确没有覆盖；选择“保留草稿，基于新版重新编辑”或“放弃本地草稿”，之后仍须显式保存；旧建议保持过期，不强行应用。主稿及版本历史同时展示 MODEL生成原文／USER手动编辑／MODEL建议·用户采用，以及“未经新增事实核验”。未执行的会员任务在数据、依据、检查器与引用处均显示无结果，不借销售样例补齐。

加入发现只对可验证、适用当前版本的发现开放，记录进本版内容；不可删改锁定事实／必要限制。要修改事实，入口“调整分析范围／口径”带回需求与方案变化预览，旧结果保留，新结果需按现有规则计算／核验。没有文字改写直改事实的通路。

## 5. 确认失效（U08）

确认栏同时区分：既有“分析认可（分析r1）”与新“报告内容确认（内容vN）”。旧认可不能填成新报告确认。确认按钮完整命名“确认这版报告内容”，不是“批准结论／行动”。Partial时命名“确认这版部分结果与限制”。

| 事件 | 报告内容版本 | 该报告内容确认 | 其他记录 |
|---|---|---|---|
| 改布局／切模式／切页／导出 | 不变 | 保持 | 不新增分析或正式决定 |
| 手改但未保存 | 保存版不变，本地脏稿 | 保存版历史仍在，但当前编辑状态不能确认 | 显示未保存，不宣称新稿已确认 |
| 保存不同解释／应用改写／纳入发现 | +1 | 旧确认不再适用，显示原因及旧版历史 | 既有分析认可不被反向改义 |
| 新分析／来源／口径／结果版本 | 对新结果形成新稿，保留旧稿 | 新版未确认；旧确认仅历史 | 相关正式决定不自动沿用，要求适用性复核 |
| 请求失败 | 不变 | 保持旧版，不能显示新确认成功 | 保留草稿／已知失败 |
| 请求结果未知 | 暂不猜测 | 显示待读回，禁再次提交 | 先查询，再显示确认状态 |
| 恢复旧报告 | 只读旧版，本期无一键覆盖当前 | 只读该版历史，不当当前确认 | 不自动恢复执行或决定 |

内容确认禁用条件：不是当前保存版本、未保存文本、改写未结束／未放弃、过期建议、UNKNOWN、只读、缺必要来源身份。冲突处理只读回与人工重新编辑，不强行覆盖。旧记录和用户操作历史不能删。

## 6. 协作、资产与正式评审（U09–U11）

“更多能力”保留技能／模板、Fork／Subagent及其独立范围入口。协作树显示发起者、父任务、独立授权／材料范围、运行／停止、意见返回、父模型使用、正式关联采纳等不同状态。原已批准可自动回流的意见仍可自动回流，不新增逐次人工批准；回流≠独立核验。

“口径与资产”保留项目维护、导入结果、候选／已批准、当前任务采用与未来默认的区别；修改默认只影响之后任务。两个版本不兼容则显式失败，不猜指标；零分母“不适用”不替换成0。专业方法／核验入口仍在本地处理和依据中。

执行反馈只在原本适用的任务／方案呈现真实正式评审提交入口；原型给出具名合成方案样例。非适用任务显示“当前任务不满足既有正式评审条件”而不是新造通用决策写入。可查看现有 Owner、baseline／expected observation／window／guardrail 与不行动／推迟／候选选择；“建议”不是实际行动，未来 Actual／Outcome 继续标未接通。本次不开发007。

## 7. 响应式与可及合同

- ≥1280：约230px侧栏、弹性主区、可开320–360px检查器；主成果＋助手受可读宽度约束，不同时硬塞四列。
- 1024–1279：保留侧栏；右检查器按需叠层，成果助手落在主成果下方。768–1023：单主区＋按需侧层；<768：侧栏／证据每次只开一个抽屉，关掉返回发起按钮；助手在成果下方而非并列，不整页横溢。
- 390px桌面等效窄窗仍可发送、看完整报告、访问六阶段；六阶段可局部横滚，表格局部横滚并有名称，不靠正文缩到10px。
- 正文14px以上、辅助12px以上、行高≥1.5；普通文字对比度目标≥4.5:1；焦点可见。键盘可到全部动作、Esc关弹层、Tab留在模态层内、关闭返回焦点；状态有文字，错误与禁用原因可读。
- 无隐藏思维链；过程仅产品允许的计划、工具、结果、错误与核验摘要。窄屏布局不改变权限或取消重要限制。

## 8. 用户审核路线（合成操作）

1. U01：看首页视觉、三种开始方式；“查看完整方案”检查保存／确认／执行的区别。
2. 点“对话与证据”：同任务标题与范围、证据检查器、逐数字依据、当前状态。
3. 点“数据选区”：勾 S01／S02→引用；倒序验证未串行；切任务再切回验证不串上下文；模拟新来源后卡过期不可发送。
4. 点“报告编审”：选择文字或“引用此段”；改解释但不保存；保存失败仍草稿；再正常保存；生成改写、比较、放弃／应用。
5. 点“确认失效”：确认当前内容→只切视图与模式应保持→手改保存应失效；看旧版确认历史；生成建议后模拟另一端保存应阻止应用。
6. 点“专业六阶段”：逐一打开六个真实内容页；查看方法、协作树、资产、正式评审／未适用提示；不能只有进度条。
7. 点“异常恢复”：UNKNOWN先读回，停止中不等于停止，失败不丢草稿；窄窗和键盘查看。

原型的仅模拟入口都有“合成”说明。现有能力中的复杂输入／授权／正式评审字段在“能力详情”中以可读面板展示，不冒充接通的提交表单；其生产行为仍以方案及旧合同为准。浏览器真实持久化、网络／Provider、后台并发、原始资料完整格式、独立计算和真导出均不由此原型证明。
