3. Analysis Core 的最小共享边界

   只表达本期 M1 或 M1＋合格 M2、合法参数、必要依赖和验证要求。Application 校验后，可信代码将它编译／物化成实际计算输入；不接受模型提供的任意 SQL、Python 或流程节点。

4. 语义、任务推进、恢复与人审如何接通
场景语义：版本配置＋任务 Binding，足够支撑 P1
复用现有指标定义、状态意义、方法资格和六类质量处置，形成有限、可维护的场景配置。多个任务真实消费同一版本，各任务再绑定自己的源文件和实际字段。
技术检查可以自动完成：编码、字段存在性、类型、时间覆盖、引用完整性、质量计数。以下不能自动猜：有效订单状态的业务含义、指标意义、未知字段映射、分组意义以及质量处置授权。
配置更新不改变旧任务；字段名称相同也不等于业务含义已确认。不需要因此引入完整 Ontology、通用语义管理后台或新 Domain Pack 平台。
未完成任务：新增业务用例，保留原 Assistant 边界
新任务协调由 Application 负责，工具只触达获准的准备、计划、计算／验证、结果读取和待审报告能力。
模型不能获得接受 Finding、Closure、正式 Decision／Expected、执行行动或自主派生子任务的工具。完成后再接续原 Assistant／003；保留原资格、人工启动、单层及 MODEL-only 采纳限制。
任务授权需要区分：
- 授权范围：允许的目的、来源、语义、方法范围、接收方、材料类别、额度和期限。
- 本次精确执行：在该范围内形成的不可变计划和实际载荷。
因此不必要求用户逐 API 批准，但每次出站、工具写入及结果发布都必须检查当前授权。先授权范围、随后形成具体计划是可行的；不能把“同计划”解释成可任意修改的任务通行证。
原始列名、群组名称、自定义语义文本和报告内容都可能含敏感信息。应从合格结构化字段重建模型材料，不能整份配置／报告直接发送。匿名组名不自动解决小群体披露；具体屏蔽规则和可披露边界仍需用户决定。
停止／恢复／点评：需要持久授权账本，不需要恢复 Pi 会话

- 停止同时封闭新准入和迟到结果发布；已发请求可能仍收费。
- 重开仅恢复视图；显式继续后才创建新 Attempt，不能清零累计预算。
