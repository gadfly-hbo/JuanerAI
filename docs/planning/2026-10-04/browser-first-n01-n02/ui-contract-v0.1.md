## 3. 审核路径与正反场景

审核者不需要操作内部对象。先走正常M1，再用附件“审核情境”直接进入关键状态；情境工具仅为合同评审，不是生产功能或验收启动器。

| 情境 | 应看到的结果 | 不得出现 |
| --- | --- | --- |
| 正常M1与混合资料 | 问题/必要授权→CSV＋XLSX至少三合成来源或工作簿多sheet→自动结构/受控准备→资格/指标核验→报告/人的判断；可同时查看直接供模型的合成业务说明 | 用户先整理双CSV、逐字段填写；未选M2有分组结论；文档阅读或模型代码被称独立核验 |
| 下降前提不成立 | 显示不下降／上升的证据，保留用户原话并纠正前提 | 仍输出固定下降，强行推荐原因／干预 |
| 缺资料、资格阻断 | 缺订单具体请求；全空阻断不生成该次报告；语义不明等待；零分母证据不足 | 把所有情形称“计算成功”，放宽旧资格 |
| 核验／解释失败 | 核验失败无可信发现；解释失败已有核验发现仍可查看 | 模型回答代替独立核验，假装完整报告成功 |
| 模型失败与一次自动重试 | 原请求确认结束后，同一有效范围和模型自动重试1/1；成功继续，仍失败停下；原请求未知先等待读回；使用及计数保留 | 换模型／扩材料、并发补发、第二次自动重试，或把计算／人审保存失败归为模型重试 |
| 停止、有效／失效授权继续 | 先保存有效进展；显式继续核验当前任务授权，后台复用有效配置；累计使用／未知在途／同一操作重试计数不清零 | 每次Attempt／Change都重批同一模型配置，自动再跑或晚到成功，重开刷新自动重试机会 |
| 刷新／断连／关网页／服务重启 | 刷新只读回；断连只读和不确定状态；关闭网页不同于停止；服务重启待显式继续 | 刷新重新执行、不确定请求再次发送，重启无限续跑 |
| 另一页面只读 | 看同一状态，不同时写同任务 | 以切模式／另页产生第二份业务权威 |
| 下载失败 | 后端报告仍在；下载失败／未确认明确可见 | 下载请求被称已保存磁盘，撤销后端报告 |
| 人工确认结果未知 | 未知即先读回，禁重复提交；恢复后显示相同精确结果 | 误报接受成功、重复发布或凭聊天消息接受 |
| 收束内容缺失 | 事实和报告可看，说明无法形成合法收束，保持待审／待补证 | 默认补造不足／偏好，接受发现、final或Completed |
| 结构或关联歧义 | 只就影响计算的订单状态/关联等问题定向澄清，解决后复用已完成准备 | 一列一问或强猜主键/状态、扩大明细外发 |
| 代码纠正成功/用尽 | 同一操作最多一次纠正，成功继续/仍失败保存依据停下；Provider重试另列，重开不重置 | 重试次数混为同一额度、换ID无限修复、代码成功即贴全链PASS |
| 无法读取/OCR不确定 | 每个文件说明读取状态及具体缺口，可替换/排除或补证；不确定原值不进入可信指标 | 静默丢文件、编造OCR值或假支持旧Office/图片 |
| 隔离拒绝/来源变化/准备UNKNOWN | 隔离未成立不执行；来源变化不发旧计划；UNKNOWN先读回，明确停止与显式继续 | 探索任意目录/网络/凭据、自动安装、覆盖原文件、盲目重执行 |
| 两类材料与内容风险 | 材料面能区分表格结构/本地明细和直接文档内容；凭据/已识别敏感材料具体阻断或排除，格式不保证安全 | 正文/图片一律禁止，或者只因换成PDF就允许表格明细绕过保护；实际未调用模型却展示已送达 |

若附件暂未覆盖某生产机制，列为未验证，而不是用动画证明。此合同只提供可评审行为；真正首次浏览器路径和跨进程恢复由工程在获准环境中验证。

### 3.1 首试确认前的摘要

继承旧analysis-only整体效果，不将首试简化成单独保存报告。M1上升／持平摘要分别呈现已核实总体变化和**对原因／经营方案选择的不足**：方法仅描述，未有合格策略效果和方案比较证据，因而无方案偏好。单期零分母说明该期率／率差不可计算，其他已核验事实仍有效。摘要来自当前证据和受限方法，是用户待审建议；不是因“无决定”而自动生成不足。

确认前可查看对应报告版本／范围、事实／来源、眼前摘要与理由，清楚接受／保存／完成／final的整体效果以及不产生决定／预期／行动。缺合法内容不提供可生效确认，保留待审；取消／补证不产生正式效果；未知提交只读回同一来源及摘要。后台完成精确绑定和原子保存，不新增专业表格、内部对象审批或多颗checkbox。

## 4. S1后续接通，不删除承诺

沿用同一布局和任务，接回M2、专业完整检查、报告点评／期间重算、正式决定／Expected及单层Fork／Subagent。点评在有效任务材料授权内不逐条机械批准；新披露或新期间才说明变化并必要授权。正式人审展示复合效果、Expected护栏和依赖分开、草稿／正式／历史可辨；保存不明先读回。新载体差异实质影响可见行为时只取得受影响UI批准。

首次UI差异接受不等于后续未展示行为提前全部接受；已有有效001～004 Contract在其适用范围继续有效，不默认重新设计S1整套页面。

## 5. 验证、审批与工程留白

用户只审本合同差异及附件，不要求重新通过视觉全套。未收到直接用户接受前，本合同保持待UI Gate。产品计划新鲜只读就绪审查不替用户接受；UI Gate也不替Q1～Q5和工程接收。
