# Change005 v1.1 UI Contract 修订 R1：对话优先、按需深入

## 1. 视觉与结构保留

中文、白/浅灰、绿色主动作、JuanerAI字标和“持续做出更好的决策”、紧凑新建按钮、无图片Logo。左侧项目会话，中央对话/展开成果，右侧详情抽屉按需打开且默认关闭；专业模式保留完整六阶段，对应同一真实任务/版本/权限，不使用快速来源的专业占位。

样式直接复用固定原包px006/styles.css、brand.css、workspace.css，仅添加本文所需的信息显示与响应式适配，源身份见source-manifest.json。专业原型保留原PX004完整交互来源；审核iframe明确来源回放，不证明新行为共享后端。无新配色/字体体系、节点审批界面、七页或五页向导。

## 2. 默认可见规则

| 当前场景 | 主区默认 | 按需查看/真正动作 |
| --- | --- | --- |
| 起步 | “今天，想弄清什么？”与输入框、添加资料 | 不要求选行业/Skill/指标/流程 |
| 简单完成 | 简洁答案、必要单位/范围及重大限制；“查看依据” | 口径/来源/方案/计算核验在详情；不自动插入五张卡 |
| 对焦复杂需求 | 简短目的/交付理解，可有一段简洁提纲 | “查看/调整方案”；不是每次必须点确认才开始 |
| 真正缺信息 | 一条具体问题及影响原因，与当前消息相邻 | 在同一输入框回复；无技术字段表/重复同问题 |
| 长任务推进 | 一条真实业务进度摘要 | “查看进展”打开真实步骤/检查；无伪进度或思维链 |
| 部分/失败 | 有效部分成果＋具体受影响项和下一步 | 补资料/修正业务条件/停止；不得称全任务完成 |
| UNKNOWN/重开 | “结果待核实”或保存的等待/停止状态 | 读回/核验；合法显式继续，不能盲重发 |
| 经营报告完成 | 有据发现摘要＋图表/报告入口＋重大限制 | 展开完整报告、逐条证据/质疑，不默认全文过程日志 |
| 修改/对照 | 简短旧→新变化、真实失效/待重算状态 | 按需展开影响与旧新比较；新版失败保留历史 |

“五个时刻”不作为前台导航、固定标题组或必须完成的五段卡片；不是删掉相关能力。只有本场景需要的内容进入对话，其他从“检查详情”或成果对应入口访问。

## 3. 输入区与操作

默认能力条保留“＋资料”“更多”“查看报告”；“更多”提供可选分析方法(Skill)、表达方式(Prompt)、原范围分支讨论/委派子任务和沿用历史方案。完整能力可达，不靠灰掉全部入口简化。没有现成方法也能在已支持工具内分析；方法适用性和版本按需查看，不显示程序/插件清单作为用户先决条件。

发送后立即出现用户消息与真实受理/等待状态，随后自动收回回复/成果；不要求点停止、刷新或查看方案触发收回。暂停性闲聊如“先等等”由Agent结合当前状态处理，不当作新计算目标。

停止仅在有当前执行/在途操作时提供中止动作；非运行状态不作为主操作。停止受理、物理结束、UNKNOWN及迟到围栏按原合同呈现；它不承担“显示回复”功能。关页/服务重启语义不变。

查看口径/方案/证据、切专业和选历史版本本身不执行、不重复发模型。自然语言修改明确时按原有效权限推进新版本及受影响计算，不额外强制“接受预览”才能处理每条对话；实质歧义/新权限/正式人的效果时就地提出必要选择。

## 4. 详情抽屉与展开成果

原抽屉保留口径、方案、资料、证据、执行五个检查面，但默认隐藏，不五面并列常驻。

- 口径：显示本任务实际采用的定义、来源/版本、用户解释与未知；有真实项目定义才写“沿用项目口径”，无库不虚构。非必要未知与阻断冲突分清。
- 方案：可读目标、输入/工作表、指标/单位、分组/筛选/关联、方法和当前限制；区分固定业务条件与可调整分析方法。动态新增/替换检查来自实际IR，不要求用户读JSON。
- 资料：已选材料及实际模型可见范围/接收方、原件/派生边界；不承诺零明细外发。
- 证据：定位选定发现的原始来源、计算/适用独立核验、反证/未知；代码成功不是整体已核验。
- 执行：真实步骤/工具结果、当前状态、停止/恢复和脱敏持久调用记录；技术IR/代码身份放高级详情，不显示秘密或思维链。

表格/图表/报告在原主区展开，保留返回对话与上下文/输入草稿。重要限制不藏在抽屉；历史结果明确历史范围，不能冒充当前回答。

## 5. 影响和双模式

表达调整不重算事实；业务口径/范围改变形成新版本，说明受影响内容，实际重算核验后比较。当前版本、历史版本、已失效、探索性、已核验、部分/UNKNOWN等状态用文字表达。方法调整在固定业务条件内不制造重复口径审批，但执行身份和核验记录更新。

同一项目沿用历史方案仍人工显式发起新任务，检查当前材料/适用性，不复制旧数字、授权或核验成功；“更多”仅更改入口位置，不新增自动学习。分支/子任务保留独立对话、精确材料、单层顺序、人工发起及回流待审，不被Agent自主推进扩大。

专业模式原完整六阶段的深度编辑/核验/正式会员人审保留，不改变专业页布局；它消费与快速同一Context/计划/证据/版本。专业已有强制正式判断仅按适用原合同存在，不能迁移为所有快速任务的口径确认。

## 6. 审核附件与评审路径

[可点击R1](clickable/index.html)使用固定合成状态，不读文件、不调用模型/工具、不计算/保存/联网。自由输入只回显审核说明，不按关键词生成假AI。审核场景下拉不是生产入口，按钮切换不是已实现证明。

建议先看“简单计算”是否只呈现答案；打开依据/方案确认内容可查；切“经营分析推进/报告”看简洁提纲、进展和成果；切“需要澄清”看单个问题；切“范围修改/部分失败/UNKNOWN/停止重开”核对不伪成功；打开更多检查原能力仍可达；切专业看原完整参考，返回快速保留审核状态。

原型不生成任意用户文本分析、不支持真实文件上传/报告下载；标明合成而非假装成功。示例45.5万元等数据仅视觉案例，不作为新业务默认或方法认证。

## 7. 验收与可访问性

UI-RV01简单题无同时五模块、无必选Skill、无固定确认；UI-RV02真实发送自动收回，停止仅中止；UI-RV03复杂提纲/动态进展可查且不强制逐步点击；UI-RV04必要冲突/重大限制就地可见；UI-RV05原抽屉/成果/影响/旧新版本及更多能力可达；UI-RV06快/专业同事实版本，生产不是iframe回放。

1440×900和1366×768桌面核对、390px健壮性；窄屏抽屉覆盖而非挤成三栏，工具条换行，长中文/表格不溢出，主对话滚动而输入可达。键盘Tab、可见焦点、Escape关闭并回到触发控件、输入标签及文字状态；不靠颜色。保留安全文本渲染。

上述与产品RV-01～08组成完整增量，不替代原会员/Runtime安全/产品体验验收。用户UI接受仍PENDING；静态/规划审查不代表真实实现/工程或产品验收，用户确认前保持停止。
