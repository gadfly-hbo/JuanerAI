## 2. 产品结果：对话驱动的专业分析工作台

用户自然提出问题、交资料、补必要歧义、修改方案、质疑结论和作正式判断。AI整理出业务理解与分析框架；语义参与编译，IR决定真实执行，Harness推进并验证，交付可检查、可修改、有据且可保存的成果。用户不必先填字段表、选择会员任务、学习IR或逐节点点继续。

开放的是**需求入口、问题组织和获准工具组合**，不是任何问题都保证答案正确／所有方法已认证／所有资料可外发。新任务不能因不叫“会员复购”被拒；不能回答时必须定位具体业务、资料、工具、识别条件或核验缺口，保留需求和有效工作，给出可行下一步。简单问答或文档整理无需硬造量化IR、Finding、Closure、Decision。

首版完整结果包含：实际LLM多轮对话；业务理解／框架形成与修改；文件实际消费；可执行计划、受控本地数据准备与分析／图表；证据及报告表达／点评；项目、搜索、历史、停止与恢复；可消费的内建Skill／Prompt；003同范围Fork／Subagent及回流／采纳；与专业模式同任务／版本。不是“每个模块独立PASS后用户自行拼接”。

会员复购仍是完整专业回归／验收场景，保留旧口径、全空阻断、合格单期零分母不足、M1-only不执行M2、M2贡献不是因果、独立Python复算和一次整体人审；**不是开放任务的通用默认业务事实**。其他任务使用对应定义和核验，不套CNY／Asia/Shanghai／两期／下降／复购语义。

### 3.1 Semantic Context Runtime（OA-01）

整理目的、对象、分析粒度、指标定义／单位、时间／时区、适用筛选、关系／关联键、前提、输入角色和交付形式。原话、资料事实、业务假设、AI建议及未知分开。任务采用确切资料和已有获准配置／语义版本，不凭同名列或LLM回答确立业务权威。

无需每次人工装配：已有合格定义与Binding复用；没有维护定义时可从选定业务材料与明确原话形成**任务级候选**，标来源／推断／待澄清，不静默晋升Ontology或长期资产。明确、无冲突且适用的解析可自动推进；只有影响结果的真实歧义才询问。无须逐指标新增批准门禁；正式资产发布仍走原Owner边界。

同一配置须实际服务至少不同问题、分组或期间的任务变体；配置／资料含义不适用、冲突、过期或改变时保留旧快照、明确差异并重解析，不默选latest。跨Case资产学习／自动采用仍属N07/N08，不借“语义复用”提前交付完整学习平台。

### 3.2 Analysis IR（OA-02）

业务理解与自然语言框架结合当前Context／Binding，编译成明确的输入、步骤／依赖、方法及版本或任务级代码身份、参数／筛选／粒度、前提、预期产物、核验要求和执行能力需求。**不是先生成与业务脱节的IR再补语义**。人类框架与机器计划有对应关系，两者不能各写一份互相漂移。

不能停留固定M1/M2：首版要支持由问题生成、组合并修订的本地分析步骤，消费已获准且实际可用的查询／Python分析／图表工具。新的计算表达不因未预置会员模板被拒；仍须能编译、准入、执行及按声明核验。工程确定具体Schema和执行器支持，不创建万能IR平台；每个开放操作必须有真实消费者与支持性说明，未知内容不得解释成任意Shell或通配执行。

计划决定真实方法、参数和输入范围；自然语言修改产生明确diff及新版本，失效相关下游结果，复用不受影响的有效部分；旧计划、Run和报告不改写。仅改措辞不重算事实。IR内容／Binding／数据／代码或工具错配、不支持时在执行或发布前拒绝，不能退回固定脚本、执行任意代码后称成功或仅更新显示。

### 3.3 Harness / Execution Runtime（OA-03）

LLM在当前任务、能力描述和授权内多轮选择下一步，Application核验准入，Adapter执行，真实结果供下一轮决定。不能只由固定后台顺序推进后让模型润色；也不要求业务工具必须裸挂Pi来证明Agent。真正证明是**不同问题／观察结果导致不同合法工具序列，Agent能改计划并完成任务**。

支持读取获准资料、检查结构／质量、执行受检本地准备及分析、读取获准结果、生成图表和证据报告。继承Pi Adapter与业务Ports，不新增Runtime或泄漏Pi类型。模型单次辅助与多轮Agent区分；确定性计算、资格、权限、账本及保存仍由系统执行。

生成分析代码是新增职责，不只准备代码：在只读选定快照及本任务派生区中运行，禁止网络、凭据、任意目录、改原件、Shell／子进程及安装；受信解析器与不可信代码分开，隔离不成立不执行。支持多次**新的合法分析步骤**，不等于同一失败操作无限纠正。旧一次模型重试／一次准备纠正保留；新增分析代码失败默认不自动换操作绕过纠正次数，按同一操作最多一次受检纠正的候选规则处理，见§9 D3。

显式停止封闭后续推进与迟到发布；保存以后台回执为准；刷新只读，关页不等于停止；服务重启不自动续跑，显式继续先核验有效授权及已完成部分。UNKNOWN先读回且不重复发出副作用；消费与重试机会跨Attempt／刷新／重启持久保留。运行到成果待审、必要信息、授权缺口或不可安全继续时停下，不以“无累计上限”无限循环。

1. **分工及隔离**：单次模型辅助使用 `@earendil-works/pi-ai`；快速模式自主多轮、工具调用及任务推进使用 `@earendil-works/pi-agent-core`＋`pi-ai`，全部留在现有Pi Adapter。保持 Product Core → Application → Port → Adapter → Profile；Pi类型、事件、错误、工具与内部Session不得进入业务及公开合同。产品Session／revision／Run／Attempt不等于Pi内部Session。不新增平行Runtime、通用注册表或中途Runtime切换；接通聊天API、固定后台流程后润色或附件单次调用示例均不能冒充完整Agent。
2. **主备模型**：主用 `minimax-cn / MiniMax-M3 / https://api.minimax.cn/v1`；备用 `xiaomi-token-plan-cn / mimo-v2.6-flash / https://token-plan-cn.xiaomimimo.com/v1`，参考协议均为 `openai-completions`。复用已批准调用配置；后续Change不得重新选型或重复要求用户批准配置，只有用户明确要求才调整。真实SDK版本／导出路径、模型型号可用性、内容及工具调用能力、协议／思考标签处理由Mini在intake和实际调用中核验；不盲复制示例的 `0.86.x`、虚设上下文／成本／输出值或以字符串过滤替代真实兼容。发现不兼容须具体报告，不能静默换模型、Runtime或削弱多轮能力。
3. **后端私有凭据**：按有效读取权限及精确配置在后端初始化／显式配置刷新时发现：匹配接收方的环境 `LLM_API_KEY / LLM_BASE_URL / LLM_MODEL` → `~/.zcode/v2/config.json` 指定MiniMax项 → `~/.pi/agent/auth.json` 的 `minimax-cn/minimax` 项 → zcode指定Xiaomi项。不是逐请求／网页刷新扫描；不扫描其他目录、账号或所有凭据。显式配置与接收方冲突、同级多候选冲突不能任意配对；无读取权限不访问，缺失／空值／损坏按不泄密的明确状态及既定优先级处理。发现Key不产生模型或资料出站授权。凭据只在后端私有配置／内存使用，不进入前端、Git、日志、审计原文、夹具或交接正文；只读状态接口最小暴露提供商／主机及实际可用状态，不暴露Key或私有路径。无有效模型时如实不可用或明确本地模板，不宣称Agent已工作。
4. **授权及受控工具**：后台先复用核验有效的任务级资料、模型与工具许可，必要时才重新授权，不逐Attempt／工具调用审批。快速主任务必要明细可在许可内出站；严格明细零外发延期，本地真实计算／独立核验不延期，子任务仍须自己的精确材料子集。模型只能请求业务工具，Application／Harness确定性执行准入、IR／版本校验、只读原件、任务派生范围及隔离；提示词不是围栏。获准任务派生计算／图表／报告按本合同推进，不套附件“前10行＋每次落盘确认”成新前台门禁；原件修改、越界写入和现实行动不能借此授权，正式人的效果仍按既有合同。禁止生成代码网络／Shell／子进程／安装、未选目录／凭据访问；不能靠模型承诺、AST或同代码重跑证明安全与独立核验。
5. **停止及恢复**：多轮循环、在途模型请求及工具受显式停止约束；停止后不再发新请求／步骤、迟到结果不正式发布，保存／停止效果以真实回执为准。关网页不停止已启动获准任务，刷新只读；服务重启不自动续跑，用户显式继续先核验授权、已完成成果及UNKNOWN，再推进缺失部分。产品历史和任务状态持久保存，不直接把Pi会话当产品身份；实际无法取消的在途效果如实标明并对账，不伪称已停止。
6. **计量和一次额外请求**：暂不设累计额度上限，但每次实际请求（成功、失败、超时、主／备、重试）均持久记录并归入同一任务累计。超时／失败允许自动重试一次；同一逻辑操作总共至多原请求＋一次额外请求，备用请求共用这一机会，SDK／应用／Provider重试不能叠加。停止、失效授权、UNKNOWN或不安全错误不盲重发；主模型未发实际请求且合法选用已批准备用，不虚记为失败重试。计量、重试机会及失败身份跨Attempt／刷新／重启保留，不清零。模型重试与§3.3的一次代码受检纠正分开计量，但纠正的模型请求仍记入任务累计，不能改操作ID绕过次数。
7. **持久调用记录及真实性**：每次调用关联产品任务／revision／Run／Attempt、逻辑操作及请求序号、Provider／Model与配置版本、授权及材料版本／范围、时间、耗时、实际可得输入输出量／usage、成功／失败／超时／UNKNOWN／取消和脱敏原因。实际不可得用未知／未提供，不编造零成本或成功；不保存Key、内部思维链或未获准明细提示原文。重开能读回并继续累计，内存环形队列不是唯一记录。记录、模型回答、工具输入结果及成果身份必须互相可回链，不以UI状态或配置存在代替执行证明。

附件适用差异已由现有及本次用户批准明确：隐私零外发／预算三封顶不适用于当前快速许可；参考单次调用、内存审计、任意配置扫描和固定路径骨架不能覆盖上述既有多轮、持久、安全及架构合同。该显式化不改UI、不增Gate、不授权MacBook实际凭据／Provider／业务数据操作；具体SDK兼容、实现方案和工程验证由Mini承担，新的实质冲突集中交用户。

## 4. 可信成果及方法开放（OA-04）

预测、因果、探索等需求均可提出、形成框架和检查前提，不按名称硬编码禁止。若当前方法、资料、工具及核验支持，就按实际能力执行；否则指出具体缺口、保留候选方案，不能静默降级后仍回答原问题。新增专项方法质量不是聊天开放自动获得的认证，分别对回N09～N15。

成果分清：①引用资料的事实／观点；②已计算但未达到独立核验要求的探索性产物；③经过适用独立核验的分析事实；④AI解释／假设及建议。探索性结果可供检查，不标“已核验”或进入正式已支持Finding；报告明确其限制，不能给整篇统一可信印章。

量化计算须有与原始来源／语义对应的资格和独立核验：已受支持指标使用独立计算路径；开放分析依据方法采用独立重算、原始数据抽查／对账、守恒／统计不变量或外部方法验算，具体方案由工程评估，**同一生成代码再跑一次和模型自评不算独立核验**。核验覆盖程度不能被结果一致或平均质量掩盖。预测需适用留出／样本外评价与不确定性；因果主张需可识别前提，前后比较／相关不能写成因果；条件不足不伪造专业结论。

## 5. 快速UI中看得见的专业流程（OA-05）

“按区域比较”“排除新开门店”以自然语言或框架编辑提出，产品区分表达／业务变化／新授权，显示对结果的影响。框架查看／编辑不等于每个节点人审。后台授权、资格和持久预算不变成更多前台表单。

Skill／Prompt（OA-06）：首版提供实际可消费的内建能力而非空标签。建议内建“数据质量检查”“分组比较”“证据报告”；方法、输入要求、限制、版本可查。Prompt只影响表达／协作协议，不覆盖语义／核验／权限；Skill须改变真实计划／工具消费者。手动选择覆盖当前建议，冲突或不适用如实说明；不存在插件市场、任意安装或后台资产自晋升。

Fork／Subagent（OA-07）：复用003单层人工发起、有界子任务、精确授权、顺序物理槽、停止／恢复、来源版本、成果回流待审及采纳／拒绝。不自动派发、递归、并发或采纳。开放主任务若尚不能形成003支持的材料资格，保留子任务建议并定位兼容缺口，不能照搬无来源意见假称独立验证。首版须真正完成至少会员和开放分析的合法协作路径，而不是整个入口禁用；材料扩展见§9 D2。

报告／判断（OA-08）：快速模式可查看／修改报告、定位证据、下载既有副本；后端保存、下载发起、实际落盘分开。会员正式Decision／Expected及护栏复用002/004的精确整体提交，聊天“好”不是正式接受；开放任务可交付洞察／探索结果／待补证，不强造旧会员Closure。开放任务的分析认可与正式业务Decision区分；没有业务选择不创建Expected。现实行动执行、Actual／反馈评价及学习发布仍按N05～N08／N20，不由本包授权。

**开放任务本轮交付终点（具体候选规则，随本包整体审核）**：成果及其核验等级已保存、可读回，或待补证成果连同准确缺口已保存、可读回；到此停止本轮自动推进。前者可显示“本轮成果已交付”，后者仅显示“待补证，已保存”，不冒充原目标已完成。失败／停止／UNKNOWN本身不是成果交付成功。

用户“认可分析”只为精确成果版本附加判断，不创建会员Closure、不接受未经核验Finding、不生成Decision／Expected或执行行动；它不把待补证变为完成，不另产生final／Completed效果。“成果已保存”与“用户已认可”分别显示和读回，未认可不妨碍保存及本轮自动推进停止；后台判断保存失败／UNKNOWN不得显示认可成功，先读回同一操作，不盲目重发。取消不写判断；新问题按现有版本规则继续。用户自然表述可作为待写入判断的意图，正式效果只以该判断的成功保存回执为准，不引入新一轮强制审批。

会员仍保留**仅确认分析／要求补证／记录决定**三个合法出口：仅确认分析按旧合同整体保存适用Finding、合法Closure及最终报告；要求补证／暂不采纳不冒充分析完成；记录决定才按旧合同整体保存Decision和适用Expected。合法性／不足语义／原子性保持004及原包，不把开放收束规则覆盖会员。
