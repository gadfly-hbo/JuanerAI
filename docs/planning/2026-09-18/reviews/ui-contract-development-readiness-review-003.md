## 1. What I Would Build

An explicitly labeled synthetic and simulated high-fidelity Xanthil workbench
that preserves quick/professional modes, Project/Session navigation,
independent child conversations, Composer capabilities, Inspector/drawer,
search and background task status. Professional mode carries the full six-stage
membership-repurchase Case. Quick mode, Fork and Subagent demonstrate the
accepted simulated interactions. No real calculation, persistence, model call
or production capability activation is implied.

## 2. Required Guessing

1. Fork/Subagent unlock conditions and what happens after inherited data scope
   or the source revision changes.
2. What adopting a child result may change, what authority it may not replace,
   and how adoption behaves after Finding acceptance or Case completion.
3. When a report becomes final and how accept, reject, defer and request-more-
   evidence map to the v1.0 Decision Closure and Case states.
4. How a builder can verify direct reuse of the accepted interface without a
   self-contained visual/static reference attachment.

The v1.1 precedence over conflicting v1.0 UI exclusions is explicit and was
not a review problem.

## 3. External Study Required

The supplied package would require the builder to open PX-2026-004/006 source
material to verify the exact accepted interface. The minimum correction is to
attach representative visual/static reference material and the missing state
decisions to the formal package.

## 4. Untestable Requirements

- child-conversation unlock and source-revision invalidation;
- adoption after source change, Finding acceptance or completion;
- report draft/final/superseded transitions and execution-feedback outcomes;
- direct visual reuse of the accepted interface.

## 5. Correctly Deferred

Exact pixels, components, TypeScript names, production schemas, Runtime,
scheduling, resource limits and packaging remain correctly deferred. Quick
mode and general Fork/Subagent/Skill/Prompt execution may remain Preview.

## 6. Required Plan Additions

1. Add a child-conversation state table.
2. Add an adoption-effect table.
3. Add a report/Decision Closure mapping table.
4. Add self-contained representative UI screenshots or static reference pages
   with permitted adaptation called out.

## 7. Verdict: NEEDS_CLARIFICATION

The package fixes the product direction and visible inventory but still
requires load-bearing choices for new capability state, recovery and authority.
Correct only these gaps, then send the corrected package to a fresh Reviewer.
This result does not authorize changing the clickable draft or starting
production development.
