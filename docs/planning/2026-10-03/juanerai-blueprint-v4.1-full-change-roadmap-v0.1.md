## 1. 一页总览

**下一次先交什么：在本机一键启动浏览器，用会员／订单双 CSV 和一个获准真实模型，在简单模式完成“提出问题 → 必要澄清与授权 → 真实计算和独立核验 → 有据报告 → 人的判断”。** 必要证据查看、停止、保存和重开安全一并具备。这是 N01/N02 内的首次内部试用点，不是第三个 Change，也不等于 S1 完成。

- **不等什么**：不等专业模式完整展开、深入访谈全部变体、报告点评／期间重算全部交互、Fork／Subagent 浏览器兼容全验，以及 N05～N08 学习闭环。它们仍有明确后续归属，不标为已交付。
- **什么必须先过**：真实模型及资料的明确授权；当前路径的文件与访问安全、计划消费、关键计算／证据、停止与保存；不能用合成模型或固定报告替代。
- **什么可以后修**：不妨碍该任务且无安全／业务意义影响的布局、文案及低风险体验 bug，记录影响、可行绕行和返回点后继续。不能因此把当前不可用的任务说成可试用。
- **何时能用**：首批第一次满足上述完整路径及底线时就交用户内部试用，不等整个 S1 收尾。接收方核对剩余实现后给预计交付时间；本稿不虚构天数，不将内部试用当商业试点或全部工程验收。

**当前建议：保留 4 个已有 Change，规划 20 个后续结果型候选。** N01～N20 只是本表的规划索引，不占用或猜测 Mini 的正式 Change005 等编号。产品结果与能力归属一次列齐；Mini 在工程接收时按风险与依赖确认正式分包，可以合并或拆分，但须保留本表的结果和验收映射。20 不是未经工程评估的工期或最终数量保证，也不等于 20 项均已具备开工条件。

## 3. 顺序与依赖

默认近期主线：**已有 001～004 → N01／N02 首次真实内部试用 → 按反馈补齐 S1 → N05／N06 结果回访 → N07／N08 改进与下一 Case。**

若试用证明分析范围不足或报告交付妨碍使用，可将 N09 的必要方法／领域子集或 N11 的必要报告交付子集前移到 S1 或紧随其后的批次；先明确消费者、增量及原范围是否变化，再按既有权限决定。**不要求先完成 N07/N08 才解决当前可用性问题。** 只前移必要子集，不顺带建设完整 Pack／Report Studio；其余目标仍留原候选，学习闭环也保留明确返回点。

- N03／N04 是按需支撑：回访或专业任务缺新数据／语义时，只插入所需增量；已有资料足够就继续主线，不先造完整平台。
- N09～N15 按实际专业消费者展开，不要求七项串行，也不要求全部完成才能商业试用。相同底层能力由共享模块实现，不能每个方法另建一套 Runtime、语义和报告系统。
- N16／N17 在经营、多人成立需求出现时进入，不以所有专业方法齐备为前置。
- N18 的企业试点安全与治理必须在进入真实环境前满足，不能留到 N19 补票。N19 扩大的是已成立边界的覆盖范围。
- N20 依赖行动证据、适用治理与专项权限，不必等待全部 Enterprise 扩展完成；但分析授权绝不自动变成行动执行权限。

阶段成果确认复用蓝图已有的场景、能力、体验三类验收，不另建审批流水线。每阶段交付固定集成产品，而不是要求用户自己拼接多个 Change。

| 阶段成果 | 到达条件 | 用户验收的整体结果 |
| --- | --- | --- |
| S1 可信易用的分析 | N01＋N02，复用 001～004，完成浏览器真实链及本机安全／状态验证；先试用再收尾 | 简单／专业模式共同完成支持任务、报告修改和人工判断；阶段后可讨论有界商业试用，早期内部试用不冒充 S1 完成 |

| S3 可复用的改进 | N07＋N08 | 一项合格改进被下一 Case 实际采用，学习发生与是否有效分别报告 |

### 3.1 近期运行载体与暂缓项

只做 PC 浏览器＋同机本地后端，保留简单／专业两模式；移动端、云部署、远程访问和企业运维不进入本批。首轮建议在用户当前 Mac 环境验收，其他操作系统须另有工具链与凭据证据。前端继续复用现有技术栈，不要求改成纯静态 HTML。

| 范围 | 本次处理 |
| --- | --- |
| N01/N02 | 将本机连接、文件与凭据装配、一键启动及真实 AI 激活放入同一批；载体适配先接既有 004 链，不必等 N01 全部变体完成 |
| N03～N16 | 原则上复用浏览器＋本机服务；各自数据／方法／外部来源权限照常关闭，不以 Desktop 安装包为交付条件 |
| N17～N20 | 保留远期目标与进入条件；当前单机载体不代表团队共享、企业部署或现实行动已成立 |
| Desktop 专属 | 暂缓壳层优化、DMG、签名／安装／分发及仅证明壳层的原生验证；不删源码、旧验证或遗留缺口，恢复 Desktop 时再核对适用义务 |
| 仍必需 | 浏览器到业务链的真实验证、本机访问与文件权限、凭据保护、计算证据、持久状态、停止／重开；名字含 desktop 的共享业务测试不因此取消 |

浏览器本身无权任意读写本机路径；服务只开放必要的本机业务入口并防跨站访问。后端持有数据与密钥，状态仍以业务存储为准；两个载体不能同时写同一项目。浏览器刷新／断连／关闭与服务停止的具体差异见[近期产品片](xanthil-task-experience-integration-proposal-v0.1.md)，在首次试用前关闭适用 UI 语义，不静默继承或改变 Electron 窗口规则。

## 6. 怎样保证能力真正收口

每个候选正式冻结时，在现有产品包明确五件事，不新增看板或管理平台：

1. **支持范围**：哪些用户、任务、数据、方法、输入变体及部署；不能只写“通用”“智能”或“完整”。
2. **真正消费**：前台意图与授权 → Application／Core／Port → 实际执行 → 验证 → 产物；参数变动能改变实际行为。
3. **边界表现**：缺数据、错配、越权、失败、取消／重开、修改及旧版本如何处理。
4. **完工结论**：范围内的实现、集成、独立验证与用户结果分别有证据；失败研究可形成有效评价，但不能冒充能力正向有效。
5. **剩余归属**：范围外能力明确指向本表已有候选或用户批准的新范围；不能只写“未来完善”。

“目标范围已完成”与“整个能力家族覆盖到哪里”同时展示，不用笼统“局部实现”掩盖已交付结果，也不通过缩小口径把全蓝图标绿。各阶段先冻结有限范围；若用户未来选择更多行业／方法，是可见扩展，不倒改原验收。

六＋二全覆盖表示没有漏掉目标，不保证完成这 20 项后所有行业、模型、部署或商业价值都自动成立。产品能力完成、用户会用、学习有效、客户愿付费分别取得证据。全景图继续由唯一累计清单和每 Change 快照承载，本稿只负责规划映射。

本调整稿已获用户确认，后续用[近期产品片](xanthil-task-experience-integration-proposal-v0.1.md)细化首批，不另造管理材料。一次收口适用 UI、数据／模型授权和环境；有效决定直接复用，只处理缺失或变化。真实 AI、PC 双模式、首次试用范围、沿用视觉与浏览器关闭／停止的产品行为不重复确认；具体 UI 表达及未决安全／权限项仍须关闭。

Mini 读回固定产品包和本表，核对实际代码、WIP、分支、权限及现行政策；普通工程选择由它决定，不增加 MacBook 技术签字。工程按已获准完整结果分包，不把每个 UI 小修、测试循环或内部子任务变成正式 Change。

| 粒度 | 工作与反馈方式 |
| --- | --- |
| 日常小步修改 | 保留行为说明及有效测试循环，跑受影响检查和相关主流程；复用未失效证据，不每次重跑全部回归、重做 UI 审批或重派独立角色 |
| 首次内部试用及后续预览 | 已获准范围内提供固定可识别版本、可用路径、已做检查和已知问题；满足本次暴露功能的安全／正确性底线即可收集反馈，不等待 S1 全部变体，不声称工程验收或商业试用 |
| 完整功能／正式 Change 交付 | 集中做适用回归与独立验证、必要用户接受及获授权 Git 交付；每个正式 Change 的验收义务不因改称批次而免除，内部提交无需逐个重复完整审查 |
| 阶段交付 | 对同一集成产品做场景、能力、体验的整体判断，集中展示全蓝图覆盖、增量、证据和剩余缺口；不要求用户拼接多个小包 |

普通布局、文案及低风险体验问题在既有问题／交付记录写明影响、绕行和具体返回点即可继续；改变指标含义、授权理解或误导成功状态的文案不是低风险。数据越权、隐私泄漏、错误计算／证据、预算或停止失效、成果丢失，以及本次承诺主流程无法完成，阻止相应试用／交付。安全隔离后的无关工作可继续，不无限修复外部工具。

### 7.1 必须与工程规范对齐的最小差异

- **已经允许，直接复用**：现行连续工程政策已允许受影响检查、复用有效证据、普通纠正不重复审批；PR #61 的 CI 提效不重做。SDD/TDD 保留为内部工作方式，不重新恢复 Spec→Test→Worker 的逐阶段批准。
- **本批需明确适用性**：纯浏览器交付不跑仅证明 Desktop 壳层的打包／安装／原生检查；原记录继续保留。新的浏览器连接、安全、文件和状态验证不能省略。仍有效的共享测试不可按名称删除。
- **待工程规则同步**：建议每个 Change 维护能力增量、证据和快照，日常交付正文简报增量并链接全图，阶段验收再完整展示。当前政策仍要求每个 Change 的回复展示全图；在工程规范负责人依授权完成这一个显示节奏调整前，继续用既有生成全图满足规则，不把草案当已生效豁免。无需重新编写全图或增加新台账。
- **合并保护不暗改**：日常轻量检查不等于取消现有产品 PR 的 portable required CI。复用已发布规则，完整节点按适用入口验证；若还要改 PR 触发／分流，由工程规范工作统一处理，不在此另建 CI。未通过适用合并要求就不宣称可合并。

这几项差异在同一交接中集中核对，并对唯一执行政策／必要引用作最小同步；不是新的审批链。缺权限、重大范围、安全或真实资源选择才集中询问用户。批次工程拆分不能扩大产品承诺或重置额度，也不能推导远期权限。

**“一次规划、按批授权、批内连续开发、阶段整体验收”。** 批次是授权边界，不是反复重新讨论路线；普通工程选择归 Mini，不新增 MacBook 技术签字往返。

用户已授权本轮 Git 发布与首批交接，具体接收任务由用户转发确定，不自动选择最近 session、创建或迁移任务。[近期产品片 §7.1～7.2](xanthil-task-experience-integration-proposal-v0.1.md)提供两段可转发指令，转发时附实际发布提交。首批只交接产品准备及工程规则的最小调整；接收方采用须明确读回，不能宣称已经工程接收或获准生产执行。不从历史聊天重放 Git、Provider、安装或主机操作权限。
