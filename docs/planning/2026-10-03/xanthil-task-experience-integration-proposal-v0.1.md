### 1.2 运行与启动体验

- PC 浏览器＋同机本地后端，前端复用 React/Vite 等现有基础，后端复用 Application/Core、Pi、SQLite、DuckDB/Python；不改纯静态技术栈，不新建分析引擎。首轮建议验证当前 Mac 环境，其他操作系统不自动获支持声明。
- 首次环境准备与日常一键启动分开。日常启动检查前后端就绪后打开浏览器，前端修改可快速刷新；缺工具／凭据、端口占用或后端异常说明原因和可行下一步，不暗装依赖、不杀无关进程。
- 数据根和凭据由本机服务管理，只允许所选／获准资料；浏览器传文件只到同机服务，不等于允许外发给模型。服务须防其他网页擅自访问，不开放局域网／公网；浏览器不持久保存密钥或输出到日志。
- 暂缓 Desktop 壳层、打包、安装和分发；只属于壳层的旧原生问题不阻塞浏览器试用，也不因此被关闭。移动端、云部署、远程访问和企业运维均不在本批。

## 3. 用户路径及产品边界

| 前台阶段 | 本轮产品结果 | 后台能力及覆盖 |
| --- | --- | --- |
| 分析需求 | 简单问题直接审阅简要方向；复杂但受支持的问题可讨论并修改框架；已知信息不重复问 | PIM／Semantic／Analysis；C1-01/03、A-02/03 |
| 数据准备 | 系统解释资料用途与缺口；检查真实获准文件，不要求用户配置内部清洗步骤 | 数据资格、口径与 Binding；A-01/02、B-02 |
| 数据分析 | 授权范围内自动推进真实计算／验证，呈现实际阶段、等待与失败；不是逐节点点继续 | 复用 IR／受控执行；C2-01、C4-01/02、A-03/04、B-01 |
| 报告输出 | 根据同一次已验证证据生成可读待审报告，保留来源、限制和版本 | C5-09、A-05、B-01 |
| 沟通结论 | 意见与对应报告关联；改表达不捏造事实；合法范围变更说明影响后重算 | C5-08/09、C1-03、A-04/05 |
| 确定行动 | 可仅确认分析、要求补证或记录选择及事前预期；不执行外部业务行动 | 复用 C5-01/02、B-03；不交付 C5-05 的行动执行 |
| 反馈结果 | 仅作为整体路线说明，不伪造可运行入口或完成状态 | C5-06/07、C6-02～04 留在蓝图后续返回点 |

上表描述 S1 整体目标，不要求首次内部试用同时开放全部功能。两种模式最终共享同一任务、证据和版本，专业模式提供按需检查，不产生第二套状态权威。S1 保留合格 Fork／Subagent 的入口与范围，不新增自主派发、并行、递归或自动采纳；首次试用可暂不开放其浏览器入口。C3-01 承载整体验收，A/B 贯穿，C6-01 复用历史与来源；不把家族整体标为完成。

修改需求时说明原结果哪些仍有效；实质范围或来源改变不能静默沿用旧授权。失败时说明已完成部分、原因及可行下一步。停止、保存、正式接受和预算规则复用已有能力；执行能力不足时明确拒绝或让用户选择收窄，不能以“跳过讨论”默认变更目标。

**已确认的浏览器生命周期行为，首次试用前须在适用 UI 中表达并验证**：刷新或短暂断连只重新读取状态，不调用会中断任务的“重新打开项目”，也不重发不确定命令；关闭网页不等于停止，后端可在原授权／时限内完成已启动任务，页面提前说明这一点。点击停止、退出服务或服务崩溃后，不自动新建执行或重置预算；重启只读回已保存状态，继续须有适用的人为操作与权限。多个页面不能同时成为同任务的写入控制者，Desktop 与浏览器服务不同时写同一项目。后端已保存并核验报告，与浏览器下载副本的结果分别展示，不伪造客户端落盘回执。

## 4. Demo 的采用与不采用

- **已确认方向**：视觉可沿用、停止独立美化；PC、简单／专业双模式、单入口、渐进展开和深入讨论可跳过。七步不是七道审批；纯分析允许在前六步内结束。
- **仍属参考／须确认的差异**：Demo 的具体状态、表单默认、授权材料、文件与下载交互、已确认关闭行为的提示与操作表达、未开放入口及失败恢复。只补影响本批使用的部分，不重新审整套视觉，也不将“视觉接受”升级为全部交互 UI Gate PASS。
- 不采用内存假持久化、关键词规则冒充真实理解、固定示例日期／结论冒充任意数据结果。
- Demo 中沿用的“每条报告意见单独确认”及表单数量没有因页面可运行而获正式批准。正式 UI Contract 按已批准任务授权语义处理：边界内不增加机械确认；确需新披露或新范围时再询问。不得借简化 UI 默默扩大外发权限。
- 数据检查、模型理解、分析计算、证据验证分别证明。模型回复不是独立计算核验；草稿、人工接受、决定和行动授权仍分开。

## 5. 建设组织建议

按 N01/N02 同一批逐步交付，以下是工程工作顺序，不是三个新的审批 Gate 或正式 Change：

1. **优先形成首次真实内部试用版**：复用 004 链接上浏览器、本机文件和状态，再接 N01 最小需求框架及一个获准真实模型，完成 §1.1。模拟传输可用于内部开发，不是此次交付。必需的停止、保存和授权检查不能延至收尾。
2. **边试用边补 S1**：依据实际阻塞补深入讨论／跳过、框架变化、M2、专业检查面、报告点评／重算及正式人审，接回 Fork／Subagent。不要等这些全部完成才第一次给用户试用。
3. **固定集成候选整体验收**：完整 S1 路径、变体、关键反例和兼容共同验证，展示能力增量及剩余缺口。首次内部试用通过不等于 S1 完成。

如果任务适用范围或报告交付实际妨碍试用，可从 N09／N11 前移必要子集，明确对应用户问题、增量、权限和返回点；重大范围变化仍交用户。学习闭环不是可用性的前置，不为了这次补齐整个 Pack／Studio。N05～N08 保留后续返回点，不因先改体验而消失。

工程内部小步提交、可测试、可回退；无需重新选 Runtime／数据库或启动全量重构。日常跑受影响检查，完整结果节点集中适用回归和独立审查；普通布局／文案问题可记录后继续。现有正式 Change 的验收和 PR required CI 不自动免除。能力汇报减负与工程规范同步采用[总拆解 §7](juanerai-blueprint-v4.1-full-change-roadmap-v0.1.md)，本稿不创建第二套规则。

## 6. 三类验收与未决测量

**首次内部试用的最低证据**：在正常一键入口、获准模型与数据下完成 §1.1；证明实际计划影响计算、独立核验通过、报告来源可查、用户判断按其状态保存；拒绝越权／不合格输入，停止及保存重开有效。记录固定代码／运行配置、检查结果、未开放项和已知问题。当前路径无法完成、安全／计算／授权／恢复失效时不交该路径试用；普通不影响结果的中间 bug 可注明绕行和返回点后收集反馈。

首次使用是否独立开始、首次有据结果等待、用户主动操作与重复确认、能否理解限制并作判断，从第一版就观测；不要求先证明普遍商业价值才能内部试用。场景和样本范围先定，不能把一次成功当 S1 全面接受。

**S1 固定候选的完整验收仍为：**

| 类型 | 本阶段必须证明 |
| --- | --- |
| 场景 | 用获准的代表性 CSV，在同一真实产品上完成需求、准备、分析、报告修改和人工判断；再检查改期间、资料不足、停止／重开，不用 Replay 冒充结果 |
| 能力 | 框架中受支持的真实变化影响 Contract／Binding／计划及实际计算；错误、越权或不支持的计划被拒绝；报告绑定本轮核验结果；旧 001～004 合同与成果继续可读 |
| 体验 | 首次使用者不需要他人讲解内部对象即可开始；清楚当前进展与下一步；不重复提供已知信息或批准内部节点；能解释结论、限制及下一步选择 |

使用同一任务和资料记录可取得的 Change004 基线，以及首次浏览器版本的独立完成、首次有据反馈、主动操作、重复输入／确认和结果理解。旧产品不能运行的项目标不可测，不为补齐历史基线先修 Desktop；用首次真实浏览器版本作为后续迭代基线，不填造对比收益。时间区分系统等待与用户投入；不能用操作减少抵消质量或权限边界下降。

体验样本及时间／负担阈值尚待正式产品输入中关闭；不把截图、点击数下降或测试通过替代用户结果。真实 Provider 质量、错误、预算和实际外发内容也须按获准条件单独留证；离线通过不能代替。
