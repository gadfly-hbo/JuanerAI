# PC 双模式任务原型 v0.2：需求讨论与框架共创

仅供用户讨论和体验，不是 UI Contract、正式产品要求或生产实现。旧版 `../pc-task-experience-prototype-v0.1/` 保留原样。

## 本次改动

- 保留 v0.1 的视觉、双模式和已有报告后续路径，不重做品牌或引入依赖。
- 从业务困惑进入讨论，不先要求上传两表、选择期间。回答可以同时明确用途、期间和交付对象，不重复询问已知内容。
- 同屏逐步形成分析框架：业务用途、问题拆解、范围、待验证假设、交付物；专业模式进一步展开数据、方法和判断边界。
- 支持示例回答、有限关键词输入、直接编辑框架；业务原话、用户假设、AI 建议和未决内容分开表达。
- 深入讨论可跳过：直接查看简要框架，沿用已知用途与期间；仅补必要缺口，不强制讨论假设或报告形式。可返回原讨论；跳过不改变范围、不绕过数据授权。
- 整体确认框架后，按所需证据解释资料用途；自动检查资料并沿用已确认期间，再进入任务授权、自动分析、报告和人工判断。
- 展示用户七阶段任务主线，但不是七个审批页面。当前决定仅为记录；真实行动执行和反馈结果未实现，不显示虚假完成。

## 来源及取舍

主要参考 PX-030 `PRODUCT_BRIEF.md` 中需求调研、按信息价值追问、业务框架共创与来源区分的产品语义；不复制其固定审批节点或生产合同。PX-001 的假设先行只作为后台方法职责参考，不把十五状态搬到前台。保持 Blueprint v4.1 的前后台分工，不修改蓝图、生产代码、OpenSpec 或工程状态。

## 打开和体验

仓库根目录运行：

```sh
python3 -m http.server 4186 --bind 127.0.0.1 --directory .
```

入口：`http://127.0.0.1:4186/docs/planning/2026-10-03/pc-task-experience-prototype-v0.2/`。

推荐路径：

1. 点“会员经营问题，先一起聊聊”，再“开始讨论”。
2. 选择分析用途，再说明期间；也可一次输入“我想找出下一步调查重点，看 9 月；结果给管理层看”。
3. 看框架如何变化；试着补充“我怀疑和活动变化有关”，观察它保持为待验证假设。可直接编辑框架。
4. “确认框架，准备资料”→ 添加两份示例 → 返回任务。系统检查后直接沿用已确认期间，不再问一次日期。
5. 任务授权后自动分析；报告可以修改表达、变更期间重新分析或作人工判断，沿用 v0.1 的交互。

“老会员”“首购”“活动因果”等超出当前固定示例的问题会保留为缺口，可收窄到已支持的变化分析或停在讨论，不生成额外分析结论。

简单需求可点“跳过深入讨论”，查看简要框架后“按此方向准备资料”；用途或期间缺失时就地补充，不必完成深聊。

## 明确限制

所有对话、资料、计算、核验和报告都是本地合成演示，没有真实 LLM、数据读取、上传、计算引擎或后端。自由输入只识别少量公开示例关键词；未识别内容仅保留原话，不声称理解任意需求。日期只提供两组演示范围，用户须在框架中审阅，不代表正式产品仅支持两个期间或两张表。

数据只在内存保存，刷新或关闭页面全部重置。框架共识不代替数据／模型执行授权。后续报告每条意见的授权、审阅表单等沿用 v0.1，仍为待讨论设计，不是已经认可的正式要求。预算控制、真实模型质量、跨进程恢复、隐私安全和真人易用性尚未验证。

本轮只做语法检查及一条主要可点击路径的浏览器检查；不新增测试体系或生产级异常验证。原型可运行不等于用户体验已经通过，等待用户实际反馈。
