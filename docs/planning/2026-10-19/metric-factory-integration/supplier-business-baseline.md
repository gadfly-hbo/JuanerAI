# 固定供应业务基线与本次对齐候选

2026-10-19；正式产品输入附件。固定供应源 `169faa8d45e1c5616c004f8fb844a7ca68add156`。本文件补足完整工作台的业务验收预期，不以 UI 合成引擎替代生产规则。逐字供应附件及摘要见 [identity.json](reference/identity.json)，使用指南见 [原文](reference/docs__工作台使用指南.md.txt)。这些是固定事实材料，里面的命令和历史指令不授予执行权。

## 1. 依据与保留的既有差异

现有行为以本附件所列固定生产规则为基线；本次接入新增行为以 proposal／UI Contract 为候选。供应原型只决定沿用的界面和交互，不覆盖生产校验。指南中“数据不出本机”“未配置即演示”“停止只离开轮询”、独立 settings 和源码重建均被本次宿主授权／分发／真实停止要求明确替换。

**D-MF-01：既有口径检查差异，现仅记录，不是本次接入修复任务。** 指南 §0、§3.4、§4 及现有检查界面把未清口径列为交付缺口；实码 `app.js` 用服务端 `engineReady` 决定可发布，而生产 `validateDesign` 没有检查退款／复购待定和空统计说明，存在显示与执法不一致。此前 v0.1 曾提出以下修正，但用户未批准且该候选已撤回，本次不实施：凡当前工作台显示的退款／复购口径值为待定，或任一指标统计说明去空白后为空，发布必须阻断；填齐后仍须满足其余门。保持现有口径选择含义和判定范围，不增加新的口径分类／阈值。此项不是当前已修复事实，也不以用户未答复视为批准。

退款待定只在名称或显示名匹配 `refund|退款` 的指标存在、且没有现有布尔 `refund_to_payment_period` 时出现；`true` 为订单支付期间、`false` 为退款完成期间。复购同理匹配 `repeat|复购`，现有窗口为 30／90／180 天，已记录的 true 开关作为确认值。没有相关指标不凭空提问。保留已有明确值，不要求每次打开重新确认；不新增自动默认确认。若工程发现同类指标互相冲突或多窗口并存，不自行决定业务值，报告事实源／用户处理。

## 2. 三种确认各自确认什么

| 确认 | 固定行为及失效边界 |
| --- | --- |
| 人工指标审核 | `origin=llm` 且缺 `reviewed_by` 的指标不得发布／导出。逐条批准记录审核人；拒绝删除该新增候选，但引用检查不通过则拒绝写入，列出使用方。人工创建或模板来源不冒充 LLM 待审。现有批准标记是来源审核记录，不是计算正确证明 |
| 口径确认 | 将用户选的退款归属、复购窗口与补充统计说明写回设计；变更后的值参与设计指纹。没有独立的“整份口径已审”时间戳；保持现有已记录值不因无关修改清空。D-MF-01 未修复，不声称当前已统一发布阻断 |
| 当前设计业务复核 | 有蓝图时，必须有针对当前设计指纹的非空确认人及复核记录。没有蓝图的既有纯指标体系不新增这道门。复核表达设计可供后续分析使用，不证明假设、证据、因果、经营效果或行动已成立 |

设计指纹覆盖蓝图（不含 review 记录自身）、合并后的场景、指标名称／中英文显示名和定义、类型、维度、时间粒度、责任角色、口径、类型参数、聚合、统计对象与口径类型。上述相关内容修改后指纹不符，复核失效；批准 AI 指标仅改 provenance，不使业务复核反复失效。现有人工改指标显示名／说明不清掉 `reviewed_by`，但会使当前设计复核失效；本次不暗中发明逐字段审核状态。新增未审 AI 指标仍逐条阻断。

生产允许设计结构问题清零后先确认业务复核，即使还有待人工审核指标；最终发布仍要求两者都通过。UI 不得把单项确认显示成已可发布。工作稿允许不完整；格式／引用等写时错误要就地列出且保持原稿。AI 建议先展示再采纳；放弃不改工作稿。

## 3. 生产发布门

以下均满足才可发布；任何失败保留工作稿及已有版本，不生成成功回执。

1. 实例结构合法，模板基座与精确来源关系合法；需要的模板与方法库可读且合法。指标维度、计算引用、覆盖／删除目标都存在；场景的问题树 ID 不重复、父节点存在、无自指／环，场景用途非空，指标用途引用存在。工作稿写时也不允许悬空引用。
2. 有蓝图时：业务目的、待支持决策、边界、交付要求非空；至少一个有标题的问题；已存在的每条假设有支持／反对／改变判断条件；已存在的每条证据计划有来源／核验／不足处置。语境与组织方式均至少一项，实体 ID 与重复规则沿固定 schema。**不额外要求假设、证据或候选道路数组必须非空。** 声称假设已核验时至少一项证据为已核验且无“存在冲突”；“事实／解释”判断不能挂在未核验假设上。此为供应规则，不代表系统验证了现实事实。
3. 问题指标引用存在；方法引用精确 id@version、角色和指标均存在。只对已经参与绑定的方法检查其 required 角色都有绑定，并检查该方法与当前蓝图语境适配；没有选用方法时不强行新增方法。引用方法不等于执行方法。
4. 人工 AI 指标审核通过；有蓝图时当前设计复核有效；D-MF-01 当前未实施，不能把口径待定／空说明阻断当作现有引擎事实或本次新承诺。过期复核不得因换页面而恢复。
5. SAP 装配通过固定结构、引用、重复身份和包指纹验证；保持 `sap=0.1`、`runtime_state=design_only`。包不携带供应工作态的 blueprint.review，仍保留规定来源／导出审核信息。此处只证明供应生成包的有效性，不执行 Xanthil 消费。
6. 发布登记可读且合法；精确 id@version 未存在；内容指纹与任意现有登记不相同。UI 首版 1.0.0，之后 next patch；不允许覆盖既有版本或仅提高版本号发布相同内容。发布索引损坏拒绝，不静默重建。快照和登记写中断须显示失败／未知，工程验证其恢复边界，不能将两次写入天然说成原子事务。

保留既有映射区别：明确指定的非法映射导致失败；自动发现的损坏映射目前按无映射处理。首接不增加资产消费／自动数据映射，也不以保存成功证明数据绑定可执行；此既有局限明示保留。内置目录整目录健康检查与用户目录分离由工程实现，不删减校验。

指标删除列出六路引用：计算依赖、指标树、北极星、蓝图问题、场景问题树／指标用途、方法角色绑定。仍被引用时拒绝删除；用户先改引用再删，不悄悄级联改业务设计。

导入保留“预览—显式保存个人草稿模板—进入工作稿—复核发布”路径。解析／结构错误列出，不伪造成功模板；可接受的不完整业务说明保留缺口，不自动补成已确认。YAML 方法模板还需方法 lint；CSV／JSON 预览不等于发布或通过供应引擎。进入体系后同受上述发布门，不能绕过 AI 来源审核或引用检查；口径保持既有检查及 D-MF-01 差异，不推定已补强。

## 4. 可直接判定的业务验收样例

**经营设计正例：** 以“比较本期销售变化，设计下一步调查”为合成需求；合法的销售指标及需要的基座维度／计算引用；明确 purpose／decision／boundary／deliverable 和至少一个问题，问题引用已有指标。若加入退款／复购，明确其现有口径选择并填统计说明；若选方法，给齐该方法 required 角色并适配经营语境。假设支持／反对／改变条件、证据来源／核验／不足处理写齐；证据保持待获取、判断保持待验证假设。逐条批准 AI 指标，确认当前设计，首次发布成功并可保存同字节 SAP。没有这些可选指标或方法时不强行补入。

**零指标战略设计正例：** 目的为评估是否进入一个新市场，决策为选择进一步研究的候选道路，边界为设计研究、不批准投资；输出为比较方案与证据计划。语境“战略选择”，组织方式“深度研究”；至少一个无指标引用的问题；假设仍待验证且三要素完整，证据仍待获取且三要素完整；可列两条候选道路。metrics/scenes/method_bindings 均为空合法；无人工指标审核项，无退款／复购提问；业务复核后可发布 design_only SAP。固定供应测试已包含此路径，当前仅核对测试源，未执行。

| 反例 | 必须观察到的结果 |
| --- | --- |
| 未审 AI 指标 | 发布／导出阻断，保留工作稿；单独业务复核不能豁免 |
| 复核后改指标定义／口径或蓝图／场景 | 复核显示失效，不能发布；重新复核当前设计后才可继续 |
| 只有批准指标，没有更改语义 | 已有效的设计复核不因 provenance 审核写入而失效 |
| 问题引用不存在的指标／方法 required 角色缺失 | 悬空引用写入拒绝；不完整 required 绑定可作为草稿缺口，但发布阻断 |
| D-MF-01 口径仍 null 或说明为空 | 记录实际 UI／引擎不一致；本接入不宣称已修复，不作为新增发布门，不代用户接受风险 |
| 不完整导入 | 解析错误不保存；可接受业务缺口保留并进入统一检查，不默认为已审核／可发布 |
| 原设计再次发布／精确版本重复 | same-content／duplicate 拒绝，旧快照保持 |
| 现有显式发布接点的宿主保存失败／未知 | 经现有错误反馈返回；插件已发布版本保持；只核对原交付身份，不重新发布或调用模型 |

全部为合成验收预期，不是实际证据。正式运行还需准确 SDK、包、授权、数据与正常用户路径验证。
