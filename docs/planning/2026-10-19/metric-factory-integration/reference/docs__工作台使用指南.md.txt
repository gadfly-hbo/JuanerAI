# Metric Factory 工作台使用指南

> 面向使用者的操作手册：浏览器里完成「描述业务问题 → AI 起草分析体系 → 修正微调 → 复核交付」全流程。启动方式见仓库根 [README](../README.md#web-工作台)（双击 `启动工作台.command`，或 `node dist/cli.js ui` 后打开 http://127.0.0.1:4173）。
>
> A2 起，工作台 UI 与产品评审原型（demo）严格一致：侧栏/顶栏/弹层/键盘行为/右侧 AI 助手栏逐面复刻；差异只出现在数据真实性与真实延迟的必要状态（加载/失败）上。

## 0. 开始前

- 工作台只监听本机（127.0.0.1），数据不出本机；顶栏常驻边界标签「本地工作台 · 真实引擎」，写范围说明在「方案与评审说明」弹层。
- 所有写操作（改蓝图/存场景/批准审核/发布）都经过同一套引擎校验——**校验不过零写盘**，错误就地列在弹层里。
- **写时宽、交付严**：工作稿允许带着缺口保存（边想边写）；「检查与交付」stage 会把缺口逐条列出，**缺口未清零且未完成业务复核前，交付被阻断**。
- 刷新与深链：视图地址在 `#work/<体系>/<stage>` 哈希里，刷新/分享链接恢复到同一位置。

## 1. 创建体系（三种起点，汇入同一工作台）

**推荐起点 · 首页「用一句话开始」**：用一句自然语言描述业务问题 → 「生成体系草稿」→ 生成中视图（可「停止生成」：离开轮询，需求文本保留；服务端产物不丢，会出现在「我的体系」）→ 完成后**自动创建并进入** work 视图。四条示例需求可点击填入。

> AI 草稿带未决项，需你修正与复核；未配置模型时为确定性演示模式（模板路径不需要模型）。

**次要起点**：

- **模板库 → use-template**：内置 7 个行业模板 fork 创建（带模板基座，指标全量继承）；「我的模板」（导入/另存沉淀）创建空白基座副本。
- **粘贴导入**：模板库「＋ 导入模板」→ 选择 CSV/JSON 指标表 → **浏览器本地解析预览**（行级错误、缺口口径如实标注，不上传）→ 命名保存为个人草稿模板。

体系保存在工作区 `system-<时间戳>/instance.yaml`（git 可管）；「修改名称」只改蓝图标题不动目录。

## 2. 我的体系与模板库

- **侧栏「我的体系」**：工作区自动发现的实例列表（最近编辑置顶，显示工作草稿/已交付版本）。
- **模板库**：两类——`指标体系`（7 行业 + 我的模板）与`分析方法`（6 内置方法：语境 chips + 角色 + 步骤 + 证据 + 限制；「预览与使用」进详情）。方法「引用不实现」：用于体系时形成场景并匹配绑定。

## 3. work 视图四 stage

### 3.1 体系总览（分析体系蓝图）

- **蓝图卡**：业务目的/研究问题/边界/输出要求；语境 chips（经营改善/战略选择/独立数据专题，可组合不分级）；「修正我的理解」弹层编辑。
- **问题结构 / 关键假设 / 证据计划 / 候选道路**：假设带支持/反对/改变条件三要素，「完善检验条件」弹层逐条编辑；证据带来源/核验/不足处置（**计划完整 ≠ 证据已取得**）；「查看判断边界」弹层区分事实/解释/假设/建议。
- **右侧 AI 助手栏**：输入指令（或点建议 chips）→ 生成中 → **提案卡（修改建议）先看影响再决定**——「采纳修改」写入同一工作稿（相关复核失效）、「放弃」零改动（字节级保证）。快捷指令：补充战略视角/经营落点/客户访谈证据等。
- 没有蓝图的模板实例可经助手指令补蓝图（AT1 流）。

### 3.2 指标体系

- **树/清单切换**：树按模块分组；清单表为指标/业务解释/计算关系三列。点指标卡进**指标详情弹层**（分组/衡量什么/怎么算/单位/被哪些场景引用；改名/改说明直接保存，改计算关系走 AI 建议）。
- **口径待确认**：有退款/复购语义指标时出现状态提示 → 「查看并确认」弹层集中三问（退款归属期间/复购观察窗口/逐指标补统计说明）→「确认这些口径」。
- **删除指标**：被引用时弹「这个指标仍被使用」列出全部引用方（引擎六路检查），保留并返回；无引用时确认移除。
- **＋ 添加指标**：一句话描述 → AI 候选建议流（先看建议再采纳）。

### 3.3 场景与方法

- **场景 pills 切换 + 场景卡**：准备怎么分析（步骤列表，读自方法模板）/指标怎样参与（角色绑定 chips）/方法适用性与判断边界。
- **修改分析步骤 = 沉淀新方法**（G8）：「修改分析场景」里改步骤并保存 → 自动「另存为新方法」（templates/methods/ 落盘，场景改为引用新方法；同名不覆盖）。
- **调整绑定**：弹层内按角色选择指标（角色：结果指标/驱动指标/护栏指标）。
- **新增场景**：一句话需求 → 方法模板选用流生成场景草稿。

### 3.4 检查与交付

- **检查行全集**：①问题、假设与证据计划 ②指标定义与计算关系 ③需要你确认的业务口径 ④方法、指标角色与适用条件 ⑤当前设计的业务复核 ⑥**待人工审核的 AI 指标（N 项）——行内逐条「批准/拒绝」**。
- **业务复核**：缺口清零后「查看并确认」→ 弹层概览设计内容 →「确认当前业务设计」（复核人取环境约定）。**复核绑定设计快照指纹**：相关修改使确认失效，需重新确认。
- **交付**：「生成设计版本」一键确认（自动 next patch，如 1.0.0→1.0.1）→ releases/ 不可变快照登记。**内容未变时拒绝重复发版**（same-content）。
- **已交付块**：版本号 + 「保存指标体系模板」（另存我的模板）/「保存分析方法模板」+「下载设计包」（SAP 快照直链，含指纹与蓝图段）+ 更多格式（MetricFlow/Excel/Mermaid）。

## 4. 状态与错误怎么看

| 你看到 | 含义 | 下一步 |
|---|---|---|
| 生成中视图打转 | LLM job 运行中（faux 即时） | 等待或「停止生成」 |
| toast「生成未完成：…」 | 模型输出未过校验（零落盘） | 调整描述重试 |
| 弹层红字错误列表 | 写入校验未过（零写盘），输入保留 | 按列表修正后重提交 |
| 检查行「!」图标 | 对应缺口阻断交付 | 点右侧按钮去处理 |
| 「复核已失效」语义 | 复核后设计被修改 | 重新确认 |
| toast「无需重复生成」 | 内容与已交付版本相同 | 无需发版 |

## 5. 边界（设计如此，非缺陷）

- 单用户本地工具：无登录、无多人协同、无云端。
- 助手对话为会话内存态（刷新清空）；工作稿全部落盘。
- LLM 配置在 `/settings` 工具页（.env.local，页面打码）；未配置时 faux 确定性演示。
- 升级代码后双击启动会自动重建（源码比构建产物新时）。
