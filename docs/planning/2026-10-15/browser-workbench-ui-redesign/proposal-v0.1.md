目标：将当前浏览器工作台整体对齐用户附件的安静浅色、稳定项目侧栏、对话／成果／依据三视图、单一证据检查器和报告编审布局，同时保留专业六阶段及所有已实现、已批准的适用能力。使用户在同一任务中清楚知道：现在分析到哪里、结论依据是什么、选中了什么、报告改了哪一版、谁确认了什么、什么变化使确认不再适用。

## 2. 产品范围与非目标

范围是浏览器 Personal 工作台：新建需求、资料与口径、受控分析、循证对话、结果表与报告、已有正式评审／反馈入口、同任务助手和既有协作、项目口径资产维护。桌面宽屏和窄屏浏览器均覆盖。

不包含 Electron／原生 Desktop 壳交付、全新账号或插件平台、企业权限／协同编辑、完整 Report Studio、富文本排版平台、外部发布、真实行动／Actual 闭环、通用 Agent 平台、新数据连接器、模型／Pi 迁移、依赖升级。原专业能力不是删除对象；未实现功能不能用假按钮冒充交付。

本包不新编 Change 编号、不改蓝图顺序。它是针对已有 N01/N02 工作台的用户指定体验改造，以及完成该体验必要的 C5-09 报告表达子集；不据此启动 N11 全量 Report Studio。后续工程可组织结果包，但不能拆掉端到端验收或静默删范围。若要改变阶段排序／全量能力目标，另请用户决定。

## 3. 当前事实与改造判断

现工作台为原生浏览器 JS＋CSS，服务端已有任务、版本、资料、计算、核验、报告、协作和口径资产。已有功能不需要因视觉改造被重写。当前页面存在双顶栏、多个竞争操作区、底部固定输入和内容散布；专业与快速模式共享任务，但切换时页面展开状态会复位。重绘整块 DOM 可能影响选区／编辑焦点，因此不能把文本选区仅当一个 CSS 效果。

现有报告用户表达为追加记录，不是单一编审稿；现有“认可分析”绑定 outcome／分析 revision，并不绑定报告表达版本。资料预览有截断，不提供完整原始行稳定身份。于是：主布局、视觉与导航可主要在展示层调整；稳定引用、单稿编审与报告内容确认需要受控的应用／存储契约增量，不能承诺只改 CSS。精确工程接口、持久格式与迁移方案由 Mini 在批准边界内设计，保留旧数据和旧确认含义。

当前基线与已知接受见能力表：005v1.3／006／R1–R4 具有各自限定验收，SDK 0.5.1 受控采用已集成且限定离线工程接收；不代表真实 Provider／生产常态使用／S1 已通过。Change007 是另一个已冻结产品输入，不因本次 UI 准备变成已实现。本包原型中的新编审不属于当前产品能力。

## 5. 五项设计原则

1. 一项任务一套上下文。切模式、视图和阶段不丢任务、版本、草稿、选区与可恢复阅读位置，不隐式发请求。
2. 对话推进，成果可独立阅读。专业性通过实际六阶段和可展开依据呈现，不把内部对象堆给普通用户。
3. 主稿只有一份当前保存版本。事实、模型解释、用户修改、建议和正式决定有清楚来源，不靠色彩独自区分。
4. 确认精确绑定内容。改变了什么，就只让受影响确认失效；历史不覆盖，不重复无意义授权。
5. 严谨后台化。证据与权限随时可查；只在实质澄清、授权、决定或冲突时打断用户。

## 7. 选区引用的业务合同

引用是任务内待发送上下文，不是新业务事实或数据访问许可。引用卡至少可辨项目／任务、分析版本、资料快照、表或结果、行稳定身份或报告段落、显示范围、采集时刻与有效性。工程内部字段／散列算法不在产品侧预定。

数据引用支持当前产品已提供稳定来源的结果行；原始资料截断预览只允许已具备可读稳定身份的范围。没有稳定行身份时禁用“引用这些行”，解释原因，允许查看资料；禁止以 DOM 序号冒充行身份。排序／筛选不改引用指向，不假装勾选了全量资料。正文引用使用任务报告内容版本与段落身份；跨段落或不可稳定定位范围要求分段，最多1500字为本包提出的单卡体验上限，超过先提示用户缩小，不截断后静默发送。

用户通过鼠标选区、键盘选区或“引用此段”获得同等入口。引用选择后进入同任务输入卡，可写追问、移除和回到来源。切视图／模式保留；切任务则保留在原任务草稿，目标任务为空，不带过去。来源或分析版本改变后旧卡仍可看但标“已过期，需重新选择”，发送禁用；不自动重绑定。权限撤回／新读者无权则不展示未授权正文，卡显示不可用；不回显禁止的数据。

发送前现有权限控制复验；需要新的明细／模型数据边界就询问用户，不在引用动作中顺便扩权。局部改写只可作用于可编辑解释段，事实段可引用不可改写。产品不得仅因选择文字而调用模型或写报告。

## 8. 报告编审与确认合同

### 8.1 主稿及编辑

每个任务／分析结果有一份当前保存的报告内容版本，含锁定事实、指标口径／范围、已纳入发现、解释／建议表达、必要限制与来源。保留生成原文、每次用户保存及应用建议的历史和操作者来源；历史只读可比较，不覆盖原事实。旧追加表达仍按原意展示；不擅自折叠成已获确认的新单稿。

本期支持纯文本解释段编辑、将已验证且适用的发现纳入主稿、段落级建议、比较／应用／放弃、当前版预览和现有受控导出入口；不做任意删改事实、拖拽排版、多人同时编辑或全文自由重写。加入未核验意见只能作为清楚标注的讨论，不进“已核验事实”。必需限制不能删。现有导出格式／权限不扩张；原型下载仅合成文本副本并带醒目标识。

改写指令限定“表达方式”，用户可手改解释，需改变业务主张／数字／口径的请求转入既有分析修订及受影响重新计算，不能在报告编辑器里伪装完成。改写建议保留发起时任务、分析结果、报告版与目标段内容身份；生成期间不锁死阅读，但编辑／换版后建议变为过期，不可应用，用户可放弃或在新版重新请求。无自动覆盖、自动重试或无限生成。

可编辑解释始终标 USER／建议来源与“未经新增事实核验”；用户在自然语言里写下新断言，不会更改锁定事实或获得已核验标签。事实调整入口显式返回分析修订，不承诺靠UI自动识别所有自然语言矛盾，也不默许用用户确认补成事实证据；必要限制仍不可删除。是否适合采用该解释由用户在内容审核中判断。

草稿与已保存稿明确分开。手改后按钮“保存这段表达”；保存成功后才产生内容版本、更新当前稿并使内容确认失效；无变化保存不产生新版本。保存失败保留草稿，不能显示已保存；结果 UNKNOWN 时先查询既有请求结果，不直接再次提交。离开有未保存文本的任务可保留草稿或显式放弃；不默认丢弃。

### 8.2 三种不同的人类记录

| 记录 | 绑定与意义 | 失效／历史规则 |
|---|---|---|
| 旧“认可分析” | 既有分析 revision＋outcome／结果身份；用户对当时分析的判断 | 表达润色不擅自撤销旧认可，也不能宣称它确认了新版报告内容；分析变化时只读历史 |
| 新“确认这版报告内容” | 精确当前报告内容及其分析／来源身份；表示用户已审阅这版表达及所列限制 | 成功保存任何内容变化（解释、纳入发现、数字／范围／口径／证据／限制）后不再适用；显示原因及前版确认历史 |
| 正式业务评审／决定 | 现有适用方案与结论、证据、Owner、候选／不行动／推迟、观察窗、风险与 guardrail | 不因确认报告自动生成；新报告不自动更新或重新批准旧决定；受影响旧决定标历史／需重新评估 |

内容确认前必须是当前已保存版本、无未保存改动／未决建议冲突／UNKNOWN／写权限问题，必要来源身份完整。确认对象可为明确标注的 partial 报告：按钮与记录注明“仅确认这版部分结果与限制”，不代表任务完成或证据充分。过期／仅历史报告不可当作当前确认。已保存未应用建议可放弃后确认，不强迫采用。改写生成中允许阅读，确认须先结束／放弃该建议，避免用户误认成候选内容。

布局、视图、模式、滚动、面板宽度、仅下载副本不改变内容、不使确认失效。确认不是运行许可；不增加再次分析／明细读取额度。未确认报告可预览，受控导出显式标“未确认”；已确认导出显示内容版本，后续改稿不追改历史文件。确认失败不显示成功；UNKNOWN先读回。旧确认与决定原件永久保留，不删除、不回填。

## 9. 兼容、状态与安全

同一任务的解释权和运行状态来自同机后端，浏览器 UI 草稿／阅读位置不是第二业务 authority。重绘不得误丢草稿、引用、焦点与稳定段身份；实现方法由工程选择。并发写／控制权变化／新版本冲突不得覆盖，先展示本地草稿和服务端新版本，再由用户选择保留草稿用于重新编辑或放弃；不提供强行覆盖按钮。

启动、继续、停止、未知结果处理和累计资源边界沿用现合同。刷新或重新打开只恢复读回，不自动续跑；不可用数据、空任务、无报告、证据不足、unsupported、零分母、只读、保存失败、网络中断均有独立状态。进度条只能表达真实事件／可辨等待，不估造百分比。

不输出凭据；不复制真实项目／数据库。保持 loopback、跨站与控制权防护，不以新 UI 放宽 same-origin、权限、文件来源及数据入模边界。引用／文本编辑中的内容一律视为数据，不执行嵌入指令／HTML。不存在的插件／账号能力标“未接入”，不得诱导授权。
