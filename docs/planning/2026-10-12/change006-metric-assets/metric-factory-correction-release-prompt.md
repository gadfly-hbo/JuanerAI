## 3. 必须落实到正式资产的净销售口径

### 3.1 消除循环与双扣

当前固定旧包 `gmv = uv * cvr * aov`、`aov.numerator=gmv` 构成依赖环；cvr按用户而aov按订单，也不能把该式当金额恒等式。新净销售闭包不依赖这条错误恒等式。

GMV 明确为合格成功支付订单的**原始成交金额，包含后来发生退款的订单**；按实际金额汇总，原始gross只计一次。不含运费／内部渠道等已声明规则要与所需字段一致，不能猜客户默认，也不能先把gross净额化再扣退款。`net_sales = gmv - refund_amount` 继续由资产明确声明。订单数分母同样包含符合资格的已退款支付订单，相关描述／开关不得相互矛盾。

有限消费范围为明确基础度量及 sum／count／业务键count-distinct、同包无环加减乘除派生式、从分子分母重算的比率、声明适用的维度／粒度、两种退款期间归属。不要引入任意 eval／SQL／脚本、跨包公式、滑窗、复杂DSL或暗中新增执行引擎。

### 3.2 两种退款金额归属

- 支付归属：截至观察截止已完成的合格退款，归入关联订单的支付期间；不得漏掉跨期才完成的退款。
- 完成归属：退款完成时间在所选期间内的合格完成退款计入该期，包含支付发生在本期之前的历史订单；必须可关联历史订单并核验其资格，不能先按本期支付窗口丢掉它。
- 两版均 `include_pending_refund=false`；退款中、失败、取消不得按金额存在就纳入。首期不支持将该开关改成true，必须明确其不支持效果。
- 明确时区、`[开始,结束)` 边界、观察截止、时间粒度／周边界、金额单位、状态映射和范围规则。客户字段、状态值和实际窗口在后续当前任务 Binding 中确定，不硬编码客户配置。
- 订单身份唯一、退款身份唯一，每笔退款恰关联一个合格订单，1:N多退款合法并逐笔计金额。重复身份、孤儿退款、负退款／混币等不合格单位、累计退款超过可退款金额而无合法解释时阻断依赖，不静默去掉异常。分组使用已声明的关联订单属性，不暗改分类。

### 3.3 两版保持同一个退款率

退款率是**支付订单队列退款率**，不是所有本期完成退款的比例：

- 分母：支付时间在所选窗口内的合格成功支付去重订单数，包含已退款订单。
- 分子：上述同一队列中，截至观察截止至少有一笔完成退款的去重订单数；同一订单多笔退款只计一个。
- 两版金额归属开关不改变该队列、窗口或分母。完成归属版可把历史订单本期退款计入本期退款额，但该历史订单不进入本期支付队列退款率。
- 资产明确提供分子／分母指标引用及对应资格、身份、筛选、窗口和截止语义，不能仅靠一段文字让 LLM 临时编公式。比率按实际分子／分母重算，不能加总或平均组内比例；总体去重数不能机械相加。
- 报告／场景定义明确金额归属与队列退款率的区别，不用后者解释全部本期退款风险。
