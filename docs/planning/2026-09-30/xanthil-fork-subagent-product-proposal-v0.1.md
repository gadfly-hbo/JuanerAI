## 2. 共同来源、身份与授权

### 2.1 建议的最小准入

入口位于已有 Quick Case Assistant；父对话必须关联当前 Completed 专业 Case revision，并仍有 accepted Finding、有效 Closure 和 final report。不会把专业 Session 转成 Quick，不新建分析 Case 或复制原始数据。

创建／运行子对话时显示来源父对话、分叉点或任务目的、Case revision、正式决定基线、选定历史／报告和获准聚合子集。建议仅从根 Case Assistant 发起本片的子对话，子对话不再显示创建下一级 Fork／Subagent 的执行入口。

父消息后来增加不自动进入已创建的子上下文，也不单独使其过期；Case revision、授权数据或正式决定基线变化则按现有资格规则阻断。旧结果保留来源关系，不迁移到 latest。

### 2.2 子任务有自己的授权

本地创建对话不调用模型。运行前重新预览任务、确切所选历史／报告和数据、Provider／Model、只读业务工具、轮次／执行时间／等待截止／费用边界，单独确认自由文本外发；父任务批准不自动变成子任务批准。

仍只使用既有五种只读业务能力：读取 Case、证据、候选、聚合及报告。子任务不能借其父子关系读取未选历史、其他 Case、原始行、文件、日志、密钥或扩大工具。实际限额必须明确展示；具体数值留待任务配置／工程接收，不编造产品阈值。

父 Attempt Running／Waiting 时提示先结束当前任务，不隐式停止父任务、不排队后自动启动。另一个模型任务占用时也明确阻断；模型接入保存／删除仍遵循原互斥与授权失效规则。

Product Session／子对话、Case revision、Analysis Run、Assistance Attempt 和 Pi 内部 session 各保留其意义。对话层父子关系不使用 Pi 会话标识作为业务身份。精确内部类型、存储和兼容映射留给工程。

## 3. Fork：用户控制的另一条讨论路径

1. 用户选择父对话已保存的位置，预览截至该位置要继承的历史／报告及获准数据，输入本次讨论目的；取消不创建可用分支或调用模型。
2. 成功后出现独立子窗口，显示标题、来源父对话、分叉点、继承范围和返回入口。历史继承注明来源，不伪装为子对话重新产生的消息。
3. 用户按 §2 授权后进行真实有界多轮讨论。子对话输出是建议／草案，不能直接走正式决定采纳。
4. 建议用户明确选择一条已完整保存的结果／摘要作为回流项；不默认回流整份聊天历史。Fork 结果留在子对话，直到用户点击 `回流到来源对话`。
5. 回流成功仅生成一个有来源的待审项。重复回流同一结果不重复创建身份、父消息或报告；新的讨论结果与旧结果区分，不覆盖已审结果。
6. 回流失败保留子结果，可显式重试同一回流，不重新调用模型。过期／父对话不可用时说明原因，不把结果放到其他父对话。

Fork 不是分析快照复制或正式决定分支。它和父对话仍关联同一 Case 来源；新分析、采纳正式决定及数据修改继续走原用户流程。

## 4. Subagent：一次有界检查

1. 用户从根父对话输入一个明确子任务，例如“检查候选 A 的反证与限制”，选择必要历史和获准资料，查看并确认自己的授权。
2. 在独立任务窗口显示任务、来源、范围、运行／等待状态及停止入口。子任务可在自己的窗口追问用户，仍遵循独立等待截止；不唤醒父模型、不自行产生下一级任务。
3. 一次只运行一个子任务。成功须有完整、通过结构和来源核对、已保存的结果；模型说“完成”或仅有部分文本不等于成功。
4. 成功自动向原父对话回流一次待审结果，子窗口显示 `已回流`；不会自动采纳或继续父模型。
5. 任务失败、停止、超时、预算耗尽或 Interrupted 不产生成功回流。失败原因和真实历史可查看，父对话仍可使用。未达成功条件的内容仅为历史／中断前内容，不冒充成功子结果。
6. 任务成功但回流失败／超时：子窗口保留成功结果，显示 `回流失败` 和 `重试回流`；父对话没有虚假成功项。重试只做本地回流，不重新执行任务或计为新模型成功。

本片的 Subagent 是用户启动的有界子任务，不是 Agent 自主编排平台，也不等同于独立验证者。同源模型意见不能计为新数据、独立证据或因果证明。

## 5. 回流、采纳与正式业务记录

| 用户动作 | 允许的结果 | 不允许的结果 |
| --- | --- | --- |
| 回流 | 父对话出现待审项，带子类型／身份、结果版本、来源 revision、范围、执行／回流状态及查看入口 | 不变成已采纳材料，不自动外发，不改 Evidence／Finding 或报告 |
| 采纳子结果 | 审阅确切目标后，把该版本作为有来源、模型生成的材料加入原父对话 | 不替换原草案，不创建／修改正式决定、预期或报告，不升级为验证证据 |
| 拒绝子结果 | 保留拒绝及来源历史，不进入已采纳材料 | 不删除子对话，不伪造任务失败或改写已回流历史 |
| 父对话继续 | 用户选择要外发的已采纳材料，按原精确授权创建新 Attempt | 回流／采纳不启动模型，也不授权整份子历史 |
| 发布正式决定 | 仍通过 Change 002 的人工审阅、当前资格、正式采纳及版本追加流程 | 子窗口、回流和子结果采纳均无直接正式发布通道 |

建议采纳／拒绝提交绑定用户实际审阅的子结果和版本；期间来源、正式决定或目标变化时阻断，要求重新查看。重复提交同一动作不追加重复父材料。局部失败不显示半成功；结果保持可读并允许安全重试。

来源过期后，已有待审／采纳材料继续作为带过期标记的历史可见，但不得在当前来源下采纳或外发。重新绑定当前 revision 时，只允许逐项重新授权用户约束，不默默继承旧模型结果、Evidence／Finding 或工具回执。

## 6. 停止、窗口关闭与恢复 — 建议连接语义

- 切换模式、切换查看父子对话或返回来源仅是导航，不停止任务、不扩授权。
- `停止` 阻止后续模型／工具调用；迟到返回不能恢复运行或补出成功／自动回流。
- 建议独立子窗口提供明确 `关闭并停止`：存在 Running／Waiting 时告知会中断；关闭使该子对话未使用授权失效并终结活动 Attempt。保存的成功结果及已回流项不删除。
- 建议实际 `关闭父会话` 时明确告知，会一并中断该父关系下未结束的子任务并使其待用授权失效；不是后台续跑。仅离开父视图不等于此关闭动作。
- 应用退出／崩溃后重开，遗留 Running／Waiting 显示 Interrupted；不恢复 Pi session、不自动重发模型请求。
- 建议成功但尚未回流的 Subagent 结果在重开后显示 `待回流恢复`，用户明确重试；这是本地回流，不恢复模型任务。父来源过期则保留结果并阻断回流／采纳。
- 已回流／已采纳／已拒绝状态及来源可重开读回；重复恢复或回流不产生重复项。
- 继续模型工作须重新披露选择的上下文并创建新 Attempt，不复活原终结 Attempt。

父子关闭／恢复连接处须由正式 UI 场景与全文审阅确认，不是从单会话规范直接推导的旧批准要求。

## 7. 增量 UI 范围及 Gate 场景

沿用第二 Change 的 JuanerAI logo、slogan `持续做出更好的决策`、三栏及品牌／交互质量。专业模式完整流程以 PX-2026-004 为参考；快速模式、模式切换、独立 Fork／Subagent 对话及回流／采纳以 PX-2026-006 和[保留 UI Contract](../2026-09-18/xanthil-desktop-ui-contract-v1.1.md) §4.3–4.5 为参考。Demo 交互不是生产实现证据。

建议增量界面：输入区保留两个既有位置，准入满足后显示真实功能；左栏显示根对话下的子对话；独立子窗口显示来源、任务／分叉点、状态、返回及停止；父对话新增待审结果，右栏继续显示来源和授权。专业六阶段及原正式采纳／报告 UI 不替换。

正式可点击 UI Contract 尚未制作，不能宣称 UI Gate PASS。至少覆盖：

1. Fork 创建、取消、历史选择、独立讨论、人工回流及重复回流。
2. Subagent 正常运行、子窗口追问、成功自动回流、失败／停止无成功项。
3. 回流失败、重试及成功后待回流恢复，不重新调用模型。
4. 查看子来源、采纳／拒绝、重复提交，及正式发布与子结果采纳的区别。
5. 父 Running／Waiting 或其他任务占用时阻断，顺序执行提示。
6. 来源／正式决定变化、旧子对话保留和过期采纳阻断。
7. 视图切换、关闭子窗口、关闭父会话、重开及无后台自动运行。
8. 未配置模型、拒绝外发、失败手动路径、键盘／焦点及原功能回归。

工程接收后拥有精确合同、Schema／迁移、资源实现、事务、错误分类和测试组织；不能以既有 Session 创建代替父子来源关系，或用正式 adopt 代替子结果采纳。

竞争价值假设：减少主对话混杂，让用户比较另一条思路或检查反证后再使用。需验证独立操作、来源／状态辨认、回流与采纳理解；不编造质量提升率、节省时间或多 Agent 优于单 Agent 的结论。

完成本片后回到结果回访／复盘，再到改进与下一 Case 显式采用。未完成 Subagent 时不能把整个 Change 003 标成已交付；无法在批准边界完成须直接向用户请求范围决定，不自动拆成永久 Preview。
