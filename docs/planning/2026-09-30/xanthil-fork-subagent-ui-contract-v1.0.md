## 2. 页面与信息架构

根窗口维持三栏：左侧父子树与历史；中部对话／任务、状态和待审结果；右侧来源、授权、材料、历史。Fork／Subagent 创建及授权用明确对话框，不在聊天里隐式派发。

子窗口也是独立三栏工作区，显示自己的类型／标题、父来源、分叉点或任务、授权、Attempt 历史、停止和结果。不是仅在父消息流画一张“子对话卡”冒充窗口。父树显示活动状态、已保存结果与打开入口。弹窗被浏览器拦截时可从可见链接再次打开已创建子窗口；该降级不扩大范围或调用模型。

专业来源模式保留六阶段导航和当前正式记录；“返回父对话”只是导航。对话历史、已采纳子材料、正式记录分开，模型意见始终有来源等级和版本。

## 3. 可见行为合同

| UI ID | 正例与可见内容 | 阻断／失败／边界 |
| --- | --- | --- |
| UI-FS-01 来源准入 | 根来源显示 Completed revision、accepted Finding、Closure、final report、当前正式决定基线；打开专业来源 | 不满足时解释具体缺项；不能创建可用子对话或 Attempt，不自动 latest 重绑 |
| UI-FS-02 Fork 创建 | 从已保存父消息选择分叉点、仅其之前的继承消息／回执和报告，显示任务目的及来源；确认只创建本地子对话 | 取消／创建失败无半成品；未勾选历史不继承，分叉点后的内容不可勾选 |
| UI-FS-03 Subagent 创建 | 输入一个有界检查、选择上下文，明确单层、单个任务 | 不自动派发、不递归、不让模型自己选工具范围；创建无模型调用 |
| UI-FS-04 独立子窗口 | 有独立地址／窗口、父子树定位、任务／分叉点、自己的消息与 Attempt；返回父来源不混并历史 | 仅根有执行派生入口；历史可重开；浏览器拦截提示及可点击备用入口可见 |
| UI-FS-05 精确授权 | 开始前看到任务、选择的父历史／报告／子材料、聚合 artifact／hash／字段、五只读工具、Provider／Model、Skill／Prompt、轮次／执行／等待／费用上限和自由文本外发确认；Fork 下一 Attempt 默认不勾选自身历史，用户逐项选择保存的用户／模型消息、回执和结果版本，看内容、来源、原 Attempt／状态 | 缺失或失效配置不可开始；新上下文／限额须新预览和新 Attempt；未选自身历史和结果不发送，不由 Pi 隐式恢复；默认不带回流材料、原始行或新工具；同 Attempt Waiting 回答仅逐条确认当前可见文本，不扩原边界 |
| UI-FS-06 顺序模型任务 | Running／Waiting 有可见占用者和停止入口；父可浏览，子须等父终结或显式停止后重试 | 不自动停止、不队列启动；Waiting 也占用；父／子／三辅助／接入变更不并行 |
| UI-FS-07 Fork 完成与回流 | 成功保存的完整结果显示版本／来源；用户选择一份再点击“回流到来源对话”；父收到一份待审项 | 失败／中断／部分文字不能回流；重复回流无重复项；新版本不覆盖旧版本 |
| UI-FS-08 Subagent 成功 | Running／Waiting／成功／失败／停止等状态区分；成功结果有摘要、引用、限制并自动回流待审，不启动父模型 | “依据不足”可以是完整意见；执行失败／超时／预算／取消／Interrupted 无成功结果和伪成功回流 |
| UI-FS-09 回流失败与恢复 | 任务成功、回流失败分别显示；保留原成功结果；本地“重试回流”，读回确认已回流 | 不再调用模型；幂等；父关闭／来源过期先阻断；重开成功未回流项须显式重试 |
| UI-FS-10 人工处理 | 待审显示子身份、版本、来源、范围和状态；查看原结果；采纳／不采纳确认绑定该版本 | 取消无变化；失败无半成功；一个版本仅一次终结处理；拒绝不能靠重试变采纳 |
| UI-FS-11 父继续 | 采纳仅追加 MODEL 用户采纳材料；父新 Attempt 明确选择、披露该材料，新的草案仍需原正式流程 | 回流／采纳不自动外发；不编辑原草案／用户文字，不直接改 Evidence／Finding、DR／EO、报告 |
| UI-FS-12 来源过期 | revision／正式决定基线／数据资格／授权变化显示过期及变化前后；旧历史仍可读，提供回到根重新绑定入口 | 阻断新运行、继续、回流、采纳和外发；不自动套用最新源；普通父消息新增本身不失效 |
| UI-FS-13 停止、关闭、重开 | 停止始终可达；子活动时“关闭并停止”确认；父实际关闭明确停止关联未完子；取消保留；重开历史及 Interrupted／待回流恢复 | 导航／模式切换不关闭；迟到结果不启动／成功／回流；应用重开不重发模型，授权失效；不确定提交先读回 |
| UI-FS-14 专业不变面 | 六阶段／来源／正式记录与报告 v2 可读；采纳子结果后仍保持；链接旧完整合同 | 不增加第七阶段，不把子材料当证据，不以新卡片替换原分析／报告能力 |

所有禁止效果是工程验收要求，不只是前端按钮灰显。原型只能让用户评价信息与流程，真实来源检查、事务、副作用和原生窗口行为须后续工程验证。

## 4. 用户 UI Gate 场景

通过启动说明打开本地 HTTP 入口。右下角“UI Contract 场景”只设合成前置状态／结果；不代表生产菜单或工具。用户沿实际按钮完成任务，场景注入不代替操作。

| 场景 | 操作／应可评价的结果 | 对应 |
| --- | --- | --- |
| A 完整 Fork | 查看根来源 → 选分叉点／历史 → 创建独立窗口 → 精确授权 → 成功 R1 → 新 Attempt 默认无子历史，选择 R1 再问“展开第二点” → 成功 R2 → 手动选择一份回流 → 查看并采纳；R1 保留，未选历史不外发 | 01、02、04、05、07、10 |
| B 完整 Subagent | 创建单项检查 → 独立窗口授权 → Waiting 回答 → 成功自动回流 → 人工不采纳 | 03、04、05、08、10 |
| C 顺序互斥 | 父 Running 或 Waiting 时尝试子动作；显式停止父后重新尝试；子运行时看父／专业页 | 06、13、14 |
| D 失败与中断 | 子模型失败、等待截止、费用／时间上限、用户停止；历史及原因可读，没有成功回流 | 08、13 |
| E 回流故障 | 成功结果但回流失败 → 明确本地重试 → 父唯一待审；重复不增加项／材料／报告 | 09、10、11 |
| F 人工边界 | 取消采纳无变化；采纳一份／拒绝另一份 → 父材料与审阅记录正确；专业正式记录不变 | 10、11、14 |
| G 新父 Attempt | 父继续前逐项勾选已采纳子材料并看精确内容／来源；不勾选不外发，不自动继续 | 05、11 |
| H 来源变化 | 已保存结果时使 revision 或正式决定基线变化 → 尝试回流／采纳／继续 → 阻断且历史保留 | 12 |
| I 关闭与重开 | 运行时取消关闭 → 仍运行；确认关闭 → Interrupted；导航不停止；重开不自动模型／回流 | 13 |
| J 设计及视口 | 根／子／对话框／专业页在 1440×900 和 1280×720；键盘操作、清晰来源状态、品牌／旧 UI 延续 | 全部 |

可点击附件应提供正常流程与最重要负例的直接演示。未模拟的真实进程崩溃、提交不确定、结构验证、全部接入配置变体和 Adapter 负例，明确留给工程而非声称由静态 UI 证明。用户 Gate 看流程、语言、信息层级和控制点，不需要操作 JSON／Schema／命令才能判断产品行为。

## 5. 可访问性、密度与实现自由

最低桌面验收视口 1280×720，参考视口 1440×900。三栏、对话框和主动作无横向溢出或不可达按钮；内容可滚动而停止和来源仍清晰可达。状态不仅依靠颜色，危险动作不与主要继续混用。

原生按钮与有名字的输入；可见键盘焦点；对话框标题关联、焦点进入／限定及 Escape 取消／返回触发者；状态更新有可读文本及礼貌通知，不把动画作为完成证据。遵循现有 UI 标准而非泛化 skill 的主题建议。

本合同不冻结 exact DOM、TypeScript、窗口 IPC、存储表、端口、资源数字或测试机制；工程可采用满足产品验收的最简单实现。不得删减独立窗口、精确授权、成功门控或人工边界来简化实现。
