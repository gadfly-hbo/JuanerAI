## 4. 哪些内容必须审查

重要主张包括任务答案和摘要中的业务判断、变化原因／归因、适用范围外推、因果措辞，以及全部行动推荐、预期收益、关键风险与条件。按内容与业务影响识别，不按卡片标题或是否有数字选择；不能把主张藏在正文、下载版或Expected里绕过审查。普通事实呈现继续受既有数字／引用检查。

结论审查逐项回答：

- 同版证据究竟支持观察、关联、候选解释还是因果？量、单位、期间、总体／分组与业务口径相符吗？
- 哪些证据支持，哪些反驳？有没有被忽略的缺数、选择偏差、退款归属／资料变化、替代解释？
- 在实际支持的方法和资料范围内，是否足以回答当前问题？尚需什么检查？

策略审查逐项回答：

- 建议面向什么目标，依赖哪条结论？该结论被削弱时建议受什么影响？不行动／补证是否合理备选？
- 谁实施，是否具备权限、资源和约束？代价、主要风险、停止条件及效果验证安排是否明确？
- 建议可以是可验证的受限试点，不要求预先证明未来收益；但不得保证收益，或把原因成立当行动有效。未证实的收益只能为显式假设，不填成已证事实。

使用已有明确配置和用户已给条件；缺关键事实只问影响判断的一题，不新增专业问卷。没有经营目标时沿用任务目的，不强制新建OSM目标对象。所谓“独立”见§6，不是另一模型说同意。

## 5. 判定、问题类型与交付效果

四种是**每条主张／选项完成审查后的判断**，不是任务运行状态，也不是整份报告的总通过标记。

| 判定 | 含义 | 必须影响的呈现／交付 |
| --- | --- | --- |
| 有支持 | 当前可用证据足以支持这项明确、有限的主张或建议；未发现未解决的承重冲突 | 可在结论／推荐区呈现；仍显示方法、范围和未知。不叫“语义／因果认证”或收益保证 |
| 有条件支持 | 支持只在列明条件／范围成立；条件有已知依据，未满足项和确认状态可查 | 条件紧邻主张；关键实施条件未满足时只为待满足的受限选项，不显示“可直接实施”。条件不能藏在脚注 |
| 证据不足 | 无充分依据支持关键部分，或缺少可判资料／方法 | 从已核实结论／正式推荐中移出；保留待补证解释、检查建议及有效事实。不是判“为假” |
| 存在冲突 | 同版可用证据、已确认口径或硬约束与主张／建议有承重矛盾 | 明示冲突位置；受影响内容不作已核实结论／正式推荐，修订后重审。不能多数投票化解 |

“未开始／审查中／无法完成／已停止／结果未知／需重新审查”另列运行状态。不能把失败变成证据不足、把取消变成存在冲突，也不能用历史成功填当前未审。

区分三种问题来源：①**数字检查**（未绑定数字、核验失败、单位／期间／范围错配）；②**结论判断**（证据不足、替代解释、无因果资格）；③**建议条件**（目标／资源／权限／风险／验证安排）。三者独立读回，修好②③不改变①的partial，除非已有数字链为新版本提供真实修复证据。

硬边界包括计算／来源／身份错配、未获准材料／工具、未解决的承重矛盾和虚假认证；系统不把相关内容作为已核实结论／正式推荐。局部无关格式问题不封锁全部成果，明确影响及返回点。条件或证据缺口可以保留为候选，但不能仅加一句免责声明后原样作为推荐。

人的选择与系统资格分开：用户可确认分析、要求补证、暂缓、不行动，或在既有合同允许范围内作具名业务选择；审查结论、未满足条件和风险随选择保存，不能改写成通过。涉及不合法计算、越权或不支持的执行不能靠人工选择放行。建议不是行动、审查不是批准、批准不是实施或有效。

## 6. 生成与评估分离、自动修订

后台审查者有与生成分离的职责和上下文，消费当前任务问题、明确业务条件、精确口径／计划身份、真实证据及候选主张；可读必要原始证据摘要和实际核验结果，不只看生成者结论或其自评。先前协作意见保留 MODEL 分类、来源和权限子集，不能当额外独立事实来源。

独立上下文不等于独立事实：可复用现有获准模型，不要求新增Provider／多模型投票；是否同模型、审查输入范围和未完成检查在详情可查。确定性计算资格、引用和授权检查不交给LLM裁决。未获准外部证据不能由模型记忆补齐；没有因果设计／验证者，不输出独立因果核验通过。

候选交付前后台自动完成审查及必要修订。**推荐本期一轮初审→至多一次合并内容修订→一次针对修订的重审**；集中改多个发现，不逐个Agent互审循环。不能修则保留有用事实与明确待补证候选。用户给新资料／改变需求可发起新批次，但必须有真实变化；同输入同缺口不改名绕过有界次数。此为待用户确认的产品停止点，不预定SDK字段或工程拓扑。

可自动修改措辞、缩小被证据支持的范围、撤回无依据原因／保证、补足已有条件、替换为补证建议。**不能暗改用户已确认口径、任务承诺、权限或业务选择**；真正含义冲突先问用户。需要新计算时调用现有获准计划／IR／执行和核验链，不能在审查文本里补数字。

初审和重审均记录实际问题、支持／反证、判定和交付处置；修订保留前后差异及理由。修订者不能自行宣称重审成功；如果评估意见分歧，返回具体承重证据／条件判定或保留冲突，不设“换模型直到同意”。

物理超时／失败重试与内容修订不同：沿用当前已批准“原请求＋至多一次额外请求，备用共用”，不每个异常叠加。暂不设累计额度上限，继续持久计量，不清零历史。停止、UNKNOWN、迟到和显式恢复复用原任务机制。新用途的材料／工具授权是否被当前配置覆盖须架构／intake核实；本规划不调用真实Provider或添加权限。

## 7. 同版身份、变化与恢复

审查必须可追溯到实际任务修订、采用口径／Context/Binding、实际计划及证据快照、报告版本和受审主张／选项／约束。仅报告hash不能替代审查所消费材料。存储结构、业务Port及兼容方案由Mini在获准后设计，不在产品计划预冻TypeScript或公共schema。

| 变化／故障 | 必须行为 |
| --- | --- |
| 新数据、期间／分组／口径、实际计算／证据改变 | 仅影响相关主张及其下游策略；依赖不明按受影响处理，不能误复用旧认证。旧报告／审查不改，新版待重算／重审 |
| 改报告里的主张、原因、范围或策略资源／风险／停止安排 | 对应内容重审；同时更新依赖它的建议。纯排版不改含义／身份关系可保留适用审查，须能说明依据 |
| 审查失败／超时／材料不可见 | 当前检查为无法完成，不分配四种完成判定；已核对事实可先交，重要未审内容只能待审草案。说明可行下一步，不强迫用户重批已有授权 |
| 显式停止 | 停止整个根任务及审查／修订；实际确认前显示停止中／UNKNOWN。迟到意见不升格当前成果；已保存事实、旧报告和历史可查 |
| 保存失败 | 明确哪些结果仅在当前页面、哪些后端已保存，不能显示已保存；恢复保存不重跑模型或计算。当前新审查未持久化不能伪作可恢复认证 |
| 下载失败 | 原后端报告和审查不变，仅重试下载，不重新审查。下载版与页面同版、同限制，不能删掉partial／待补证标记 |
| 刷新／关闭网页／服务重启／重开 | 沿用已批准根任务机制：刷新不重复提交；关页不是显式停止，已启动任务仅在有效授权内继续；服务重启不自动续跑。重开先读回持久状态，显式恢复核验现有授权，必要时才重授；未知调用不盲目重放 |
| 旧报告重新查看 | 显示原审查时点、范围和历史限制；新数据不让旧版自变成功，也不把旧版假称按新版审过 |

正式人工审阅继续以一个整体提交绑定同版报告、Closure、Decision／Expected及审查处置；Agent只备草案。缺资源时优先沿用配置／提出有依据建议；不把依赖条件当护栏，不为审查再造Expected表单。具体消费与原合同兼容是架构评估必答项。
