## 2. 新增可见行为

| UI ID／需求 | 原位置与可判行为 |
| --- | --- |
| JRUI-01 / CR-01、04、10 | 中央现有成果，分别“数字检查／结论依据／建议条件”；不显示一枚全报告PASS。每条结论或选项显示四判定之一及一句理由；尚在审查／失败则用运行状态，不伪四判定 |
| JRUI-02 / CR-02 | 发现／结论卡“查看依据”打开现有证据抽屉：支持、反证／替代解释、适用范围与待补检查；因果说法无资格时撤回／候选，不能只补脚注后原样认定 |
| JRUI-03 / CR-03、08 | 原方案比较卡展示目标、条件、风险、备选、停止与效果验证摘要。条件缺口紧邻选项，不能显示可直接实施；已有明确配置优先，不增加一套表单 |
| JRUI-04 / CR-04、05 | 后台审查和有界修订用实际事件概述，无伪百分比；报告可看到“修订了什么／仍未解决”。正常任务不要求用户逐卡接受审查，模型同意不作为事实来源 |
| JRUI-05 / CR-06 | 修改期间／口径／资料或选项条件后，受影响内容标需重审；旧报告保留、不认证新版。历史／修订对照显示原措辞、现在措辞和判定理由，纯排版不机械触发全重算 |
| JRUI-06 / CR-07 | 初审／重审无法完成、停止中、UNKNOWN、已停止、保存失败、下载失败可区分；已核对事实可见但未审主张是草案。重开不自动执行，显式恢复检查现有授权；下载重试不重算 |
| JRUI-07 / CR-08 | 沿用成果的人审入口；确认分析、补证、暂缓、正式业务判断仍是人的动作。同版审查／限制进入整体提交，Agent不代签。选择不修改审查资格，不执行行动 |
| JRUI-08 / CR-09 | 现有资料／执行详情显示实际审查材料范围、生成／评估分离、用途／消耗与未完成项；不把内部session、Pi类型或SDK字段推给普通用户 |

## 3. 可点击审核路径与合成边界

本原型**所有数据、模型判断、进度、保存／下载／人审结果均为明确合成内存预演**，不读取文件／真实数据、不计算、不调用模型、不持久化、不下载文件、不发网请求，刷新清空。顶部场景选择／推进只用于评审，不入生产。样例两期160→150元为独立合成任务，不伪成006两个实际任务之间的真实比较。

1. **审查中→有限支持**：默认先显示数字样例、当前审查中；点“推进合成事件”看到有限观察有支持、受限试点有条件支持。展开报告→“查看依据”→方案比较，数字／结论／建议三个维度可分辨。
2. **证据不足**：选择场景，销售变化保留，原因主张待补证，建议变成先核实而非加大触达；抽屉列需什么证据，不默认用户业务字段为真。
3. **存在冲突／好结论坏策略**：查看反证或超资源上限，相关内容不作核实／推荐；其他有效观察仍可读。不能用“忽略”“另一Agent同意”升级通过。
4. **修订前后**：夸大原因和收益撤回，改为有据观察和补证选项；看历史与理由。重审只解决对应问题，因果限制／数字partial不消失。
5. **改变期间／策略条件**：选择“期间改变”或“策略条件改变”，看受影响项需重审；旧版仍历史可查，新版不借旧判定。仅策略变化不让未变数字重算。
6. **失败／停止／重开／保存／下载**：分别选择场景，已核对事实保留；根停止先停止中再推进为已停止／UNKNOWN场景仍未知；“重新打开”只读回不执行，显式恢复才进入合成审查中。保存与下载反馈分开，重试不新增计算。
7. **人的判断**：原成果“人的下一步”展开确认分析／补证／暂缓／正式判断提示；本原型只示意增量如何进入既有人审，不伪生成正式Decision／Expected。完整真实提交仍由原合同验收。
8. **专业增量位置**：切专业模式，在六阶段原导航第4／5／6查看相同合成主张／人审说明；第1～3没有新行为，链接PX-004完整参考。此位置预演不证明生产专业流程已接通。

输入自由文字仅安全显示，提示“未执行新分析”；不是聊天API、模型理解或新任务成功。返回正常场景不冒充重新修复后台。

## 4. 布局、反馈与访问性

桌面1440×900／1366×768延续壳层；工作区min-width:0、详情按需打开，长证据与版本名换行，窄窗抽屉覆盖，局部表格横滚。390px只做健壮性，不新增移动产品。

键盘可用：有标签的场景选择、模式切换、证据详情tab、关闭／Escape、历史返回及状态反馈；打开抽屉聚焦详情并返回触发按钮；窄窗覆盖时避免焦点跑到被遮内容。不单靠颜色／toast表示限制，状态文字与解释长期可查，aria-live只报重要变化。动效尊重reduced-motion。

本页局部样例不开放真实文件／授权／正式保存按钮；生产有效授权、停止与结果保存不能拿原型简化。未支持能力如实空缺，不填假成功。
