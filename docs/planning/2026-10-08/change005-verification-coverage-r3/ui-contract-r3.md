# Change005 v1.1 R3 · UI Contract：核验覆盖与限制说明

日期：2026-10-08。状态：**待用户确认，未冻结、未实施。**配套：[产品输入](product-input-r3.md)。

## 1. 保留已确认界面

严格继承 PX-006 左侧会话／中间对话与成果／右侧检查抽屉、v1.1 成果展开、PX-004 专业完整六阶段，以及 R1／五时刻／R2 的有效 UI。中文优先、绿色品牌、JuanerAI 字标和现有 slogan、紧凑新建分析按钮，无图片 Logo。已交付侧栏收起、拖动分界线、产品栏占位、布局设置与资料预览保留。

本期只改变既有位置的真实内容、核验等级和说明时机。没有方法核验中心、新流程页、第六个抽屉标签、每方法选择表单、节点审批或逐数字确认。五类方法由自然需求和业务含义驱动，不要求用户学内部分类或选择 Skill。

右侧标签仍为**口径／方案／资料／证据／执行**。新增方法与重要口径在方案／口径可检查；数字依据与检查限制在证据；真实进展与失败在原执行位置。默认不同时展开所有模块。

## 2. 三个说明时点的可见行为

| 时点 | 出现位置与行为 | 禁止行为 |
| --- | --- | --- |
| 方案形成 | 确有重要限制时，在当前对话简述，方案抽屉提供可修订的方法和范围。普通支持方法直接推进。 | 预先写“已核验”；弹出所有方法／口径表单；机械要求每步确认。 |
| 计算与检查 | 原进展位置显示实际“正在计算”“正在核对”等状态。发现不一致、失败或UNKNOWN时，及时说明受影响结论，保留有效成果。 | 虚假百分比；模型说已执行就显示通过；停止按钮用来触发回复；未知显示成功。 |
| 交付答案／报告 | 先给业务结果。关键数字可点击查依据；影响判断的重要限制直接写在相关结论旁。正常合格数字不密集贴卡片。 | 全篇“全部核验正确”；把有限检查当独立核算；把重要限制仅藏在抽屉。 |

已知超出覆盖且仍可在现有权限内探索时，可说：

> 我可以按这个规则计算并检查合计是否一致，但目前不能独立验证每项分配是否正确。结果会标明这一限制。

这是说明，不自动增加“是否允许继续”的确认。业务分摊依据不明确且会影响答案时，才在同一对话提出具体选择。新权限或范围按原边界停住受影响动作。

## 3. 默认答案与数字依据

以下为**合成验收参考**，不是生产结果或新的固定模板。报告由实际问题组织，不要求每次输出这些段落。

### 3.1 加权平均／占比

> 按销量加权后的平均成交价为 **16 元**。A商品销售额占当前总体的 **37.5%**。
>
> 这两个数字已按所列资料和当前范围核对。查看数字依据。

点击16元，证据抽屉显示：业务含义；有效记录与销量权重；`(10×2＋20×3)÷(2＋3)`；单位与范围；实际主算／独立核验结论和限制。真实来源／工作表／字段可查。不能只展示最后除法的绿色勾。

点击37.5%，显示真实分子和总体分母、计量基础、筛选／去重、派生公式检查及基础值的核验状态。分母错误或基础值只有有限检查时，不能由末尾除法通过升级整个比例。

### 3.2 贡献与多表差异

> 总净销售额增加 **100 元**：北区贡献 **120 元**，南区贡献 **−20 元**。这是变化的分组拆解，不能据此认定增长原因。

需要展示贡献率时，120%与−20%真实保留，不裁剪；总体变化为零时写贡献率不适用，仍保留绝对贡献。

多表核对发现差异时，例如：

> 发现一笔退款没有匹配订单，金额 **30 元**。已核对并定位这项差异；当前两表尚不一致。

“差异定位完成”不显示成“账目核对一致”。相关资料可由现有资料／证据入口检查；不修改原件或增加外部连接按钮。

### 3.3 部分核验与失败

> 分摊合计 **1000 元**，与待分摊成本一致。**目前只通过合计检查，各项分摊尚未独立核验。**

该限制必须同结果一起可见，不能只有绿色“通过”。点击单项显示它实际取得的检查，不借总体凭证认证。

当主算与核验不一致：

> 这项金额两条计算路径不一致，暂不能作为核验通过的结果。其他已核对结果仍可查看。

无需展示技术栈报错；证据／执行详情可查具体差异、受影响范围、旧结果及可行下一步。停止或UNKNOWN保持原语义，不显示新版本成功。

## 4. 证据抽屉内容与等级

每个关键数字的依据先显示：

1. 指标名称、值、单位、所属版本及当前／历史状态。
2. 简明计算方法与操作数；适用时可继续查看基础值并返回。
3. 资料／工作表／字段、期间、总体／分组／筛选／关联及必要权重。
4. 实际完成的检查及其结果：独立核算、派生公式核验、部分检查、探索未核验、失败／UNKNOWN或不适用。
5. 检查证明了什么、没有证明什么。

哈希、代码／Run／Attempt等技术身份保留在可展开详情，默认答案不展示。状态以文字为主，颜色辅助；不能用一个“已验证”徽标压平全部等级。

“已独立核算”按资料与方法限定；“派生公式已核验”明确依赖基础值；部分检查具体列出守恒／边界等，不写含混的“基本可靠”。缺核验器不禁止已有权限内探索，但探索结果不得进入已核验清单。

重要限制在正文与抽屉都保留，重要程度以是否改变用户对结论的理解为依据，不以技术错误严重度替代。核验不证明因果、资料完整或业务规则必然正确。

## 5. 修订、保存及双模式一致性

用户自然说“改按销量加权”“只看北区”“改用营业面积分摊”等，在当前对话更新实际方法／范围。涉及计算的修改在原版本影响位置简述：改了什么、哪些结果失效、哪些仍可用；形成新版本并真实重算、核验后更新。

历史仍可选看，不改写旧报告；历史依据清楚标注版本与范围。旧新比较区分方法／范围差异，条件不相容时不伪造差值。仅修改报告措辞不重复计算。

快速、专业、成果展开、保存读回及下载报告使用同一任务／版本／事实；导出保留重要限制和核验程度。不能网页写有限检查，下载报告写全部核验。刷新不执行新调用，服务重启不自动分析，恢复沿原明确操作。

保持现有抽屉的键盘可达、关闭／Escape焦点返回，长字段／限制不裁掉；宽屏不挤压主区，窄屏沿已有覆盖抽屉并可关闭返回输入。方法增加不增加常驻空白区域。
