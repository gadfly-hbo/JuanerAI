## 1. 用户结果与修订原因

用户自然提出经营分析问题，Agent 理解、探索和推进，本地工具实际计算；系统对关键数字执行适用核验，交付可检查依据的答案。常见经营分析广泛覆盖，超出覆盖时准确说明核验程度，不把用户变成逐步骤审计员。

本次定位为**扩展经营分析方法的核验覆盖**，不是重新建设简单计算器。已有求和、四则运算、比例、增长率、受控 Python、资料绑定、独立复算、数字依据、版本与报告能力先盘点、复用；仅补本期用户结果真正缺少的部分。不能按指标名称各建一套程序，也不承诺穷尽所有业务算法。

本期成果：五类常用方法能够在明确适用范围内实际计算、取得相应检查证据，并在同一分析／报告中准确区分哪些数字已经独立核算、哪些只完成有限检查、哪些尚不能证明。

PIM 聚焦机会、问题、证据及有边界的解释；没有原因资料时不编造因果。OSM 的目标缺口问题可以消费本期核验能力，但**本稿不建设完整 OSM 目标／策略／行动／复盘模块**。已提供且口径相容的目标与实际，可以复用既有差值、比例计算；不自动生成目标或预测。

## 3. Agent、三核心与核验协作

```text
用户需求＋有效资料／指标说明
→ Agent 与用户按需共同对焦
→ Semantic Context 明确含义＋Binding 连接真实资料
→ IR 落实方法、范围、关系、单位及执行约束
→ Agent 选择已有工具或生成受控程序，本地实际计算
→ 适用核验读取真实资料／合格操作数，执行检查并记录范围
→ 结果及实际核验状态交给 Agent 解释
→ 报告引用检查、保存和交付
```

Semantic Context 说明“这个指标是什么意思”；Binding 说明“使用哪些实际字段和记录”；IR 说明“按什么规格执行”。三者不代替自然语言理解，也不要求将用户原话逐字匹配成固定术语。没有已构建的长期语义库时，使用本任务的有效说明，不虚构知识库或本体能力。

方法由问题和业务含义决定，不因某个现成工具存在而更改用户目标。分析可以组合已有工具和受控 Python；在授权及目标范围内，Agent 可依据真实工具结果继续探索，用户不确认每个内部动作。重要口径冲突、缺资料和权限变化才向用户提出。

## 4. 可组合核验与独立性

### 4.1 三层覆盖

1. **基础检查复用**：资料身份、筛选范围、关联关系、重复／缺失、精确求和／计数／四则、单位和精度。
2. **组合检查**：新指标沿基础值与派生值的依赖关系取得证据。操作数、业务含义、范围和单位均需相容；只核对末尾除法不能证明前面的记录和权重正确。
3. **方法特有检查**：例如权重对应关系、分项变化对总体变化的还原、分摊规则与舍入余额、多表差异定位。没有充分检查能力时保留有限／未核验身份，不自动升级。

不建设任意算法证明系统。覆盖按当前任务和方法的实际条件判断，不按模型自称、指标名称或“使用 Python”决定等级。

### 4.2 核验独立性的最低要求

独立原始资料核算应使用记录的业务口径和绑定资料，另行形成计算路径，在比较前得到核验结果。不得把主结果作为唯一输入答案、复制主计算代码重跑、或让相同程序自己确认结果。

可以共享受信基础设施及明确的业务合同，但须说明共享部分及适用限制；主计算的业务算法不得成为独立核验的唯一实现。工程需用错误注入证明检查能识别漏行、重复、错权重、错范围、错关联等适用错误，而不只证明两次正常结果相同。

Agent 可以提出检查策略或生成另一种实现，但模型、第二个 Agent 或两份代码都不自动构成可信独立核验。生成检查无法满足上述条件时，只记录实际有限检查；不能靠语言声明补齐保证。

派生公式检查可依赖已合格的操作数，明确只证明引用、公式与单位相容，不冒称重新核算了全部原始资料。单一守恒检查不能证明逐项分配正确；检查通过也不证明资料完整、业务口径必然正确或原因成立。

## 5. 首期五类方法及明确边界

### 5.1 加权平均

支持有效记录的 `Σ(数值×权重)÷Σ权重`，以及按当前分组／筛选分别计算。必须明确数值和权重来源、行级对应、适用单位、缺失处理和权重含义；根据原始绑定记录独立核对分子、分母及结果。

零权重不贡献；权重总和为零时平均值不适用，不补成零。缺失值不默默补零或删除，使用资料已明确的规则；规则影响答案且无法确定时才询问。负权重没有明确且受支持的业务含义时，不冒充常规经营加权平均；可保留探索及限制。不能用简单平均替换加权平均。

### 5.2 占比

复用现有比例与派生公式，补充总体／子集关系、范围和计量基础核对。明确分子、分母属于哪些记录、是否使用金额／数量、去重及分组含义。组成完整互斥总体时检查合计关系；类别可重叠或只展示部分时不能强行要求合计 100%。

零分母明确不适用，缺失不补零；百分比与百分点区分。负金额等可能使占比超出 0～100% 时说明含义，不自行裁剪。正确除法不能掩盖分母取错总体。

### 5.3 贡献拆解

首期明确交付**可加总指标的分组绝对变化贡献及贡献率**：相同口径的两期分组值之差还原总体变化，检查新增／消失分组、覆盖和重复。总体变化为零时贡献率不适用，绝对贡献仍可展示。正负贡献真实保留，贡献率可能大于 100% 或为负，不能裁剪或改写。

多因素“量／价／结构”拆解可能存在多种合理方法和交互项，不悄悄选择一种就宣称唯一正确。本期不承诺通用多因素算法；已有适用方法可按明确合同复用，否则作为有限探索，说明残差、交互项和检查缺口。分组贡献是算术解释，不是因果证明。

### 5.4 成本分摊

首期交付**一个明确成本池按有效业务权重比例分摊到明确对象**，允许按已有分组处理相互独立的成本池。明确成本金额、对象、权重、单位和舍入规则；独立核对权重对应关系、逐项金额和总额守恒。

权重合计为零、对象漏配／重复、币种不相容等阻断受影响分摊。没有业务分配依据时不能自动改用平均分配。舍入余额按有效规则处理并可查；没有既定业务规则时，先给可修订的方案建议，需执行的重要选择在共同对焦中解决。工程不得为隐藏差额自行调整某行。

仅总额一致显示“合计一致，逐项尚未独立核验”。多级循环分摊、复杂优化、税务／会计合规不纳入本期承诺，也不把有限检查说成完整规则核验。

### 5.5 多表核对

在现有授权表格和支持的关联范围内，明确关联键、粒度、期间、单位与应满足的基数关系。逐步核对两张或多张表的匹配／未匹配／重复记录、金额及数量差异，能定位差异涉及的来源和字段。

多对多、重复键或不同粒度导致放大时，不能直接关联后求和并认证通过。完全一致与存在差异均可形成真实核对结果：**差异被可靠定位**不等于账目相等。缺少可靠关联条件时说明缺口，不猜键值、填造记录或修改原件。本期不新增数仓／外部系统连接器、写回对账或任意 SQL 权限。

| 场景 | 完整结果 |
| --- | --- |
| S-R3-01 换数据与参数 | 更换文件、字段名、数据值、期间、分组或筛选，既有方法仍真实计算和检查，不修改专用业务代码；不适用条件准确拒绝。 |
| S-R3-02 组合经营报告 | 在同一经营任务中组合上述适用方法，关键数字各有实际依据与等级，形成机会／问题分析；已提供目标可作同口径缺口比较，不增加预测。 |
| S-R3-03 超出覆盖 | 新业务算法可以在既有环境与权限内探索；明确哪些部分只完成守恒／边界等检查，哪些未独立核验，不能自建未经验证的检查器后自称通过。 |

## 7. 核验程度：何时说明、保证什么

### 7.1 三个说明时点

- **方案阶段**：已知方法超出覆盖或检查存在重要限制时提前说明，必要时建议可行方法或补资料。只能说明拟进行的检查，不能先宣称核验通过。后台明确的常规方法直接推进，不逐方法要确认。
- **执行阶段**：主计算后、作为已核验结果发布前，执行适用检查。实际失败、不一致或未知及时随真实进展说明；未核验的中间结果可以明确标为探索，但不能提前作为可靠结论。
- **交付阶段**：每个关键数字绑定实际状态、来源、方法、范围与版本。正常答案保持简洁；影响判断的重要限制直接随相关结论出现，不能只藏在抽屉。保存／读回／导出保留一致状态。

没有跨所有方法都可用的“报告全部正确”标识。

### 7.2 实际结果状态

| 状态 | 可以说明的保证 | 不可以外推 |
| --- | --- | --- |
| 已独立核算 | 在记录的资料、口径和适用方法内，另一路核算及相关检查一致 | 原始资料无遗漏、定义必然正确、因果或策略正确 |
| 派生公式已核验 | 操作数合格，引用／公式／单位／精度检查通过 | 全部原始资料再次独立重算 |
| 部分检查通过 | 明确列出的检查通过，例如总额守恒 | 每项分配／新算法全部正确 |
| 探索结果，未独立核验 | 实际执行得到结果，证据及检查缺口可查 | 代码运行成功就算核验通过 |
| 检查失败／UNKNOWN | 实际失败、不一致或回执未知，影响范围明确 | 重写成成功、未执行或可信当前结论 |
| 不适用／旧版失效 | 相应公式不适用，或依据只属于旧范围 | 补零、套用旧凭证到当前版本 |

核验失配的数字不进入当前已核验结论；必要时保留在明确的诊断／探索部分。报告可以包含可靠部分及受限部分，不能因局部成功给整篇升级，也不因局部失败丢弃全部有效成果。

## 8. 生命周期、权限及非目标

修改方法、权重、总体、关联、期间、单位、分组或筛选，按 FM-X 新版本保存含义与影响，受影响基础值、派生值、核验及报告引用失效；实际重算后才能取得新依据。未变化部分仅按现有资格复用，旧版本不改写。仅改表达不重算，当前版本选择不自动执行。

原停止／在途／迟到／UNKNOWN、刷新不重复、重启不自动执行、显式恢复、持久调用记录和已用资源继续有效。自动跟进保持 PAUSED；本稿不恢复后台循环。

复用有效 Pi Adapter／Application／Port／Profile，不新增 Runtime、Provider、模型职责、凭据来源、数据范围、安装、联网、主机或 Git 权限。原最多一次额外请求的共享上限不变，无累计额度上限不等于无计量。实际工程／合成材料验证只能沿用可核验有效授权。

**明确非目标**：预测、未来趋势／销量预测、模型训练与评测平台、目标测算插件、完整 OSM、四库／双库／语义平台、插件市场、通用数学证明、全部新算法的自动核验、因果成立保证、业务行动或原件写回。预测及目标测算返回后续 Model Pack／插件的正式产品输入，本次报告不悄悄加入预测。
