## 2. 默认回答：答案优先

示例（审核合成值）：

> 两期净销售额合计 **1050 元**。1 月 **430 元**，2 月 **620 元**，增加 **190 元**，增长 **44.19%**。
>
> 订单金额 1100 元，扣除关联退款 50 元。数字已按当前口径核对；现有资料不能证明退款原因。
>
> 查看数字依据　展开报告

关键业务数字可点击，呈现为自然段内数值链接，不堆叠每数字状态卡。不使日期、订单号或所有正文数字变成按钮。按钮具有明确可访问名称，例如“查看 2 月净销售额 620 元的依据”；Tab 可达，Enter／Space 打开证据抽屉。

“数字已核对”只指当前所列有凭证的数字；不写“全部报告已核验”。混有探索／假设时，用一句范围说明，例如“销售金额已核对；预测为探索结果，尚未独立核验”。重大不一致就在回答附近说明，不藏在抽屉中。

## 3. 数字依据：复用右侧证据抽屉

点击 **620 元**，抽屉定位该数字，先展示用户能理解的内容：

- **2 月净销售额 · 620 元**；当前版本；独立核算一致。
- 计算：2 月订单金额 650 元 − 关联退款 30 元 = 620 元。
- 范围：2026-02；当前选定资料；无额外地区／商品筛选；按原订单号关联。
- 来源：订单.csv／退款.csv 的实际工作表及有关字段；这里只按真实可读内容显示。原件不改写，行与来源详情按授权展开。
- 核验范围：重读对应资料，另一路计算与结果比较。**证明金额及记录的关联检查一致，不证明退款原因或全部业务定义正确。**

点击 **44.19%**，显示：

- **2 月净销售额增长率 · 44.19%**；派生公式已核验。
- `(620−430)÷430×100%`；显示百分比保留两位小数；底层精度未先舍入。
- “1 月净销售额 430 元”“2 月净销售额 620 元”是可点击的输入依据，转到相应数字，保留返回派生结果入口。
- 输入分别已独立核算；此检查证明引用、单位和公式一致，**不等同新增独立订单重算或增长原因证明**。

技术哈希、Run／Attempt ID、代码与完整调用记录保留在可展开的执行详情，不铺在默认回答里。证据抽屉关闭／Escape 后回到触发数字；切换数字不丢失报告位置。窄屏使用现有覆盖抽屉，正文和输入框仍可访问，不增加横向固定画布。

## 4. 状态和局部成果

| 状态 | 用户可见行为 |
|---|---|
| 正在计算／核对 | 原进展位置说明实际工作；不能预先显示核验成功。已有效的部分成果可看。 |
| 已独立核算 | 数字依据明确方法、范围与限制；默认答案无需逐项确认。 |
| 派生公式已核验 | 显示操作数、公式与单位；不混同基础重算。 |
| 部分检查通过 | 例如“分配合计一致，逐项分配尚未独立核验”，不可只显示绿色“通过”。 |
| 探索值 | 在明确的探索段落展示“尚未独立核验”，不能列入已核验事实清单。 |
| 公式不适用 | 例如“基期为零，增长率不适用”；保留本期金额，不伪造 0%。 |
| 冲突／失败 | 说明哪个结论不能使用；其他有效数字保留，不让整个页面只剩报错。 |
| 失效／历史 | “旧范围结果，当前版本不可引用”；当前受影响结果显示待重算。 |
| 停止／UNKNOWN | 沿用原状态；未知不显示成功，停止不用来触发回复，重开不自动执行。 |

颜色辅助识别，文字表达状态。用户可在同一输入框提出异议、修改定义或要求重查，不强制改填技术表单。

## 5. 修改、报告与专业模式

用户说“只看 Coffee”后，原进展／版本影响位置简述：范围从全部商品变为 Coffee；总体净额、期间差值、增长率和相关报告段落待重算。旧版数字保留在历史，不能继续作为本版答案。重算完成再展示新数字及新依据；不能修改旧凭证来适配新范围。

用户只说“报告短一点”时，事实和凭证保持，表达调整不重新计算。保存读回／导出保留当前版本、数字依据及重要限制，不把导出的探索值改标为核验通过。

专业六阶段不增加第七阶段；已有成果、核验与证据位置呈现同一数字依据。快速模式的失效和未核验状态必须同步可见。附件中的专业模式链接只是保留完整已确认参考，不是新的专业生产实现证明。

## 7. 附件性质与待确认项

附件严格标注合成审核，不访问文件、模型、服务、凭据，不计算真实数据，不保存产品成果。点击只切换明确静态场景；不会按输入关键词生成假 AI 回复。
