## 2. 三核心、Agent 与执行体系的分工

### 2.1 从需求到计算

1. **Agent 理解自然语言，形成 Semantic Context。**结合用户目标、有效指标说明和资料理解净销售额、退款归属、期间、单位、筛选与分组。三核心在后台提供专业依据和一致性检查。没有长期语义库时使用本任务有效材料，不虚构已有知识库；只有影响答案的真实歧义才询问用户。
2. **Binding 对接真实资料。**例如净销售额中的订单金额绑定到订单表金额列，退款金额绑定到退款表金额列，原订单号绑定到关联键。不能只靠模型说“已经理解”就认定字段和关系存在。
3. **IR 形成可执行分析规格。**承载已确定的计算操作、输入、关联、分组、筛选、单位等。IR 的确是需求到计算的桥梁，但不等于把所有自然语言直接翻成一整段 Python，也不规定 Agent 的全部思考顺序。复杂分析可在有效业务范围内增量形成和执行 IR。
4. **主执行实际计算。**Agent 选择已有计算能力或生成受控分析程序，由本地执行环境运行。模型口算、模型文字中的数字不自动成为受信结果。
5. **适用的独立核验重读绑定资料并检查结果。**不以“再让同一个模型看一遍”或“把同一段程序重复执行”作为独立核算。核验成功形成明确范围的凭证；失败或未支持保留真实状态。
6. **报告组合与发布检查。**已核验数字及其派生公式进入报告；Agent 撰写解释。保存或导出前核对报告中的定量主张、证据、范围、单位与版本是否一致。缺依据的数值不能获得核验标识。

这里有三种不同工作：本地程序首次算出结果；适用核验器用另一计算路径复核；报告检查确认文字／表格／图表使用的就是这些结果。三者不能互相替代。

### 2.2 核验保证与限制

“独立核算一致”表示在记录的资料、口径和方法范围内数值一致，不表示业务口径必然正确、数据一定完整或原因已证实。两条路径共享错误的业务定义仍可能得到同一错误答案；来源和口径须可检查。

默认不让用户确认每个公式、Binding 或 IR 节点。重要业务选择、权限变化、真正的口径冲突仍由用户判断；一般工程执行和后台检查由产品完成。

### 2.3 “决定方法”不是只选择 Python 或程序

这里先有**分析方法**：如何定义净销售额，退款归原订单期间还是退款发生期间，按哪些维度比较，发现变化后继续检查什么。Agent 结合业务依据和用户目标做这些选择；不能把编程语言当作分析方法，也不能因为有某个计算器就反向改变用户问题。

然后是**执行方式**：

- 已有工具能完成时，Agent 调用工具并提供真实来源、字段、关联、分组和筛选参数；后台编译／核对 Binding 与 IR，已有本地程序执行，返回结果与适用核验。当前净额路径主要是这种方式，并非每次都写一段 Python。
- 需要探索或组合现成工具不覆盖的处理时，Agent 可以生成 Python，使用当前授权的绑定快照在受控环境实际运行，观察返回后继续推进。不是把编程任务再交给用户，也不是模型在对话里写代码就算已经执行。
- 同一个分析可混用：现成工具计算基础净额，Python 探索分布或制作图表，已有适用核验路径核验重要数字。生成程序的执行成功与算法独立核验是两件事；目前没有匹配检查方法的探索不能获得核验成功身份。

自然语言理解和分析推进属于 Agent；可执行参数／程序及其结果属于实际工具链。后台不自行口算，也不只让 Agent 从两个固定技能按钮中选择。

## 3. 本增量交付范围

### 3.1 报告中的数字必须有明确身份

每个有业务意义的定量主张，应归属于可查的来源值、已核验计算、已核验派生结果、明确假设／目标、预测／探索结果之一。日期、订单编号、版本号和叙述序号不误当作金额；不能用简单“扫描所有数字字符”的机制阻碍自然表达。

受信数字的依据须能区分任务及版本、资料身份、指标、期间、分组、筛选、单位、方法、精度和核验范围。相同数值来自不同地区或期间不能互换凭证。表格、图表、正文、摘要及保存／导出结果遵循同一规则。

Agent 可以自由组织报告和解释，数值引用不得自由改写事实。实现可以采用确定性数字投影与模型引用约束，具体私有格式留给工程设计；不得只靠提示词声称杜绝编造。

查出无依据数值、证据不匹配或矛盾时，保留失败记录和有效部分成果。系统可依据已有有效结果纠正投影，但不得悄悄创造依据或改成另一业务主张。无法闭环的主张明确不支持／未核验，不混进已核验结论。重大冲突在回答中说明，其余细节按需检查。不增加模型自动重试次数。

### 3.2 通用派生公式核验

首批支持已核验输入之间的加、减、乘、除及其组合，覆盖差值、比例和增长率；表达式必须绑定具体操作数的含义、范围与单位。不为“1 月到 2 月”“Coffee”“44.19%”写专用规则，不做任意代码公式解释器或通用算法平台。

例如 1 月净额 430 元、2 月净额 620 元分别已核验后，后台真实算出差额 `620−430=190 元`，增长率 `(620−430)/430×100%=44.186…%`，按记录的两位小数规则显示 **44.19%**。这次派生检查证明公式和引用正确，不是第三次重算全部订单，也不证明增长原因。

分母为零不可显示 0% 或无穷作为有效增长率；显示“基期为零，增长率不适用”，有效金额仍保留。负基数可能造成误解时解释公式及限制，不能用增长率文字夸大改善。缺失值不默认补零。金额、万元、元、币种、百分比与百分点不能混用；资料没有汇率时不能自行跨币种换算。中间计算与显示舍入分开，记录采用的精度规则。

### 3.3 复杂方法按实际检查范围交付

Agent 可继续在现有环境与授权范围内探索新方法、生成 Python；没有匹配核验器不等于禁止探索，也不等于独立核验通过。

产品区分并可解释以下实际状态：

| 状态 | 可以说明 | 不可以说明 |
|---|---|---|
| 已独立核算 | 该方法／数值的另一计算路径与资料核对一致 | 全部业务含义和因果都正确 |
| 已核验派生公式 | 操作数有有效依据，公式、单位与引用一致 | 新算法已得到独立算法核验 |
| 部分检查通过 | 明确列出的守恒、边界或一致性检查通过 | 仅凭守恒证明每项分配都正确 |
| 探索结果，未独立核验 | 本地程序执行并保存了结果，检查缺口可查 | 程序退出 0 就是可靠核验通过 |
| 检查失败／未知 | 具体失败或回执未知，其他有效成果保留 | 重写为未执行或成功 |

成本分摊是边界示例：分配合计等于待分配总额，只证明守恒；要宣称各项分配正确，还需要业务分摊依据、正确权重与适用的独立重算。**R2 要落实这种范围区分与正反例，不要求新增成本分摊、预测或统计算法。**后续新增方法再配适用核验，不以本稿一次铺开万能核验器。没有检查器的探索值可在明确标识的探索部分展示并保存，不进入已核验数字清单。

## 4. 用户体验与结果生命周期

- 简单问题仍直接回答，如“净销售额 1050 元”；不用先展示完整方案、口径、所有核验模块或要求点确认。
- 用户点击关键数字或“查看依据”，在现有证据抽屉看到它的业务含义、来源、计算／派生过程、检查范围与限制。默认答案不用密集贴满状态标签。
- 经营报告的已核验数字、模型解释、假设、探索值清晰区分，但报告保持自然可读，不变成审计表单。没有原因资料时仍不编造退货原因。
- 修改期间、分组、筛选、单位或方法后按 FM-X 形成新版本；受影响基础结果、派生公式及报告引用均失效，实际重算和核验后替换当前答案。旧成果只作旧版历史，不改写。依赖未变化的结果只按有效资格复用。
- 仅调整表达不重复计算。刷新读回不重复调用；停止、迟到、UNKNOWN、重启不自动执行及显式恢复沿用原边界。导出中仍保留核验范围与重要限制，不因离开网页就丢失身份。
- 原专业模式使用同一任务、版本、数值与凭证；不复制一份独立事实状态。

## 5. 验收依据

下列为新增验收，不替代原 v1.1、R1、五个时刻、会员、双模式或 Runtime 实际验证。

| ID | 可观察结果与必要反例 |
|---|---|
| NR-01 | 自然需求经 Semantic Context、真实 Binding、实际消费 IR 后执行；既有工具和受控生成程序均有真实回执。模型文字值不能绕过主计算与核验进入受信结果。 |
| NR-02 | 正文、表格、图表、摘要及保存／导出的重要业务数值均可定位有效依据；注入无来源数值、交换期间／地区引用、引用旧版本均不能取得已核验身份。编号／日期不被错误拦截。 |
| NR-03 | 真实核验基础数值后，计算并核验差值、比例、增长率。430／620 得到 190、44.19%；更换输入、字段名、期间、分组仍适用，无固定凭证数量。 |
| NR-04 | 零分母、缺失、负基数、舍入及单位比例得到明确适用处理；元／万元可按明确单位换算，跨币种无汇率不臆造。百分点不等同百分比。 |
| NR-05 | 复杂方法没有独立算法核验器时，实际探索结果保持可用并明确未核验；仅守恒通过不能升格为各项分配正确。方法范围与失败／UNKNOWN 均可读回。 |
| NR-06 | 修改范围后基础结果、派生结果和报告引用沿依赖失效；新范围实际重算核验，旧版可比较且不伪装当前。仅改措辞不重算。 |
| NR-07 | 已核验部分与失败／探索部分共存时，用户能看懂哪些数字可靠、哪些有限制；不得显示“报告全部已核验”或“原因已验证”。 |
| NR-08 | 默认先看自然答案；点击关键数字在既有证据抽屉查依据，键盘与窄屏可用。无需逐数字确认；专业／快速同版本一致。 |
| NR-09 | 保存读回、刷新、停止、在途／迟到、重启与显式恢复延续原边界；凭证、方法范围、调用记录和资源消耗不丢失或伪造。 |

整合验收使用同一任务：订单／退款／指标说明 → 总额及期间分析 → 差值和增长率 → 查看数值依据 → 修改筛选重算 → 比较历史 → 追问缺资料的退款原因。另有不同字段名／数据值的任务与无核验器探索正反例，证明不是净额单案例补丁。示例数字仅验收样例，不限定开放分析范围。
