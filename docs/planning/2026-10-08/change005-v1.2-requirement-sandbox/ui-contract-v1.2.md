# Change005 v1.2 · 需求沙盘增量 UI Contract

2026-10-08。**候选待用户 UI 接受**；既有 v1.1／五时刻／R3 的有效批准复用，新沙盘不能借用旧 Gate 声称已接受。产品行为由[产品增量](product-addendum-v1.2.md) RS-01–08约束。

## 1. 不变的产品壳层

快速模式保持 PX-006 左会话、中央对话、右检查抽屉；专业完整六阶段保持 PX-004，不采用 PX-006 专业占位。中文优先、浅色绿色、JuanerAI 字标及“持续做出更好的决策”，无图片 Logo，紧凑“新建分析”不高于40px。原布局折叠、分栏宽度调整、布局设置、资料预览以及 R3 口径／方案／资料／证据／执行五页签继续保留，生产不得用本增量原型替换整页而丢失它们。

不新增常驻“需求沙盘”一级栏目，不继续视觉打磨。普通用户不需要懂 Contract/IR/Attempt，不要求逐节点推进；技术追溯在检查详情。继承 [v1.1 UI](../../2026-10-05/change005-ui-contract-recovery/ui-contract-v1.1.md) Q11-02/03/05/06、[五时刻 UI](../../2026-10-06/change005-five-moments/ui-addendum-v1.1.md) FM-01/02/FM-X 相关接缝，其余入口和约束不删除。

## 2. 新增可见行为

| ID／产品要求 | 位置与用户行为 | 可直接检查的结果 |
| --- | --- | --- |
| RSUI-01／RS-01 | 新建分析提供“直接开始分析／先帮我理清需求”；对话接受自然语言 | 后者先整理而不启动计算，同一任务以后继续；明确任务不强制深聊 |
| RSUI-02／RS-02 | 中央“业务理解／分析方案”给出当前目标及关键追问，解释其价值 | 回答改变目的、问题或证据需求；未知／来源标记，不把用户观点当核验事实 |
| RSUI-03／RS-03 | “预演不同答案”按需展开／收起：可能支持、可能反证、证据不足 | 每条说明需要什么证据、会影响什么判断、不能推出什么；醒目标明“待验证，不是分析结果” |
| RSUI-04／RS-04 | 中央显示关键冲突或缺资料；右“口径／资料”说明原因和当前许可 | 可补充、修改范围或保存待补；不得默认“继续”绕过；非关键未知标限制而非强制问卷 |
| RSUI-05／RS-05 | “查看完整框架”展开工作区；回答／修改自动保存并显示回执；“保存框架，暂不分析”有读回入口 | 生产真实保存反馈及失败保留、可重试；读回框架／来源／确认，自动或手动保存都不启动运行 |
| RSUI-06／RS-05 | 修改重点／期间等，展示新旧差异和受影响处，再整体审阅 | 实质改变形成新版本；历史确认保留但不套新版本；仅措辞不升业务版本 |
| RSUI-07／RS-06 | “审阅当前框架”与“按此方案开始分析”分清效果 | 前者不执行，后者先检查有效授权和数据／方法资格；不是每次 Attempt 重新批准 |
| RSUI-08／RS-07 | 停止、保存后重开、待对账与明确继续沿用原行为 | 重开／刷新／切模式不运行；UNKNOWN先对账，无迟到成功／自动续跑 |
| RSUI-09／RS-08 | 专业原第一阶段查看同一任务的需求／框架；切快速可回到同一内容 | 相同框架版本／来源／限制，不建第二份草稿；原后五阶段与正式人审不变 |
| RSUI-10／RS-06 | 获准开始后沿用现有进度、逐项核验与成果界面 | 实际输入／计划和结果一致，候选预演不显示为发现；核验按 R3 真实覆盖，无统一绿色通过假象 |

复杂任务的完整框架仍以自然语言摘要和可检查详情为主，不把内在七类信息转成七步前台流程。缺资料可以先整理，不能因此把不具备证据的框架宣布为可执行。用户选调查重点不是选事实；选择“证据不足”的预演分支不是业务的证据不足终态。

## 3. 可点击附件的读取方式与界限

[打开增量可点击 UI](clickable/index.html)。全部为本地合成材料，无网络、Provider、文件读取、真实计算或持久存储。任意输入仅安全显示为用户文本，固定演示不能宣称真实 AI 澄清能力。页面顶部“审核场景”是非生产控件，用来检查正常复杂需求、简单跳过、只整理保存、自动保存失败、缺资料、口径冲突、实质修改/no-op、停止及 UNKNOWN。自动保存仅在本页内存同步演示，生产必须以真实回执显示成功或失败。

中央卡片可预演、改变调查重点、整体审阅、保存／内存重开、查看新旧框架；右五页签同一演示任务。专业“需求／框架”是同一个演示状态的受影响接缝，提供原 PX-004 全流程参考链接，不在本包复制六阶段或伪装它与演示共享后台。生产必须嵌入原第一阶段并共享实际任务版本。已接受的专业其余阶段继续以原完整合同为准。

“按此方案开始分析”在本页只展示准入检查／接续位置，**不模拟已真实完成**。本页不生成计算后成果；既有成果及核验界面继续以原 v1.1／五时刻／R3 合同为准。页面内始终标合成，不能将其验为生产模型质量、存储、授权过滤或核验。专业同任务接缝的视觉接受不等于后端共享验收。

## 4. 用户审核面与工程约束

用户重点审核：新入口是否自然；高价值澄清及预演是否易懂、不像问卷；保存不分析是否清楚；来源／限制／变更影响是否可检查；快速与专业接缝是否延续同一产品。仅本次受影响可见行为需新 UI 接受，不重复全部旧 Gate。

Mini 严格实现用户最终接受的版本，不自创沙盘工作台或重画全流程。工程须证明 RS-S/C/U 的真实消费者及失败恢复；静态附件不代替工程验证。保存、授权、停止、指标含义、误导成功或结果可信性失效是主流程／安全问题，不是可以忽略的文案问题。

当前未批准新 UI；正式冻结前关联实际只读审查结论及用户接受记录。普通实现细节在原005 engineering intake 闭合；新权限和实质产品取舍集中交用户，不凭本文件安装、调用、发布或派发。
