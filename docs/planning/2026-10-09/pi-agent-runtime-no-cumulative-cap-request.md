## 3. 必须实现的语义

1. **不封累计额度，继续累计计量。** 当前 JuanerAI 不因 SDK 设定的累计模型／工具次数、累计 token、累计资源单位或累计运行时长达到某个值而被预算拒绝。明确区分“不封顶”与“未知／缺失策略”；用可持久表达的明确策略，不用极大有限数、Infinity、NaN、清零、换 Task ID 或绕过 BudgetStore 冒充无上限。接口形式由你在本项目设计。
2. **单次保护独立存在。** 单个模型请求的输出上限及超时、单次工具／进程超时、文件／输出大小、执行环境隔离、授权有效期和显式停止仍有效。把当前混用累计 token 与单次 maxOutputTokens、累计 wallTime 与执行 deadline 的接点真正分离；不要为取消累计封顶顺带取消单次保护。具体有限参数沿用有效配置，缺少必需参数时明确报缺失，不替用户编造默认值。
3. **一切实际消耗可追踪。** 主请求、备用、自动重试、工具、压缩、分支摘要及已启用 deferred 辅助请求均进入权威账本。新策略下依然可读回累计消耗、预留及不确定值。保留 AuditSink、稳定任务身份、原子存储接点、lease、停止／迟到／物理空闲语义。账本或审计失败仍关闭新准入，不把无上限解释成无需可靠记录。
4. **恢复不抹掉历史。** 重开、重启、Fork 或宿主子任务组织不使已发生消耗和 UNKNOWN 消失。共享 SDK 按自己的中立身份合同支持账本关联；业务父子计量由宿主负责，不凭新 session 声称无历史。旧有限任务改为新策略需有显式授权及可核查迁移／配置身份处理，不自动改绑或重放未知效果。
5. **重试并未放开。** JuanerAI 仍采用原请求加一次额外请求；备用与超时／失败自动重试共用这一次，不与 native retry 叠加。共享 SDK 若已有方式表达该策略，验证并给出接法；若无法表达，最小补齐并报告差异。正常多轮分析的下一步不是失败请求的额外重试；无累计上限不等于无限失败重试。
6. **保持分层和原生复用。** Pi循环、会话、队列、压缩等继续复用现有接线；公开契约不暴露Pi类型。无上限策略由可信宿主选定，模型、Skill、工具结果不能自授权限或修改它。
