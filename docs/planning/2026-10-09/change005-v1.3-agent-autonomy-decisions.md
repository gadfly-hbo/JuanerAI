### 1.1 后续直接确认：自主推进原则

用户引用下述原则并明确回复“完全认同”：

> Agent 自主推进，后台形成可检查的分析链；用户在业务歧义、权限变化和正式判断处参与，而不是管理每一步。

此原则作为 v1.3 产品准备的已确认依据：设计目标与完成条件，而非固定内部步骤；Agent 工作路线与 Analysis IR 分责；严谨机制由后台承担，避免把自主调查变为逐步人工批准。前文关于方法扩展、自动形成 IR、协作结果消费等具体方案仍须补齐行为、边界和验收，不能仅凭原则确认宣称全部细节已冻结或已实现。

### 1.2 后续要求采用：自主分析机制的五项内容

用户随后明确要求“不光这条原则，你前面的这段内容也要提炼进去”。据此，下列五项纳入 v1.3 的产品准备依据，不再只保留一句口号；具体支持范围、可见行为及验收仍在正式方案中闭合。

#### A. 目标与完成条件驱动，不以固定步骤驱动

向 Agent 提供用户目标、可用资料与业务语境、有效权限、交付要求和完成条件，由它决定阅读、追问、调查、工具及协作顺序。Agent 可先检查数据或先澄清目的，可随反馈补充分析、检查反证、修正代码及整理成果；简单任务不强走完整仪式。六阶段和五个关键时刻呈现当前理解、调查、可信程度及需要人的参与点，供检查与接管，不成为逐页打卡或固定内部调度器。

#### B. 可组合的分析能力，不以小型模板菜单限制开放需求

“支持的方法”应逐步落实为可组合、可执行、可核验的能力，而不是只有预写 M1／M2 或少数业务问题模板。依据任务组合筛选、关联、聚合、分组比较、分布检查、可视化及获准环境内的生成代码能力；Agent 可提出或探索新方法并说明限制。正式分析依据须有实际执行、方法适用性及相称验证，代码运行成功不独自证明分析正确。开放 Pi 循环不等于上述消费者已经具备；v1.3 正式输入须声明实际交付的能力范围及不支持情形，不能暗降级冒充原问题已回答。

#### C. 工作路线与 Analysis IR 分责，分析链在后台自然形成

Agent 工作路线描述接下来读什么、问什么、查什么或委派什么，可灵活变化；Analysis IR 明确某次实际分析的数据／Binding、业务含义、方法、参数及核验要求，并保持版本、真实消费及结果回链。Semantic Context 在理解、规划及结果解释中提供业务语境与来源，Binding 把业务含义接到实际数据，不是生成 IR 后才追加一层语义。

不将每次阅读、追问、写解释都编译成 IR，也不让用户逐节点批准。调用计算能力时，后台依据分析意图形成可执行描述，准确记录实际执行的方法、参数与输入身份；正式结论引用真实执行的计划及证据。探索计算也要保留实际执行记录和来源，不能事后补一份漂亮 IR 冒充原先执行过的逻辑，不能在 IR 外另跑不可追溯的正式计算。具体表示、物化及实现接点由工程接收处理，不要求手填完整 IR 或重写 Pi 循环。

#### D. 探索与协作结果自动回流、持续消费，正式效力按合同成立

子任务／工具结果可自动返回主 Agent，供比较、检查冲突、继续调查或补查，不以逐个手动采纳作为后续推理的前置。经既定计算和证据校验的结果，可按合同进入可引用证据及待审发现等相应成果状态，不新增每个数字的人工审批。回流、用于探索、通过核验和正式生效保持可辨；Agent 不能凭自称完成绕过核验、替用户作正式决定，或静默发布权威口径及长期资产。既有正式成果的人审与提交合同保留。

#### E. 有意义的边界触发参与，而非用户管理每一步

在有效任务及授权内，调整调查顺序、补查反证、自主委派、修正代码、整理草稿等正常推进不反复请求批准；后台每次实际效果仍核验权限。关键业务歧义、需要新资料／外发／工具权限、改变已确认目标／口径／交付承诺，或人的正式判断与决定，才触发相应澄清、授权或审阅。资料、文件、工具和外发边界，真实消耗、失败、UNKNOWN、停止与恢复持续受系统控制；路线自主不等于事实或权限自主。

## 2. 适用差异与保持不变

| 项目 | 本轮决定的效力 | 保留边界 |
| --- | --- | --- |
| Agent 路线 | 自主理解、分解、调查、选择工具及根据反馈调整路线；六阶段不是内部固定调度器 | Semantic Context、Binding、IR 的实际消费，真实计算、适用独立核验和来源一致性保留 |
| Fork／Subagent | v1.3 取消“只能用户发起”的产品限制；保留用户主动入口，同时支持主 Agent 自主创建／委派 | 创建／派发不自授新资料、工具、外发或现实行动权限，不替代人的正式决定 |
| 协作相关旧限制 | 不能把旧“单层／不自动派发／不并发”的整句当作 v1.3 一刀切禁令；相关机制需随自主委派一起评估并显式设计 | 本次不是任意递归／无限并发的工程合同；调度、循环防护和真实执行能力由后续方案及工程接收闭合，不以极小固定限制变相禁用自主委派 |
| 累计额度 | 当前 JuanerAI 策略保持“暂不设累计额度上限”，不是用很大的有限数冒充无上限 | 持久计量、历史消耗、预留及 UNKNOWN 保留；单次调用／工具超时、输出、隔离、授权有效期及显式停止不随之取消 |
| 重试／主备 | 本轮不更改 | 原请求加一次额外请求，备用与自动重试共用，不叠加；正常下一分析步骤不是失败重试 |
| Runtime | 修改共享 SDK 对无累计上限策略的支持，不重选 Runtime | Product Core → Application → Port → Adapter → Profile；Pi 类型留在 Adapter，产品采用独立确认 |

以上是当前用户决定的适用解释，不将旧冻结材料回写成新批准。后续 v1.3 正式输入需逐项列明被替代的产品规则，并视必要性以最小增量整合现行规则／蓝图引用；不增删 N01–N20 或另造 Runtime。生效范围是经接收的 v1.3，不据此要求 Mini 静默改写正在实施的 v1.2。

## 3. v1.3 准备时补齐的内容

- 围绕§1.2五项机制，明确实际支持的可组合方法、框架／语义／Binding／IR／计算／核验消费者，以及探索和正式成果之间的可验证转换；不以固定模板、显示文案或计划文件替代实际接通。
- 自主委派的任务目的、资料子集、授权来源、父子身份、进度、返回及失败／取消／未知状态；用户能查看并接管，而不是每次派发都批准。
- Fork 的另一条探索路线与 Subagent 的委派工作保持可辨；结果回流供主 Agent 后续分析，不等于正式事实采纳、Decision、Expected 或资产发布。
- 父任务停止如何传播、已开始效果如何结算、重启后的显式恢复，以及同一根任务下的累计计量；创建子任务不丢弃历史账本。
- 已接受 PX-004／006 壳层、独立协作历史与五个关键时刻保留；只准备新增或实质改变的可见行为，不重画替代 UI。
- 验收包括实际主 Agent 自主派发并消费返回结果、权限子集负例、停止／恢复、持久计量及来源回链，不仅检查按钮或配置。

这些是待补齐的方案项，不是本轮宣称已冻结的完整实现合同。正式方案按现行独立规划就绪审查及受影响用户 UI 接受要求推进，不新增审批机制。
