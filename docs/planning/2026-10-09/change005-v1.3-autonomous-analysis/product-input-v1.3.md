## 3. 用户任务与自主调查（AU-01／02）

### AU-01 任务目标，而非固定脚本

任务包含当前问题／目的、已知与未知、可用资料、关键业务含义、有效权限、交付要求与完成条件。系统自然形成可读框架，不要求用户装配内部对象；没有假设可形成探索方向。Agent 按实际观察选择读资料、检查质量、追问、调用方法／Skills、生成代码、补查、委派或整理报告的顺序。

同一问题遇到不同资料／反证须能改变路线；未需要的步骤不暗中执行。六阶段及五时刻供用户看“现在理解什么、正在查什么、可信到哪里、需要我做什么”，不强制按顺序逐页批准。可读工作计划是目的、工作项和依据，不展示内部思维链。

### AU-02 需求沙盘 ↔ 自主调查

进入方式继续是同一任务的“直接分析”与“先理清需求”。简单明确任务：自然表达的明确分析请求与有效任务授权成立，复用足够框架／整体审阅后推进，不强迫深聊或再点一遍每个字段。含糊任务：优先问影响判断的缺口，同时可在已有授权范围内查看结构和资料可行性，不先猜业务答案。

用户选“只整理需求”：允许获准模型共创框架、答案预演、已许可资料理解和结构／资格检查；**不调用分析计算、生成实际分析证据或正式判断**。保存与离开不启动计算；之后“按此方案开始分析”才产生明确执行意图，后台重新核验现有授权。保存失败如实保持未保存草稿，不报保存成功。

沙盘随调查按需更新：新事实可补充框架来源，普通调查安排变化自动记录；改变已确认目标、关键口径或交付承诺则停住受影响分支、展示影响并询问用户。答案预演表示“若出现某种证据，判断可能如何变化”，不造数字、因果或核验 PASS，绝不流入 Finding／正式证据。RS 保存、版本、no-op、模式共享及恢复要求继续适用。

## 4. 分析核心三角的真实消费者（AU-03／04／05）

### AU-03 Semantic Context 与 Binding

在理解、规划、工具准入及解释结果时实际消费任务语境：目的、对象、指标定义／单位、粒度、期间、关系、来源、适用范围与权威等级。区分用户陈述、资料事实、已确认含义、AI 候选和未知；列名相似不能替用户确认关键业务含义。Binding 把业务含义接到精确获准数据与物理字段／变换，保留版本和资格，不是 IR 生成后补一段语义文本。

可复用有效语义／方法配置，任务内自动发现相关定义及冲突；重要冲突需要人澄清，非承重缺失不阻断整个任务。当前任务修正仅形成任务级版本，不自动发布 Ontology／Domain Pack 或变成新全局权威。源提取资格和指标复算分开，不让“同错双算”证明源提取正确。全空输入阻断；合格输入中的单期零分母按原合同表述不足。

### AU-04 Agent 路线 ≠ Analysis IR

阅读、追问、解释、安排协作不逐项编译成 IR。**发起实际分析计算时**，后台依据分析意图形成受支持的 IR／受控物化，包含真实输入／Binding、语义与计划版本、方法、参数、代码／执行身份及适用核验要求；执行器真正消费该描述，结果回链同一计划。不是先跑另一条无约束计算再追补漂亮 IR。

每次合法筛选、期间、关联、分组、方法或参数变化须影响实际执行；错误输入身份、语义错配、不支持算子／方法或无法执行的内容拒绝，不用固定会员脚本暗降级。自动生成不等于自动放行：资格、授权、计划检查、版本一致性和结果绑定由确定性机制承担，不要求逐节点前台审批。探索计算亦保留真实计划／执行来源；未满足独立验证的计算可用于继续探索，不能晋升为已核验正式结论。

### AU-05 支持的组合范围及成果等级

延续开放问题入口，不按“预测／因果／探索”等题目名称禁用。v1.3 必须真实组合下表的最低分析能力；它不是全行业方法认证或通用平台完成承诺。每项须有方法适用性、实际执行与相称独立核验；能力描述用于 Agent 选择而非固定模板菜单。

| 最低交付组合 | 实际消费者及判断边界 |
| --- | --- |

成果分开保存／呈现：资料事实或观点、探索性计算、合格已核验证据、AI 解释／候选建议、有据待审发现／报告，以及人按原合同成立的正式效果。后台可自然组织和引用合格证据，但不代替用户的证据判断和正式提交。重要限制逐条可见，不能给整篇统一绿色可信印章。

## 5. 自主协作与可接管的回流（AU-06／07）

### AU-06 用户和主 Agent 都可发起

用户保留 Fork“比较另一思路”和 Subagent“委派检查”的入口；主 Agent 可按当前目标自主创建它们，不再逐次请求用户批准。Fork 是同根任务的另一条可比较探索路线，不覆盖主路线；Subagent 是有目的、完成条件和返回要求的委派工作。均保留独立可查历史及父子关系，与产品 Task／Case／Run 和 Pi 内部 session 分责。

可有多个独立分支，并允许必要的嵌套分解，不固定禁止孙任务。工程在既有受信本地能力内决定容量、排队和调度；容量不足显示排队及原因，不能假装同时执行，也不能以固定单层／永远一槽／禁用自动入口抵消本轮承诺。不得无限自复制：创建前核验与根目标有关、非已完成同一工作、合法资料／工具子集、可执行能力及可收敛返回；检测到循环／无有效进展时停止该分支并说明，主任务判断其他可行路线或询问用户。具体容量数值、算法和存储合同属工程；新的环境／费用／外部影响仍交用户。

**资料与授权：**每个后代具有自己目的和精确材料引用，实际可用范围是根有效授权、父分支范围、子任务声明及原协作资格的交集，不能因主任务有明细许可就继承全部明细。原 D2 允许的已核验最小汇总及获准文档精确子集保留；需要新原始表格明细／资料／模型／工具时按差异取得许可，不能主 Agent 自签。引用权限每次实际访问／外发核验，失效、移除或版本不符停止受影响效果；未选资料、任意目录、秘密禁止读取及出站。

用户可看委派目的、谁发起、父子关系、资料／权限摘要、实际工作状态、返回及主任务如何使用；可补充指示、停止某分支或整个任务，不管理逐个工具。进入历史不执行，浏览分支不自动恢复。

### AU-07 回流自动消费，不自动赋予正式权威

返回物绑定根任务、父子身份、任务／计划／数据版本、实际请求与工具执行、成果类型及核验状态；缺少有效身份／过期版本的返回不作为当前成果。主 Agent 自动接收并可比较、质疑、补查、修订下一调查工作或组织草稿；无需每个返回点“采纳”才能继续。

用户看到“已返回”“用于后续调查”“已核验”“待人判断”不同含义。原始 MODEL 意见仍不作为独立计算证据；具备实际计算和符合合同核验的返回可以进入对应证据／待审发现状态，**分支身份本身不提高证据等级**。意见冲突不能多数投票变事实；主 Agent 查资料／适用计算，无法解决就保留冲突和不足。失败或停止分支不把缺结果改写为“未发现问题”。

正式人的判断、会员 Finding／Closure／最终报告整体提交，以及 Decision／Expected／护栏、Owner 资产发布等效力继续依原合同。自动消费不触发正式“采纳为业务事实／记录决定”，不代签人审。旧手动采纳／拒绝入口可继续作用户意见／分支选择，但不再作为探索消费的强制前置。

| --- | --- |
| 有效范围内阅读、工具选择、调查顺序、反证补查、合法方法组合／参数、协作、草稿整理 | Agent 自动推进；后台资格、权限、IR 和版本检查持续进行，可查工作摘要，不重复审批 |
| 关键业务含义存在多个可改变结论的解释 | 明确问题和依据、说明为何影响结果；受影响分支等待。只有依赖可确认独立的工作可继续，否则暂停整体；不替用户猜含义 |
| 修改已确认目标／关键口径／对象期间范围／交付承诺，或新增权限 | 展示具体影响、需要的许可及可保留成果，由用户确认相应变化；确认不改变的部分复用，不把一个修改变为全面问卷 |
| 用户判断、正式决定／Expected／资产权威变化 | 保留原精确版本、人审和整体提交；聊天认可、草稿保存、AI 自动核验不冒充正式效果 |

### AU-09 修改闭环，不覆盖历史

区分同目标下正常调查计划变化、表达修改、业务承诺变化及新权限：正常调查产生准确工作记录，涉及计算产生对应新 IR／执行版本；不反复确认。表达修改不改数字／证据。业务变化按 FM-X：意图→必要澄清／影响→新版本与受影响失效→实际重算／核验→新旧对照。无变化不创建新 revision、Run 或消耗。

旧 Run／后代迟到结果不得污染新版；复用仅限证明无依赖影响的部分，影响未知扩大核验而非猜缓存有效。已批准任务内选择新版／保留旧版不伪装正式业务决定。新版本失败保留历史可查，但旧结果不能标当前成功。FM-05 同项目显式沿用方案、新任务重新核对当前资料／权限／适用性仍完整保留。

### AU-10 根任务与后代的停止、恢复与持久计量

“停止整个任务”先封闭根任务和全部后代的后续创建／调度／模型／工具及正式发布，再处理真实在途效果。显示“停止已受理／仍有在途效果”“已停止”“结果未知待核实”准确区别；不能只停止主页面或主 Agent turn。不可取消的在途操作保留物理占位、真实消耗／预留、结果未知和待对账，迟到结果不发布成功，不虚记退款。

停止某分支也封闭其后代：已经保存的有效结果仍可查；主任务只继续无依赖且权限有效的工作，依赖该分支的主张暂缺或待补证。用户停止不得由主 Agent 换名字再建等价分支绕过，除非用户明确恢复／重新允许。失败亦按依赖传播，不无条件“一处失败全任务作废”或无条件继续。

刷新／模式切换／重开只读持久状态，不重新执行；关闭网页不等于显式停止，已启动获准任务可继续；本地服务重启不自动续跑。用户显式恢复先核验有效授权、版本、已完成回执、全部相关后代及 UNKNOWN，确认物理安全后只推进缺失部分，无法核清则等待。父子摘要、调用／工具记录、返回和使用关系跨重启可读回，不仅存 Pi 内存队列或浏览器。

同一根任务累计所有后代、Fork、Run／Attempt／请求的实际消耗和未知预留；SDK 的内部 Task／Session 映射由 Adapter 实现，不把产品身份混为一体。暂不设累计额度上限，但不是免费、无限硬件或无保护。原请求＋一次额外请求，备用与失败重试共用；超时只有真实原调用已结束且安全才可额外尝试，UNKNOWN／工具效果不能盲重放。正常工具反馈后的新合法模型步骤与失败重试区分，创建子任务、重开和换 Attempt 不清账或重置重试机会。内存账本、缺 usage 填零、隐藏失败都不合格。
