# 插件接入标准（本地待审）

适用于JuanerAI固定采用的业务库、工具或同机服务。它提供现有接入提案／OpenSpec章节所需的信息，不新增批准权、公共Schema、manifest、状态机或审批台账。实际权威与本次状态见[入口](README.md)。

## 1. 共用业务实现，分别装配交付

业务实现及中立修复在插件原仓维护。独立入口与JuanerAI入口消费同一业务实现；允许不同启动、构建和装配配置，避免复制两份业务逻辑。

独立运行／发布路径继续保留；集成分发由JuanerAI携带固定插件资源和所需运行依赖，管理获准实例。集成用户不必另行安装、部署插件，也不必保有独立仓库、Node/npm或开发机浏览器。凭据、配置、数据和外发许可仍按对应任务合同显式建立，不因随包而自动继承独立版。

包、源码、设备采用、运行实例和接受是不同身份。分别记录业务源提交／快照、独立物料（若已制作）、集成物料、宿主采用提交及实际安装／运行证据；没制作或没授权的形态如实未执行，不把建设原则当现有安装证明。精确包内清单及摘要校验检测一致性，不等于发布者认证、公证或法律保证。

## 2. 按真实形态选择承载

| 本插件实际需要 | 最小接法 | 不随形态自动取得的能力 |
|---|---|---|
| 纯函数／库 | 固定依赖，按业务Port或已有函数接点调用 | 不强制HTTP、常驻进程、UI、Agent或账本 |
| 独立工具／同机服务 | 固定随包资源，显式入口／数据根；宿主拥有并按合同就绪／复用／停止 | 独立进程不要求用户另行部署；不接管未知进程 |
| 生成代码／重计算 | 采用已批准执行环境，按真实效果限制输入／网络／进程及输出 | cwd和子进程不是严格沙箱，不据此宣称企业隔离 |
| 使用LLM | 经已有共享pi-agent-runtime，产品保留业务与授权，固定实际SDK和单次保护 | 不新造Agent Runtime，不从文件夹发现凭据／会话，不统一不同任务的SDK或物理账本 |

新语言／协议等到真实消费者和授权再处理。纯库没有进程可说明相应生命周期项不适用；缺安装、数据或Provider授权必须标未授权未执行，不能写N/A。

## 3. 在现有提案／设计中补齐必要信息

| 信息 | 本次接入需明确的内容／完成条件 |
|---|---|
| 用途与入口 | 用户要完成的任务、可见入口／回程、成果含义及非目标；新增可见行为绑定适用批准UI输入 |
| 固定来源与物料 | 原仓／精确提交或不可变快照、版本、bytes／SHA、运行依赖及通知；独立与随包物料对应同一业务实现及构建差异 |
| 调用／输入／输出 | 业务Port和具体装配；获准材料的精确版本／范围／来源；输出引用、格式、限制和质量含义，不传整个业务数据库 |
| 权限／效果／外发 | 谁授权哪些效果、对象、接收方、预算／有效期；凭据保管；撤权／越界／副作用／未知如何拒绝 |
| 状态与停止 | 区分受理、工具成功、业务成功、保存成功；错误、取消、迟到、物理未停和未知效果的实际读回及允许续作 |
| 数据与历史 | 原数据、插件工作区、宿主关联／成果副本分别归谁；持久化／恢复／保留义务，无持久状态则说明原因 |
| 兼容／更新／回滚 | 谁选择采用版本，哪些合同变化需先处理；旧包／数据／任务兼容及不可逆边界；活动／未知不热换 |
| 验证与未完成 | 适用正负例、业务正确性、需要的真实权限、复用证据和失效范围；精确未执行／UNKNOWN及接续点 |

这些是信息项，不是强制字段名、文件集或万能JSON。现有合同够用就复用；公共／持久化语义变化按原执行政策处理，普通私有工程选择连续推进。

## 4. 责任放在已有层次

JuanerAI拥有用户任务与成果语义、材料选择／来源、授权、宿主入口和实例管理；业务Port使用JuanerAI业务或标准平台类型，Profile／composition root选具体Adapter。插件拥有算法、业务工具和编辑工作，返回实际产物和限制；集成不会自动赋予它原分析／正式决定身份或任意宿主数据写权。

LLM／Agent的通用运行机制继续由共享SDK承担；业务方法留在产品。Pi私有类型、事件和原生会话结构不进入业务Core／Application／公开合同。SDK版本与标准文档版本分别固定；现行唯一标准入口是本机可访问共享包的`docs/AGENT-RUNTIME.md`，本标准不复制或修改它，标准更新不批准存量迁移。

宿主明确任务授权与累计策略，保留单次保护、可靠计量、安全审计与UNKNOWN。模型主请求、实际启用的备用／retry、图像、压缩和其他辅助请求按实际SDK合同进入同一权威任务计量；次数不等于金额，接受不封累计上限也不授权新的Provider或无限失败重试。不同插件不因此合并Session、存储、数据或物理账本。

## 5. 五步连续接入

1. **盘点**：固定源和现有包，区分业务问题、模型问题、接线问题与测试环境；完成条件是当前消费者、真实能力、已验证／未知和缺失权限可读。
2. **对齐**：明确任务、最小输入输出、权限／效果、来源和适用UI／产品输入。复用有效决定，只将新增业务、安全、数据、成本和权限问题直接交用户；完成条件是影响本次接线的语义和授权闭合。
3. **接线**：业务Port／薄Adapter／composition root消费已有实现及载体，固定资源定位、实例归属和返回；完成条件是一个可观察的真实接缝，不是空抽象或平台。
4. **验证**：从[清单](acceptance-checklist.md)选择通用正负例，加插件自己的业务场景；先确定性合成接缝，真实效果按授权执行。完成条件是证据绑定实际候选，失效项补验、未变项复用，缺口如实保留。
5. **接受与固定交付**：相称独立验证，必要用户／UI接受及获准交付分别记录；有Git／发布授权才走原仓库收口流程。完成条件是本任务承诺范围有实际回执及安全回滚／接续点，不把源码同步当安装、运行或接受。

记录放既有OpenSpec、验证和交接章节，不增加PRD／审批／状态台账。本次文档沉淀止于本地待审；未授权的Provider、安装／升级、生产切换和Git／发布仍未执行。

## 6. 原仓维护、固定交付、宿主受控升级

业务功能和中立修复回原仓；宿主入口、权限、任务／成果映射与装配留JuanerAI；共享运行机制缺口向SDK提案，不分叉底座。

原仓相称验证后，从精确提交／不可变快照产出固定集成物料，列来源、版本、bytes／SHA、依赖通知、合同差异与验证。集成物料不必先公开发行独立版；不打包活动源码目录代替固定交付，不追随浮动latest、不覆盖旧包。

JuanerAI自主选择采用时点，可保留旧版或合并几次上游迭代。合同不变只补受影响装配／回归；输入输出、权限、恢复或持久合同变化先处理兼容及必要决定。采用、设备安装、运行切换、发布和产品接受分别记录；活动或UNKNOWN任务不热换，旧会话／数据／账本不改绑。保留旧包和数据兼容条件，程序回滚不等于数据迁移可逆。

首次建立升级基线及每次采用新物料前，在现有交接／验证记录做最小差异表：修复位置与业务／宿主／共享机制归属，原仓维护提交及对应回归，目标交付是否实际包含，缺口和证据。分别写“原仓与目标均证实包含”“已回流未进入目标”“待回流”“宿主专属”“UNKNOWN”；没有回执时不能从版本或提交存在推定目标包含。

不能证明新物料保留已验业务修复或数据兼容时，建议阻止**该次新升级**，保留旧验收包。必要临时补丁须单独授权，固定源／补丁／物料身份和回流计划；不抹掉补丁或形成第二业务分叉。此检查不追溯为已完成原任务增加门槛。Report Studio本次两项修复只读状态见[参考中的差异表](report-studio-reference-adapter.md#中立业务修复与维护状态)。

## 7. 留给真实下一插件的决定

第二插件、公共抽包、新语言／协议、统一Session／数据库、企业权限与严格隔离、动态发现／安装／热切换、另一个Runtime及生产运行均不在本沉淀交付中。按下一真实消费者准备最小差异与必要授权；不把方向写成既有能力。
