## 2. 已采用的定义与边界

| 内容 | v3.3.4的处理 |
|---|---|
| 双主线定位 | “目标牵引，问题探索，证据连接”；OSM管目标如何达成，PIM管问题如何查明、洞察如何形成 |
| OSM全称 | 保持Objective & Strategy Management System；目标—策略—度量继续是业务解释，不替换正式名称，不改OSM八模块 |
| PIM正式命名 | Problem & Insight Management，问题与洞察管理；将现有问题提出、需求澄清、分析框架、调查、判断和跟进归为业务流程 |
| QEA的角色 | Question–Evidence–Answer只作循证逻辑辅助解释，不并列为第三条业务线、新系统或新工作台；答案可支持、否定或尚不能判断 |
| Xanthil关系 | 统一承载两类任务的项目、会话、计划、证据、报告、审批与反馈，保留OSM经营对象所有权 |
| 三种分析模式 | 假设先行、深度研究、自主探索共同服务两条业务线；不把PIM固化为只走假设先行 |
| 共享内核 | 继续使用Contract、Context／Binding、IR、DAME、适用Pack、本地计算、四库双库与治理；PIM不另建Runtime、IR、资产库或发布权威 |
| 双向接续 | 目标Gap进入调查、证据结论返回策略候选、经验证机会经用户确认形成新目标或调整候选，分别保留精确身份与门禁 |
| 非目标型任务 | 普通问题无需Objective或Gap，可以在有边界的洞察交付后结束；异常、报告完成、用户认可不自动成为目标、行动许可或长期资产 |
| 先C后B | v3.3.3的路线保持；附件“先验证会员复购目标”仅为获准OSM场景的局部建议，不将完整OSM前置到个人Desktop |
