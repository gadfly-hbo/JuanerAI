## 1. 结论

台账有 **37 个探索：34 个 Demo已评估、2 个讨论中、1 个已Handoff**。讨论中的 PX-001、009 也保留已有 Demo 证据，不能因此认定尚未做 Demo；已评估也不能一律称为用户已接受或生产实现完成。

建议形成 **12 项优先验证单元 + 8 项按模块触发的专项 + 1 项真实用户验证**。这些是可讨论的验证队列，不是 21 个已立项项目。A/B/U 编号仅限本报告；选定下一项时先在台账登记唯一 PX ID，再冻结七项最小输入，保持一条主流程、最多三类失败路径。可以复用已有 Demo 的后续版本，不要求每项新造一套页面。

重点转向三个缺口：

1. **方法是否真实有效运行**：方法资产、实验分析、数值优化不能只靠名称、预置 Evidence 或资格灯证明。
2. **链条是否实际接续**：输入来自上一段的真实导出/公共入口，同一对象身份和计算事实贯穿下游，不能手填同名对象。
3. **现实变化是否能承受**：新数据、撤权、取消、进程退出、延迟回执和旧版本重放，不应造成错误结论或重复动作。

不是所有单元都要阻塞所有开发。A01–A06、A08 优先服务共享分析主链；A07 在模型消费模块前；A09–A11 在对应 OSM 模块前；A12 在周期任务前。每项结果只解除自己的不确定性，不代替正式产品验收。

## 3. 三条关键来源断点

### 3.1 需求共创尚未真实接入解析链

[PX-031 README](../../../explorations/PX-2026-031-context-resolve-binding/demo/README.md) 明确：029/030 仅作语义与夹具风格参考，独立合成复刻；[PX-030 引擎](../../../explorations/PX-2026-030-analysis-requirement-co-creation/demo/engine.mjs) 为固定问题与规则。032 的 [pipeline.py](../../../explorations/PX-2026-032-semantic-materialization-local-evidence/demo/core/pipeline.py) 确实消费 031，但其 [ir.py](../../../explorations/PX-2026-032-semantic-materialization-local-evidence/demo/core/ir.py) 是本探索的局部编译，不能说已经接通 PX-014 通用编译器。

因此，A04 需要先显式对齐草稿、确认修订、方法、时间窗和 Pack 版本，不能直接把 030、031、014、032 的对象改成相同 ID 后宣称贯通。

### 3.2 分析与复盘是两条真实但独立的来源链

[PX-035 compose.mjs](../../../explorations/PX-2026-035-context-commit-routing/demo/compose.mjs) 读取 032 Evidence/Provenance，并调用 034。源码明确分开 `analysis_source` 与 `review_source`；二者只是共享会员主题。032 的 60% 不能当成 034 的行动结果。[PX-036 compose.mjs](../../../explorations/PX-2026-036-review-teach-pack-adoption/demo/compose.mjs) 已真实接续 035 和 028，但没有消除前述原始案例差异。

A11 要以一个新的一致场景串联，保留原 Demo 和旧证据；若原公共接口不能接入，记录最小适配和语义差异，不能用复制 fixture 掩盖。

### 3.3 看板和数值方法之间仍有空隙

[PX-037 compose.mjs](../../../explorations/PX-2026-037-future-action-dashboard/demo/compose.mjs) 由本地 `buildScenario()` 装配，未接真实 033/034；[README](../../../explorations/PX-2026-037-future-action-dashboard/demo/README.md) 明确刷新回初始 fixture、无真实指标计算与长期持久化。它已经回答看板问题，不应重开同样页面；在 A11 中用实际链条结果驱动其视图才有新增价值。

## 7. 顺序与停止条件

### 默认串行建议

`A01 → A02 → A03 → A04 → A05 → A06 → A07 → A08 → A09 → A10 → A11 → A12`。

### 单项何时结束

1. 一个核心验证问题有可复现答案；合法主路径及最多三类失败路径通过独立评审。
2. 输入/版本/规则的判别性变化真实影响计算或状态，不是只换标签或命中预置答案。
3. 交付真实产物、来源/版本/完整 SHA、运行方式、检查证据、未验证事项和采用建议；失败也可以形成有价值的“方案不成立”结论。
4. 剩余未知属于真实规模、特定企业数据、操作系统适配或生产环境时，登记到目标模块验收，不无限扩大当前 Demo。

### 不适合提前做成“全通过”的项目

生产 SLA/压测、真实模型未来效果、真实业务增量、全部企业权限与合规、跨设备安装升级、Windows 桌面路径、真实渠道/供应链执行与灾备，只能在相应环境验证。可以先做局部可行性探针，但不能让 synthetic PASS 替代真实验收。完整 A/B 分桶平台、通用 Runtime 平台、完整项目管理套件不是当前补 Demo 的范围。
