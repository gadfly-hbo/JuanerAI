## 2. 已确认的核心决策

以下决策已经确认，后续规划不应无故重新讨论或反向修改。

### D1. 不直接以完整 B 端系统作为首个市场入口

JuanerAI 产品早期不直接销售完整“企业智能决策平台”，而采用专业个人用户驱动的渐进式路径。

### D2. 采用“个人 → 团队 → 企业”的产品驱动增长路径

```text
Xanthil Desktop / CLI
→ JuanerAI Workspace
→ JuanerAI Enterprise
→ 有限域决策自动驾驶
```

### D3. Xanthil Desktop 是 JuanerAI 的个人入口产品

Xanthil Desktop 不是独立于 JuanerAI 的另一条产品线，而是 JuanerAI 面向个人专业用户的入口和企业种子。

推荐品牌表达：

```text
Xanthil Desktop — by JuanerAI
Xanthil CLI — by JuanerAI
```

### D4. Xanthil Desktop 采用免费、本地优先策略

免费版必须提供完整的个人工作价值，不做成残缺试用版。

免费版的目标不是直接收入，而是：

- 获得真实用户；
- 完成真实分析；
- 建立留存；
- 沉淀个人资产；
- 形成企业内部传播；
- 培养企业 Champion。

### D5. JuanerAI Workspace 是不可缺少的中间层

不能只设计“免费个人版 → 企业私有部署”。团队协作、资产共享、审核和决策记忆是个人进入企业的必要桥梁。

### D6. 企业版出售的是决策闭环，不是更多 AI 次数

JuanerAI Enterprise 的核心付费价值包括：

- 企业数据接入；
- 团队和企业资产共享；
- 语义治理；
- 权限和审计；
- OSM、DAME；
- Model Pack、Domain Pack；
- 决策审批和执行；
- 结果反馈和持续学习；
- 自动化授权治理。

### D7. 全产品矩阵必须共享统一对象模型

Desktop、CLI、Workspace、Enterprise 必须共享 Analysis IR、假设、证据、决策候选、策略、行动和结果等核心对象。

不得分别设计多套互不兼容的数据模型。

### D8. 默认提供决策候选，而不是替用户直接决策

早期 JuanerAI 是决策副驾驶。自动化必须按风险、场景、历史验证和企业授权逐级扩大。

### D9. 企业专属数据和决策资产严格隔离

- 个人资产默认本地；
- 团队或企业迁移必须显式授权；
- 每家企业的假设、策略、案例和反馈独立存储；
- 不得将客户专属资产直接汇总为公共策略库。

## 4. 统一产品叙事

### 对外主叙事

> JuanerAI 帮助数据驱动决策者持续做出更好的决策。

### 个人产品叙事

> JuanerAI Workspace 把个人分析能力变成团队可共享、可审核、可复用的决策能力。

### 企业产品叙事

> JuanerAI Enterprise 连接企业目标、数据、知识、模型和行动系统，形成可验证、可审计、可持续学习的智能决策闭环。

### 长期叙事

> JuanerAI 从决策副驾驶开始，通过真实使用、假设验证和策略反馈，逐步在明确授权边界内演进为企业的决策自动驾驶系统。

## 5. 核心用户路径

```text
1. 用户下载 Xanthil Desktop
2. 导入本地文件或连接本地数据库
3. 提出真实业务问题
4. 系统生成 Analysis IR
5. 本地执行 SQL / Python
6. 形成假设、证据、反证和结论
7. 生成多个决策候选
8. 保存为 Decision Case
9. 重复使用并沉淀模板、Skill、假设和策略
10. 分享结果或希望同事复用
11. 创建或加入 JuanerAI Workspace
12. 团队共享、审核和追踪决策结果
13. 选择一个业务场景进行企业试点
14. 接入企业数据、身份、语义和权限
15. 升级为 JuanerAI Enterprise
16. 在验证充分的决策域内逐步扩大自动化授权
```

### Contract 原则

1. 对象必须可本地持久化；
2. 对象必须可导出和导入；
3. 对象必须支持版本；
4. 对象必须保留来源和证据；
5. 对象必须支持从 Personal Workspace 迁移到 Team / Enterprise Workspace；
6. 迁移时必须支持脱敏和权限检查；
7. Enterprise 可为对象附加审批、权限、审计、语义和执行状态；
8. 不得让企业治理字段侵入业务核心对象的最小可用结构；
9. Core Domain 与 Infrastructure Adapter 分离。

## 9. Desktop 首期验收标准

首个可用版本必须能够完成以下端到端验收：

1. 用户在本地导入一份真实数据；
2. 用户以自然语言提出业务问题；
3. 系统生成可读、可修改的 Analysis IR；
4. 系统仅向 LLM 发送必要信息；
5. SQL / Python 在本地执行；
6. 用户可查看执行代码、结果和错误；
7. 系统至少生成一个可验证假设；
8. 假设包含支持证据和可能的反证；
9. 结论标记为 Confirmed、Rejected 或 Inconclusive；
10. 系统生成两个或以上可比较的决策候选，或明确说明证据不足；
11. 每个候选包含依据、风险、适用条件和验证指标；
12. 分析可保存为 Decision Case；
13. Decision Case 可重新打开、复跑和导出；
14. 原始数据默认不离开本机；
15. 用户可以清除沙箱、缓存和临时资产；
16. 所有关键操作具有基本日志；
17. 个人资产结构可被未来 Workspace 读取，不需要重新设计。

## 11. 企业转化触发器

产品内需要预埋以下转化信号，但不得以强打扰方式损害免费产品体验：

- 用户频繁导出并分享 Decision Case；
- 多名同事使用相同模板或 Pack；
- 用户尝试共享假设库或策略库；
- 用户需要共同审核结论；
- 用户希望追踪策略执行结果；
- 用户重复手动连接相同企业数据；
- 用户提出身份、权限、审计或私有部署需求；
- 用户使用量表明某一团队已有稳定场景；
- 用户主动申请团队试点或企业部署。

可提供但不强制的产品能力：

- “生成团队试点说明”；
- “导出本月价值报告”；
- “创建 Team Workspace”；
- “申请企业私有部署”；
- “将本地资产迁移到团队”。

## 13. 企业试点原则

企业试点不得以“部署整套平台”为起点。应采用：

```text
单一高价值场景
→ 有限数据接入
→ 明确业务指标
→ 生成决策候选
→ 人工审批
→ 执行
→ 结果反馈
→ 形成价值报告
```

推荐试点场景：

- 会员流失与召回；
- 商品库存诊断；
- 营销活动复盘；
- 门店经营诊断；
- 销售预测与异常归因。

每个试点必须预先定义：

- 业务目标；
- 现有基线；
- 数据范围；
- 决策责任人；
- 结果度量；
- 风险边界；
- 人工接管点；
- 试点结束和扩展条件。

## 14. 必须避免的错误方向

1. 不要把 Xanthil Desktop 做成纯聊天式智能问数；
2. 不要以下载量代替真实任务完成和留存；
3. 不要一开始开发完整企业平台；
4. 不要让 Workspace 缺席；
5. 不要以更多模型次数作为主要企业付费点；
6. 不要把企业数据用于未经授权的跨客户学习；
7. 不要让 Desktop、CLI 和 Enterprise 各自维护独立核心；
8. 不要在没有反馈闭环前宣称自动驾驶；
9. 不要先做大量行业功能，再寻找首个高频场景；
10. 不要把复杂企业治理逻辑提前塞进个人产品 UI；
11. 不要牺牲本地优先和数据安全换取短期便利；
12. 不要只沉淀聊天历史，必须沉淀结构化决策资产。

## 17. 总控执行指令

请以本文件作为 JuanerAI 产品矩阵与增长路径的战略基线，完成后续产品和技术规划。执行时应遵守：

- 保持 JuanerAI“持续做出更好的决策”的总定位；
- 以 Xanthil Desktop 免费、本地、可信、真实任务可用为当前第一优先级；
- 统一 Analysis IR、Decision Case 和核心决策对象；
- 将 Workspace 作为个人到企业的必经桥梁；
- 企业版以决策闭环、治理和行业能力为核心，不以问数和聊天为核心；
- 暂不超前建设完整企业平台，但必须在架构中保留自然升级路径；
- 所有自动决策能力必须建立在证据、反馈、授权、审计和回滚之上；
