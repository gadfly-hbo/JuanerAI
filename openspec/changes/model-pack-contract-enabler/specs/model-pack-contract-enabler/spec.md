# Model Pack Contract Enabler Specification

## Capability Contract

- Change: `CHG-model-pack-contract-enabler`
- Planning contracts: `MP-C01..MP-C05`
- Accountable user: Data Analyst
- Package identity: exact `juanerai.sales-demand-forecast`
- Schema/contract version: exact `1.0`
- Runtime scenario: one local, deterministic, 28-day per-category demand forecast
- State in E: inactive

`SHALL`, `SHALL NOT`, `MUST`, and `MUST NOT` are normative. Unknown fields, values, versions, capabilities, permissions, and identities are rejected rather than ignored, coerced, defaulted, migrated, routed, or retried.

## Stable Error Vocabulary

The exact public TypeScript types and signatures in `design.md` are normative.
All nine `packages/contracts/model-pack.ts` functions are synchronous. Their
only failure carrier is `ModelPackContractError`, whose exact public fields are
`name: 'ModelPackContractError'`, one closed `code`, and `message` exactly equal
to that code; `modelPackError` accepts only the code. The Runtime factory is the
only other synchronous boundary and throws that same carrier with
`ANALYTICAL_MODEL_RUNTIME_INCOMPATIBLE` for construction failure. Runtime
`preflight`, `openRun`, and `predict` always return a Promise and report every
specified failure by Promise rejection with that carrier, never by synchronous
throw or raw predictor rejection. No public error message/cause exposes a URI,
credential, path, training/provider/SDK/MLflow object, raw data/rejection,
stack, tool/session structure, or partial prediction. A lower boundary's listed
business error is preserved unless this specification explicitly assigns a
more precise code.

| Code | Exact condition |
|---|---|
| `MODEL_PACK_CONTRACT_INVALID` | malformed/non-canonical serialization; unknown, missing, null, wrong-type, out-of-range, internally inconsistent, or otherwise invalid closed package/release structure |
| `MODEL_PACK_CONTRACT_UNSUPPORTED` | package schema, release-status, JuanerAI contract, scenario input, or scenario output contract version is not exact `1.0` |
| `MODEL_PACK_IDENTITY_MISMATCH` | expected and observed package identity, stable version, or package checksum differ |
| `MODEL_PACK_ARTIFACT_MISMATCH` | package-declared Artifact checksum, byte size, or model-Signature checksum differs from the supplied observation |
| `MODEL_PACK_PERMISSION_DENIED` | manifest serialization/admission finds a missing or widened value outside the fixed local-only grant; the defensive preflight comparison uses the same code if unequal admitted permissions ever reach it |
| `MODEL_PACK_LICENSE_INVALID` | a present closed license has an empty/invalid identity or terms checksum |
| `MODEL_PACK_REVOKED` | the supplied Controller-authoritative release status marks the exact package release revoked |
| `MODEL_PACK_RUNTIME_INCOMPATIBLE` | admitted manifest Runtime identity/version or dependency requirements differ from the immutable factory binding |
| `MODEL_PACK_INPUT_INVALID` | the scenario input is not the exact closed, continuous, single-currency snapshot contract |
| `MODEL_PACK_OUTPUT_INVALID` | predictor-fulfilled forecast shape, dates, categories, values, or intervals violate the closed forecast contract |
| `MODEL_PACK_RELEASE_REQUIRED` | input does not carry exact `MP9_MODEL_RELEASED` stage and exact Controller `model_released` decision |
| `MODEL_PACK_RELEASE_REFERENCE_INVALID` | Registry version is non-exact/alias/latest; the Artifact locator is imprecise, non-canonical, a raw path, or non-`file:`; or the supplied local location-verification assertion has missing/invalid identities or the wrong kind |
| `MODEL_PACK_RELEASE_EVIDENCE_MISMATCH` | two valid values that repeat across the frozen release input conflict, or the supplied Artifact observation's URI/SHA/size/model-Signature differs from its release/manifest counterpart |
| `ANALYTICAL_MODEL_RUNTIME_INCOMPATIBLE` | Runtime factory/Port/Run call has a malformed closed shape, predictor/deadline/signal, or Pack/readiness binding that does not equal the immutable factory/preflight binding, or contains vendor/tool/session leakage |
| `ANALYTICAL_MODEL_INPUT_CHANGED` | the current canonical input bytes do not equal the Controller-confirmed snapshot SHA-256 |
| `ANALYTICAL_MODEL_RUN_ALREADY_STARTED` | the one-shot Run's `predict` is invoked concurrently or more than once |
| `ANALYTICAL_MODEL_CANCELLED` | cancellation wins the terminal race |
| `ANALYTICAL_MODEL_DEADLINE_EXCEEDED` | deadline wins the terminal race |
| `ANALYTICAL_MODEL_RUNTIME_FAILED` | selected Adapter rejects/throws, or another valid non-output Runtime failure wins before cancellation/deadline; an invalid fulfilled output is never this code |

Error selection is deterministic. Manifest admission applies: canonical/closed shape -> exact contract versions -> license -> permissions -> expected package identity -> Artifact observation. A missing license object is a closed-shape failure; an admitted license object with invalid values is `MODEL_PACK_LICENSE_INVALID`. Each missing or widened manifest permission fails at serialization/admission as `MODEL_PACK_PERMISSION_DENIED`. Runtime factory construction independently admits only the same exact literal permission binding and maps malformed permissions to `ANALYTICAL_MODEL_RUNTIME_INCOMPATIBLE`; consequently a permission-unequal admitted manifest and valid factory binding cannot be constructed through the public surface. Preflight retains a defensive permission equality check but has no separate executable mutation obligation. Manifest Runtime/dependency shape errors are `MODEL_PACK_CONTRACT_INVALID`; equality against the factory Runtime/dependency binding is checked only at preflight and is `MODEL_PACK_RUNTIME_INCOMPATIBLE`. MP9 admission first classifies absent/wrong stage or Controller decision as `MODEL_PACK_RELEASE_REQUIRED`, then canonical/closed shape (including limitation, license, rollback, and supplied location-verification validation), exact local `file:` reference, equality only for repeated release fields, separate expected-package equality, and observation equality only for URI/SHA/size/model-Signature. A conflict between repeated release values or those four comparable observation values is `MODEL_PACK_RELEASE_EVIDENCE_MISMATCH`; only conflict with the separately supplied expected package is `MODEL_PACK_IDENTITY_MISMATCH`. A different valid release-instance singleton is not a mismatch. `admitModelPackReleaseStatus` closes both `released` and `revoked`; Runtime preflight then verifies its exact package/version/Artifact binding and rejects `revoked` before readiness. Runtime `predict` applies one-shot admission first, then exact call/deadline/signal validation, already-aborted cancellation, expired deadline, issue, terminal race, forecast admission, and final cancellation/deadline check. The first applicable code is returned and no later check causes an external effect.

## Requirements

### REQ-MPC-001 (MP-C01) — Closed Model Pack Package Contract

The shared contract SHALL expose exactly the public v1 types, constants, stable
error carrier, and nine synchronous function signatures frozen in `design.md`.
It SHALL admit and canonically serialize only one exact v1
`juanerai.sales-demand-forecast` package contract containing stable
package/artifact identity, compatibility, approved purpose and prohibited uses,
closed scenario I/O, Runtime/dependency/permission requirements,
release/training/evaluation provenance, limitations/confidence, license,
immutable revocation-policy declaration, and rollback. It SHALL also admit the
closed versioned `ModelPackReleaseStatusV1` value that carries the
Controller-authoritative current release decision separately from the immutable
manifest. Admission SHALL be pure, deterministic, fail closed, and independent
of a filesystem, MLflow, SDK, Profile, registry, persistence, network, or
external repository.

- **AC-MPC-001-01:** `serializeModelPackManifest` and `admitModelPackManifest` have exactly the Design signatures. A canonical manifest with the exact normative TypeScript declaration, exact package identity, strict stable `MAJOR.MINOR.PATCH`, lowercase SHA-256 values, positive safe byte size, exact v1 compatibility IDs, required release/evaluation evidence, non-empty limitations, valid confidence/license/immutable revocation policy/rollback, and the fixed local-only permission set is admitted from the one call carrying canonical `manifest_bytes`, `artifact_observation`, and `expected_package`, and round-trips to byte-identical canonical UTF-8 JSON. Recursive TypeScript property order is canonical JSON member order. The manifest contains no mutable current revocation state, and returned bytes/values do not alias caller-owned mutable input.
- **AC-MPC-001-02:** Fatal UTF-8/JSON, BOM, duplicate object member, non-canonical bytes, unknown/missing/null/wrong-type field, non-stable version, invalid checksum/size, empty required value, invalid date/decimal, malformed lifecycle union, or internally inconsistent package structure fails as `MODEL_PACK_CONTRACT_INVALID` without an Artifact, filesystem, MLflow, network, or model access.
- **AC-MPC-001-03:** A non-`1.0` manifest, release-status, JuanerAI, input, or output contract version fails as `MODEL_PACK_CONTRACT_UNSUPPORTED`; an expected package identity/version/checksum mismatch fails as `MODEL_PACK_IDENTITY_MISMATCH`; Artifact observation mismatch fails as `MODEL_PACK_ARTIFACT_MISMATCH`; malformed release status is `MODEL_PACK_CONTRACT_INVALID`; release-status binding conflict is `MODEL_PACK_IDENTITY_MISMATCH`; and invalid license, supplied `revoked` state, permission excess, or Runtime/dependency mismatch uses its precise listed code. Every public failure uses the exact sanitized carrier and sync-throw/Promise-reject mode frozen above.
- **AC-MPC-001-04:** The approved purpose is exactly 28-day category-demand planning review. The manifest carries the complete fixed prohibited-use set, local-only/no-network/no-external-data/no-MLflow-at-runtime/no-training-workspace/no-source-write/no-online-learning permissions, deterministic execution, limitations, and prediction-interval confidence. Missing or widened values fail closed.
- **AC-MPC-001-05:** `admitCategoryDemandInput` receives exactly `{ candidate, manifest }`; `canonicalCategoryDemandInputBytes` receives exactly `{ admitted_input, manifest }`. The exact scenario input contains `contract_version`, `as_of_date`, `currency`, and ordered `history`. History ends at `as_of_date`, covers at least 56 consecutive UTC days, has exactly the manifest's non-empty ordered `supported_product_categories` once on every day, and uses only `business_date`, `product_category`, non-negative safe-integer `order_count`, and canonical non-negative decimal-string `gross_order_amount`/`discount_amount` with discount not greater than gross. Duplicate keys/rows, missing date-category combinations, extra/unknown categories, future/invalid/non-continuous dates, mixed/unsupported currency, invalid amount, or insufficient history is `MODEL_PACK_INPUT_INVALID`.
- **AC-MPC-001-06:** `admitCategoryDemandForecast` receives exactly `{ candidate, manifest, admitted_input }` and admits only the forecast, not caller/predictor provenance. The exact forecast covers the 28 UTC dates immediately after `as_of_date` and every admitted category exactly once per date. Each row contains only `business_date`, `product_category`, canonical non-negative decimal-string `predicted_order_count` and `predicted_net_order_amount`, plus ordered non-negative lower/upper decimal strings for each target's 80% interval. Missing/extra/duplicate date-category rows, wrong horizon/category/currency, negative or non-canonical value, unordered interval, or unknown field is `MODEL_PACK_OUTPUT_INVALID`. Only the Runtime constructs the exact closed result/provenance from captured admitted bindings; it never admits provenance supplied by the predictor or caller.
- **AC-MPC-001-07:** Release metadata names exact `sales-demand-forecast-evaluation/1.0`, which freezes the 196-day training minimum, isolated-actuals policy, three 28-day rolling-origin folds, seasonal-naive `t-7` baseline, 5%/10% relative WAPE improvement, 5% key-category share, 5-percentage-point key-category regression limit, and 70%-90% observed coverage for nominal 80% intervals. The manifest carries only per-release observed aggregate values and evidence SHA, which must satisfy that contract. Neither training rows nor `acceptance-actuals.csv` is a manifest or Runtime input; no validator reads either source or recomputes training metrics.

### REQ-MPC-002 (MP-C02) — Exact MP9 Builder Input Gate

The shared MP9 release-input validator SHALL accept only one exact, internally consistent `MP9_MODEL_RELEASED` package release bound to a Controller decision, exact MLflow Experiment/Run/Registry version, one precise canonical local `file:` Artifact URI, Artifact checksum/size/model-Signature checksum, the exact v1 manifest, evaluation evidence, permissions, limitations, license, immutable revocation policy, and rollback. It SHALL validate each singleton at its own closed boundary, compare only repeated release values and the supplied observation's URI/SHA/size/model-Signature against their release/manifest counterparts, and SHALL never discover, fetch, dereference, read, or query an Artifact, MLflow, a filesystem, or a training workspace.

- **AC-MPC-002-01:** `serializeModelPackReleaseInput` and `admitModelPackReleaseInput` have exactly the Design signatures; admission receives one call carrying canonical `release_input_bytes`, the supplied `artifact_observation`, and `expected_package`. An exact MP9 input whose Controller decision is `model_released`, whose Registry version is a positive decimal integer, whose Artifact URI is one canonical normalized absolute local `file:` URI without credentials/query/fragment/alias/latest/traversal, whose repeated identities agree across decision/MLflow/Artifact/manifest/expected binding, and whose supplied observation's URI/checksum/size/Signature exactly match their release/manifest counterparts is admitted as an immutable Builder input when the supplied location verification has the exact kind and valid Controller-authorization/store/evidence identities. E validates that closed assertion but does not prove filesystem truth; P privately proves real existence, approved-root membership, and exclusion from training-workspace/cache/source paths.
- **AC-MPC-002-02:** MP7/MP8-only, missing/wrong stage, or missing/wrong Controller release decision fails as `MODEL_PACK_RELEASE_REQUIRED` and performs zero Artifact comparison. SDK/Consumer/product-completion fields are not part of the closed input and fail as `MODEL_PACK_CONTRACT_INVALID` rather than changing MP9 meaning.
- **AC-MPC-002-03:** `latest`, an alias, a non-positive/non-numeric Registry version, a raw absolute/relative path, every non-`file:` scheme, a non-absolute or non-normal `file:` URI, any credential/query/fragment/traversal/non-canonical locator, or a supplied location verification with a missing/invalid identity or wrong kind fails as `MODEL_PACK_RELEASE_REFERENCE_INVALID` before any Builder effect. E does not inspect the path or independently decide store/root membership.
- **AC-MPC-002-04:** `MODEL_PACK_RELEASE_EVIDENCE_MISMATCH` applies only to conflicts between fields that repeat in the two frozen inputs: Controller decision/package/release binding; MLflow Experiment/Run/Registry/URI; Artifact SHA/size/model-Signature; existing manifest/controller/evaluation-evidence bindings; and the supplied observation's URI/SHA/size/model-Signature versus release/manifest. Invalid permission, limitation, license, rollback, or location-verification singletons retain their precise lower-boundary code. Another valid value for a singleton, including Controller-authorization/store identities, is not an E-detectable evidence mismatch. No partial Builder input or success is returned.
- **AC-MPC-002-05:** E's contract suite supplies the Artifact observation through a deterministic double only and compares it as a pure value. A future P implementation owns real observation and Builder behavior after its own authorization and must privately prove approved Artifact-store/root membership and real existence; it may not change this validator, schema, driver, or error mapping.

### REQ-MPC-003 (MP-C03) — Scenario-specific Analytical Model Runtime

The `AnalyticalModelRuntime` Port SHALL expose exactly the Design TypeScript
surface. `defineAnalyticalModelRuntime({ binding, predictor })` SHALL be the one
real production construction seam shared by E's deterministic predictor and a
future C Consumer Adapter. The instance SHALL immutably own the exact
Runtime/Adapter/dependency/permission binding. The Port exposes only
scenario-specific `preflight` and `openRun`; `openRun` returns one one-shot Run
exposing only `predict`. One Run SHALL bind one exact Pack, Runtime, Adapter, and
confirmed input snapshot for its lifetime and SHALL perform at most one local
28-day prediction. No Agent Runtime, registry, fallback, retry, hot switching,
automatic routing, universal Runtime, network, provider/tool/session object, or
infrastructure error may cross the Port.

- **AC-MPC-003-01:** Construction accepts exactly `{ binding, predictor }`; a wrong key/shape/value, malformed exact-literal permission binding, or non-function predictor synchronously throws `ANALYTICAL_MODEL_RUNTIME_INCOMPATIBLE`, while successful construction captures a detached immutable Runtime/Adapter/dependency/permission binding and performs no predictor call. `preflight` receives exactly `manifest_bytes`, `artifact_observation`, `expected_package`, and supplied `release_status`; callers do not echo or select the instance binding. It compares admitted manifest Runtime/dependency requirements with the immutable factory binding and retains a defensive permission equality check. Because manifest serialization/admission and factory construction each admit only the same exact `ModelPackPermissionsV1` literal, Test SHALL NOT bypass either boundary or require a separate preflight permission-unequal mutation; permission widening is proved at manifest serialization/admission as `MODEL_PACK_PERMISSION_DENIED`. The release status binds that exact package identity/version/Artifact checksum, carries exact `released|revoked` state plus Controller decision ID, evidence ID, and decision time, and is supplied as a pure value with no lookup. Shape/version failure, reachable manifest-versus-factory Runtime/dependency mismatch, and `revoked` use their precise listed codes. Successful preflight returns one deeply immutable readiness record retaining the admitted manifest, exact release-status evidence, and factory binding using only JuanerAI business/standard-platform values. The future Application/A composition must obtain and supply the current Controller-authoritative status for the preflight of each Run; E provides no freshness lookup, cache, or registry.
- **AC-MPC-003-02:** `openRun` accepts one stable `run_id`, one exact readiness binding, and one confirmed snapshot containing `snapshot_id`, `confirmed_at`, lowercase SHA-256, and the closed input. It validates the input, recomputes canonical bytes, rejects checksum drift as `ANALYTICAL_MODEL_INPUT_CHANGED`, captures an immutable private snapshot, and causes no model execution. A Run cannot accept another Pack, release status, Runtime, Adapter, or input snapshot.
- **AC-MPC-003-03:** The Run's first `predict` requires one `AbortSignal` and one absolute RFC3339 UTC `deadline_at`, then calls the constructed local predictor exactly once after all admission checks with exactly `{ run_id, input, cancellation_signal, deadline_at }`, including the same signal object, same admitted absolute deadline, and captured admitted input. Only a valid fulfilled forecast is admitted; the Runtime constructs and returns the exact 28-day forecast result plus complete `run_id`, Pack, fixed model-release, exact release-status evidence that admitted the Run, input-snapshot, Runtime, and Adapter provenance. A concurrent or later `predict` is `ANALYTICAL_MODEL_RUN_ALREADY_STARTED` and issues no second call.
- **AC-MPC-003-04:** Cancellation already observed before admission wins over an already-expired deadline and returns `ANALYTICAL_MODEL_CANCELLED` without issuing work. Otherwise expiry before work admission returns `ANALYTICAL_MODEL_DEADLINE_EXCEEDED` without issuing work. After issue there is one atomic terminal outcome; cancellation wins over deadline when both are observed before terminal publication, while a deadline already published before a later abort remains final. Predictor rejection and fulfilled-output validation receive a final cancellation/deadline check, and success is published only after output validation. Production uses only standard `Date.now`, `setTimeout`, the supplied `AbortSignal`, and Promise semantics; no clock/scheduler hook or mandatory internal scheduling protocol exists.
- **AC-MPC-003-05:** Once cancellation or deadline wins, later predictor fulfillment/rejection is observed and discarded, cannot publish success, partial output, retry, fallback, alternate Runtime, or unhandled settlement, and cannot change the terminal code. Predictor synchronous throw or rejection that wins before cancellation/deadline is sanitized as `ANALYTICAL_MODEL_RUNTIME_FAILED`; its reason is never exposed. Invalid fulfilled output is `MODEL_PACK_OUTPUT_INVALID`.
- **AC-MPC-003-06:** Across two separately opened Runs using the same exact Pack, model release, release-status evidence, canonical input snapshot, Runtime, and Adapter, forecast rows are value-for-value identical. Run-specific provenance may differ only in `run_id`; a non-deterministic implementation fails the unchanged Runtime contract suite and cannot be activated.
- **AC-MPC-003-07:** Output exposes no MLflow URI, training path, external-repository path, Provider/SDK error, tool structure, session object, credential, raw stack, Decision, or Action claim. Network and source-write attempts are forbidden side effects and fail conformance.

## Normative Scenario Encodings

- Canonical decimal string: `0` or a non-zero integer without leading zero, optionally followed by `.` and one or more digits, with no sign, exponent, whitespace, `NaN`, or infinity.
- UTC business date: exact valid calendar date `YYYY-MM-DD`.
- Stable semantic version: exact `MAJOR.MINOR.PATCH`, numeric components without leading zeros, no `v`, prerelease, build metadata, range, alias, or `latest`.
- SHA-256: exactly 64 lowercase hexadecimal characters.
- Canonical ordering: the manifest's `supported_product_categories` is a unique non-empty ordered enum; input and output rows are strictly ordered by `business_date`, then that manifest order. Category identities are Unicode NFC, 1-128 scalar values, contain no control character or path separator, and are not `.` or `..`; the data authority remains responsible for confirming that they are stable business identities rather than free text or direct personal identifiers.
- Canonical JSON: UTF-8 without BOM, whitespace, duplicate members, omitted required members, or reordered object members. Objects follow the Design field order; arrays preserve their contract order. Admission reserializes the validated object and requires byte equality.
