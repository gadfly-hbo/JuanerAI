# Change002 增量产品输入：单一 Provider 模型接入 v1

日期：2026-09-30（Asia/Shanghai）。状态：拟议可点击输入，等待独立 Development-Readiness 与用户受影响 UI Gate；尚未冻结或开始生产实现。

## 1. 授权、目标与基线

用户先前批准 Xiaomi Token Plan、MiMo 2.6 Pro 真实测试及不设 Token Plan 总预算上限；本次明确回复“先做单一 Provider 的简洁配置面板即可”。批准的结果是用户能在普通 DMG 安装后的 Xanthil 中配置自己的 API Key，正常启动后使用既有模型能力，无需测试启动器、命令行或工程人员临时注入。

这是同一 Change002 的可用性增量，不新建 Change、不重置旧失败或接收记录。继承：AGENTS.md、docs/planning/README.md 所指 Blueprint v2.0 §4–10、2026-09-28 Case Assistant Product Plan v1.0、UI Contract v1.0、UI Gate/Product Input Freeze、原附件 README。工程执行唯一政策：docs/governance/product-change-execution-policy.md。复用 docs/governance/xanthil-first-slice-reuse-baseline.md 及已验收 Change1；旧 candidate008 / DMG007 仍为先前固定候选，不能代表本增量已完成。

四视图映射：Personal C3 的正常桌面可用性、C5 的可审阅决定以及贯穿 B 的明确数据授权；复用 PIM/假设先行、原六阶段、Application/Ports/Pi Adapter/Personal Profile。价值假设仅为“用户无需终端即可接入并辨认数据外发边界”，证据是普通安装/重启/配置/授权的可完成性；不宣称模型质量、效果、留存或整个闭环完成。C1/C2/C4/C6 的更大能力仍回到 Blueprint 对应消费者需求，不前置建设。

## 2. 本次产品范围

- 顶部全局“模型接入”入口，快速/专业模式及尚未打开 Project 时均可进入；未配置提示可直接进入同一面板。
- 固定 Xiaomi Token Plan（中国区）与 MiMo 2.6 Pro。无需用户填写 endpoint、模型 ID 或运行时参数。技术标识沿已验证的 xiaomi-token-plan-cn / mimo-v2.6-pro；不提供选择器、备用路由、自定义地址或模型下载。
- 使用范围：Case Assistant，以及 Change1 已批准的“帮我整理问题／帮我解释证据／帮我起草候选”单次辅助。统一接入配置不合并两类任务授权，单次辅助不变为多轮，不改变固定分析方法或 Finding 采纳权。每一入口仍使用其原有精确 payload、自由文本确认及失败回手动流程。没有新助手、新工具或业务数据类别。
- 输入 API Key → 用户点击测试连接 → 显示结果 → 成功后保存启用。保存后当前与后续正常启动可使用；不自动开始任务，不恢复旧 Attempt、不后台测试。
- 更换、取消、删除以及失效/网络/存储错误的可见恢复路径。Credential 是用户/本机范围，不放进 Project，也不随项目复制；MacBook 和 Mac mini 各自配置，不自动从 .zcode 导入或跨设备复制。
- 沿用冻结 Change002 的品牌、颜色、居中模式切换、三栏和六阶段布局。新弹窗为本次受影响 UI；原附件不修改。

可点击附件：provider-settings-ui-v1/index.html、panel.css、panel.js、README.md；base.css 与品牌图来自原稿。背景工作台为合成定位，完整 Case/单次辅助授权界面继续由原冻结合同约束，不以本原型替代其验收。

## 3. 凭据与数据边界

正式应用通过系统钥匙串保存此用户在这台 Mac 的 API Key，不打包进 DMG、不写入 Case/SQLite/导出/日志/命令参数/浏览器持久化。不得回填已存 Key 或提供读取/复制已存明文接口。用户正在输入的新 Key 可主动显示/隐藏；取消、关闭或成功保存后清空输入。只有经授权的本机接入链路接触凭据，进入模型认证头而非 prompt、工具参数或 transcript。若钥匙串不可用/用户拒绝系统权限，不降级明文，不声称保存成功。

“测试连接”是一次由用户明确点击触发、对固定 Provider/Model 的小型真实请求；仅固定文本 `Reply with OK.`，不带任何 Case、文件、历史、路径或工具。按钮附近说明消耗少量 Token Plan 额度；提供查看逐字文本。一次点击最多一个模型请求，有限输出及时间，不自动重试、轮询、切换模型或 PAYG。私有数值由工程方案确定并通过实际验证；全局不另设未经用户要求的总预算上限。手动再次测试是新的明确请求。

配置成功不授予业务数据外发权。普通 Case 不再被“专用合成测试启动器”作为唯一激活入口限制，但每次真实任务仍由原 UI 逐字/逐项披露并明确确认；仅该确认内容可发给固定 Provider，原不允许的数据/工具仍禁止。工程验收只使用固定合成数据与专用命令；不得把当前用户 Project 自动当作真实测试输入。未来任务发送的每条用户文本仍是明确发送动作。开机/打开 Project/切换模式/查看报告/更换配置本身都不能发送业务数据。

本拟议 UI 包零网络、零钥匙串、零持久化；不读取用户的任何真实 Key。真实请求和新生产凭据存储路径须待本增量 UI Gate/工程接收后按上述已批准效果完成，不把原型演示称为真实接入验证。

## 4. 操作、状态和失败语义

| 情形 | 可见行为与状态 | 必须保留的事实 |
|---|---|---|
| 初次进入 | “未配置”，固定 Provider/Model，空的 Key 输入；无值时测试不可用 | 无隐藏默认 Key、无联网 |
| 测试进行 | “测试中”，只允许取消/关闭；重复点击不重复请求 | 不自动保存；取消/关闭终止后续处理，已发请求可能消耗额度 |
| 测试成功，尚未保存 | 绿色“连接测试通过，尚未保存”，启用保存按钮 | 修改输入立即使测试成功证明失效；只保存本次已测试的输入 |
| 保存成功 | “已启用”，掩码“已安全保存”，清空输入；全局“模型已配置” | 当前及下次正常启动可用；任务仍待授权 |
| 应用重启 | 读取本机配置；显示“已配置／上次测试通过”，不声称实时在线 | 不自动测试、联网、开始或恢复任务 |
| 更换 | “原 Key 保留到新 Key 测试通过并成功保存” | 测试失败、取消或保存失败均不破坏旧 Key/历史；没有新 Key 的运行时半生效 |
| 现有 Key 被认证拒绝 | “凭据失效”，提供重新测试/更换 | 本次失败不自动重试；不能把网络失败/额度不足误称 Key 无效 |
| 网络/超时/额度失败 | 分别说明网络、超时或 Token Plan 额度不足，用户可手动重试 | 保留已保存配置与历史；不把暂时失败永久标成凭据失效 |
| 钥匙串不可用/权限拒绝 | “钥匙串不可用”，提示解锁/允许访问后重试 | 禁止开始新模型任务；无明文备份或另一 Key 回退 |
| 保存失败 | 清晰“尚未启用／旧 Key 保留”，可显式重试 | 未确认成功不得对外显示新配置可用；未知结果经读回核对，不猜测成功 |
| 删除 | 确认“仅删除这台 Mac 的 Key；Case/对话/草案/报告保留” | 取消无变化；成功回到未配置；失败不假装删除；不撤销远端账户 Key |
| 正在运行/等待回答 | 可看配置；测试、更换、删除不可操作，提示先停止任务 | 竞态时重新检查并拒绝变更；未提交的授权不能在换 Key 后偷偷沿用 |
| 非活动历史/草案 | 配置变化不改历史与来源，也不撤销已获用户确认的正式记录 | 新 Attempt 重新准备/确认；原合法草案人工采纳沿现有有效性规则，不因换 Key扩大权限 |

配置保存/删除生效时使尚未开始任务的旧授权失效，重新准备任务；已有 Running/Waiting（含正在启动/发送/配置测试）不会与凭据变更并发。具体锁/版本/提交点/错误码由工程决定，不能弱化以上可见语义。应用退出取消连接测试，不写入迟到成功，不产生后台模型调用。

生产状态需区分“模型未配置”“已配置（上次测试结果）”“凭据失效”“钥匙串不可用”与“任务待授权”；不得用“Provider 未授权”同时表示配置缺失和任务许可缺失。

## 5. 验收

- PS-01：从两模式及无 Project 状态进入同一面板；1440×900/1280×720 清晰可操作，键盘焦点进入/困住/返回，Escape 取消关闭；不得泄露已存 Key。
- PS-02：空值、测试成功未保存、输入修改、取消、关闭、重复点击/迟到响应均保持正确状态；每次显式测试最多一个固定测试请求，实际未携带业务数据。
- PS-03：正式 macOS 钥匙串实际保存/读取/替换/删除，正常 Finder/LaunchServices 重启后保持本机配置且无自动外发；另一设备/用户不自动获得 Key。依赖系统权限失败真实可见，检查日志/项目/包/导出无凭据。
- PS-04：认证拒绝、网络、超时、额度、系统权限/存储失败分别可辨认，旧可用配置和全部业务历史不受损。存储不确定结果读回后诚实结论，无失效配置/迟到事件误启用。
- PS-05：配置与活动任务/未开始授权竞态，Stop/重启/继续、新 Key 的使用边界正确；更换和删除不跨任务偷偷切换凭据，不撤销历史。
- PS-06：配置后普通安装应用中 Case Assistant 可走真实 Pi 路径；原三类单次辅助复用同一固定接入但分别确认原 payload。工程使用合成数据验证，不读取真实用户业务；未配置/删除/不可访问时模型路径关闭而原手动分析/采纳/报告路径保留。
- PS-07：全部旧 Change1/2 关键保护继续：精确数据授权、只读工具、来源/revision、停止/失败/重开、草案及用户采纳、不可变报告、Fork/Subagent Preview，无自动行动。
- PS-08：新唯一编号 DMG 在目标 MacBook 正常安装/启动后经用户输入 Key 完成设置，重开可用；本机测试、跨设备用户验收、工程验收分别标注。不得把临时启动器测试代替这一终点。

## 6. 非目标、工程留白与停止线

无多 Provider/自定义接口/模型市场/运行时切换/账户登录/同步/远端 Key 撤销/自动从 .zcode 导入/企业 IAM/新遥测/后台检查/订阅购买。保留现有 Pi 和模块边界；凭据存储 Adapter 与业务 Port 的最小合同由工程负责，无通用注册表。OS API、私有接口、运行时切换时机、可见本次任务数值上限、确定性错误码、证据及构建命令由工程在上述闭合语义下细化。

本增量正式流程：独立 product development-readiness PASS → 用户确认可点击 UI → 固定输入/增量 Engineering Intake → 同一工程上下文 OpenSpec/TDD/实现 → 固定候选与独立 Validator → 工程验收/新 DMG → 用户 MacBook 产品验收。用户已批准单一 Provider 方向，不再重复询问是否允许 Xiaomi 接入；尚未看过的新面板由受影响 UI Gate 确认。Git 提交/推送/合并/归档仍需现有独立授权，当前无此动作。
