# RS-PROCESS-01：本任务所有的独立后台子进程

对应M01/M06/M07、AC01/09/10/11。宿主的具体组合在固定资源验证之后，给私有启动器明确Node、内置入口、资源和数据目录。启动器不发现系统Node、独立仓库、已有端口或其他进程。本增量只提供生命周期接缝；固定随包构建与最终Profile接线仍需验证。

- 首次明确打开才启动。并行打开共用一个启动Promise；ready必须来自本次子进程IPC、符合固定版本/提交/协议且实际HTTP owner握手成功。服务绑定127.0.0.1随机端口，不凭端口开放声称就绪。
- owner随机令牌仅经专用IPC传递；子进程环境从最小平台清单构造，不继承宿主API密钥、其他工具认证或主分析控制令牌。内置模式必须显式开启；程序资源与用户数据分离。
- 超时、错误ready、启动失败或异常退出使实例不可用；不扫描或终止其他PID，不自动切换独立版。失败允许用户明确重试，此时新实例/令牌替代旧实例。
- 关闭只收回本实例准入并终止本启动器持有的子进程；先TERM等待、超时再KILL并等待exit。未观察到退出不能宣称已停止。退出不删除资料和交付，不影响主分析或独立版。
- 该增量无活动模型任务，制作接口维持closed。完整任务停止/UNKNOWN恢复、计量与用户许可仍需后续实现。

RS-LIFECYCLE-01：同一内置数据根以专属SQLite OS EXCLUSIVE锁确保单个合作实例持有，不靠PID猜测或抢占；锁文件不存业务/凭据，已有未知schema/链接拒绝，进程退出由OS释放。取得所有权后才可进行该根内状态恢复；重启未完成记录转UNKNOWN，不重跑。

宿主停止前通过已认证owner bridge明确请求close-intent。仅无活动/UNKNOWN、无配置不确定及无在途写请求时关闭新的准入并返回ready；pending/协议错误/超时保留服务、连接和所有权，不发送TERM/KILL。ready后仅停止已拥有的子进程并观察退出；启动未完成的新子进程清理仍不接管旧PID。

宿主必须先完成模块关闭，拒绝时不关闭主HTTP、项目工作区、凭据设置或主服务身份。关闭操作可在用户处理状态后重试，不能因一次失败失去退出处理。子entry不能在close拒绝后finally强制exit；主网页入口保留信号处理并显示状态，条件修改tools/browser/service.mjs仅为已批准退出行为接线，不改Host Loop或既有服务配置。

意外owner IPC断开立即关闭新准入，取消本实例已拥有的制作，等待SDK物理idle、业务回执、已受理的配置/材料/桥接请求结束后，才关闭监听和释放该根OS所有权。请求断开不是物理完成凭据。未决记录保留，不自动核对、清预留或重发；重新打开时不从新Runtime空闲推断旧任务结束。已有physical_settled=true的UNKNOWN仍须用户明确核对，随后明确发送新制作。缺物理凭据仍阻断。该意外退出路径不批准更新或版本切换。

RS-VERSION-01：取得独占所有权后、创建业务目录或恢复状态前读取数据根的闭合v1版本标记；固定插件版本/供应提交/协议/data schema必须全部匹配。首次只允许空根，或父启动器建立的空HOME/TMPDIR及已验证所有权文件。非空未标记根、未知字段/版本/坏文件/链接/非普通文件拒绝，不自动收养、迁移或覆盖。首次写入用独占创建、同步和独立读回；中断残留不自动修复。首版未声明前序迁移或降级兼容；后续版本需明确兼容或经验证迁移，不靠新程序自报兼容。

## RS-EXIT-01：三种显式退出选择（当前增量）

对应M07/M09、AC09/10、RUI10，扩展上文最初无制作任务时的增量边界。

- 有活动/停止中/UNKNOWN或在途保存时，原生退出提供“等待完成”“停止制作并等待结算”“取消退出”，默认取消；无未决项正常关闭。普通标签关闭不调用退出控制。
- 等待禁止新制作/资料或关联写入；既有任务继续下一模型/工具步骤，原有逐效果许可/模式仍检查。原生菜单和Studio显示正在等待，可取消退出。取消恢复新准入，但不撤回已发出的停止。
- 停止仅通知本实例持有的主/图片Host及本地导出/预览。逻辑abort受理不等于物理完成；不自动核对UNKNOWN、不退款、不重试、不允许直接版本切换。请求/配置/宿主交付未结算也阻断关闭。
- 私有owner bridge只读生命周期，不把自己的观察请求计为未完工作；closed请求体只允许wait/stop/cancel。未知字段和force等额外权力拒绝。宿主自身在途回传加入阻断。
- 原生等待只观察真实状态，无定时推进；再次读回无未决项并通过原关闭握手才释放宿主/供应服务。状态读取失败则取消这次退出并保留资源，提示用户核对。

RS-LIFECYCLE-02：HTTP断开不证明处理器已完成，但实际处理器完成后也不得永久留在阻断集合。跟踪自身onRequest异步准入与路由处理器的真实完成；客户端断开后仍在处理的配置/材料/导出/回传阻断关闭，待处理器结束才收尾。断开且未进入路由的请求不得随后启动工作。正常响应、错误、断开三条路径使用同一幂等收尾，不用socket.close提前解除实际处理器。SSE只读观察不作为持久业务写入。
