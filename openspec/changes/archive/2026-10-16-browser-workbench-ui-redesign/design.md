# Engineering contract / impact decision

Reuse task JSON in the existing atomic local SQLite store, with an optional append-only `report_content_events` extension. No new DB, table, migration, authority or shared runtime. Grain remains one task/revision; events have command UUIDs, current saved report hash and exact task/source/outcome identity. Missing extension is legacy: no report-content confirmation, old appended USER expressions and analysis judgments retain their meanings. Rollback: preserve database; older code will fail closed on extended records, not silently reinterpret them. Do not downgrade a populated trial database to older code.

Current report is a pure projection from the original immutable outcome plus successful content saves. Original facts/limits remain outside editable interpretation. Content identity covers the exact before/after snapshot, analysis/source/outcome identity and paragraph provenance. Append-only content snapshots prevent changed baselines or legacy history from replaying a saved edit as a no-op and re-numbering it. Legacy appended expressions and previous model discussion rewrites remain inspectable history, never silently adopted as a new confirmed main draft. Save text/findings changes produce a new content version; equal save returns an idempotent receipt without version increment. Confirmation binds full current hash. Neither changes analysis judgment or formal review. Existing history retains old events; new revisions/outcomes start unconfirmed. Commands are serialized by the same store transaction; stale target fails without overwriting. Pending operations recover via immutable command receipts, never automatic replay.

Suggestions use the already declared `report_edit` purpose on the existing Runtime Port, same task accounting/configuration, no tools or new model/data boundary. Persist request before dispatch and completion before publishing. Stop closes publication authority; unknown requests remain fenced until readback/reconciliation, no repeat. Input is only the target saved interpretation, wording instruction and existing source-bound limits; no arbitrary file reads. Applying is explicit, exact target bound, provenance MODEL_SUGGESTION/user adoption. Draft edit invalidates application of pending suggestions in the client as well as server hash checks.

References are task-local UI drafts with stable backend finding IDs or saved report paragraph identity, source snapshot and report-content hash. No DOM row number aliases. Before send the server resolves references against current authorized task state, rejecting stale/mixed task sources. Raw previews without supported stable row identity are read-only. Quote/selection never invokes a model or acquires a grant. Browser drafts/scroll/focus survive shell changes but are not business authority.

Draft cache keys include the actual opaque project identity plus task/new-task identity; ambiguous former global new-task keys are not restored into a selected project. Files stay in memory only. Export reuses the existing numericReportCopy proof formatter with no old explanation text, preserving its complete checked numeric catalog beside the current editable interpretation. Waiting partial writes require actual applicable verified findings and settled latest step events; Application additionally blocks physical pending effects. These are corrections of the approved isolation/locked-fact/partial semantics, not a product revision.

This closes private implementation mechanics under approved proposal §11 and the current user grant; it changes no approved product semantics or safety authority. AgentHarness multi-base structural design is not introduced; all business meanings, version/confirmation invalidation and compatibility obligations are already approved in BUI §§7–9, not a new product approval request.
