## 用户任务、范围与价值

在既有 JuanerAI 分析任务中，用户需要进行品牌／行业外部研究，审阅研究问题与报告框架，了解调查进展、证据与不足，形成可追溯研究版本，并将选定成果保存回原任务。价值验收是“原任务→完整研究→两次有意义确认→受限或完整成果→证据回看→保存副本→返回”，不是单个 API 返回成功。

固定源码 `gadfly-hbo/deep-research@3a3f8c3a910460423a8b7a2638655a100a2aa8e6`，tree `093d72c2f17cb2959cc811dfac0e093cf4b737f2`。插件内研究方法、计划生成、采证、分析、评审与输出沿该版本；宿主提供分发、进程、权限、任务关联、入口／回程和稳定副本。首期只面向个人本机浏览器＋同机服务；没有企业租户、公共服务、自动经营动作或新 Agent Runtime。

覆盖 N12/S4 深度研究子范围，C2-02 为直接研究能力；C1-01、A-05、B-01、B-02、B-03 为来源／权限／运行与证据支撑，C3-01 为宿主体验。这里是准备增量，未把累计能力登记改成实现或验收。完整地图见 `docs/planning/capability-coverage/latest.md`。不启动 N12 全部业务或下一阶段。

## 确定的产品语义

- R01 入口：原任务右上角“深度研究”；没有选定任务时不可进入并提示先选任务。打开时保留原任务的草稿、当前视图和模式；不自动把宿主全部数据发给插件。显示原任务标题及“返回原任务”。一个任务可以有多个研究项目／运行，关联由宿主维护；不同宿主任务不互相看见未授权项目或把副本错存到另一任务。
- R02 原确认：发起研究后先生成问题清单，用户可编辑／增删并确认；再生成框架，用户可编辑标题、章节、目的和要点并确认。两门均可放弃；空问题或空标题不可确认。未决门重开时重新读取当前门，不代确认、不由 body.plan 绕过。确认失效／冲突时读回当前状态，不重复提交旧门。生成计划和框架本身可能调用模型，不能把“尚未采证”当作无需有效任务授权。
- R03 研究推进：六阶段计划、采证、分析、草稿、评审、发布完整保留；进展、调查流、用量、来源、干预、加注、重跑沿固定插件语义。追加来源、预算或干预只在既有有效授权边界内执行；超范围直接说明缺失授权，不静默扩大。此合同不批准具体 Provider、凭据、真实数据、站点或费用。
- R04 结果与证据：`running`、`awaiting-confirmation` 非终态；`published` 为完成运行，`limited` 为有限交付，另有 failed/cancelled。有限交付展示全部 limitations 与 unresolved，正文／推荐／导出／宿主副本均保留；不因为运行结束、引句命中或版本存在就宣称事实充分。原文不可用显式标注，保留来源与历史引用，不伪造核验。
- R05 保存：完成运行→显式发布为研究版本→选择版本→可选生成正式版／导出→保存到原任务，动作不互相替代。研究 version 固定，但插件正式排版文件可再生覆盖；宿主副本按所选版本、实际导出字节／摘要、生成时点、来源身份与限制固定，后续插件重生成不改写旧副本。相同内容重复保存返回原副本；同版本正式产物变更作为不同副本并保留旧副本。保存失败留在原版本，可重试；回复未知先查询同操作，不新建研究或重复发布。原工作区不可用仍可读取已经独立保存的副本。当前审核稿的“保存”仅内存演示，刷新清空，不是磁盘存储证明。
- R06 回程与取消：返回／关闭研究页面不等于取消，不丢未决门；重新打开恢复同一关联与可读状态。取消表示请求受理，实际 stopped/terminal 与在途副作用分开；UNKNOWN 不报告已停止、不自动恢复或重试。恢复须基于保留检查点和当前有效授权。失败显示原因、可读既有结果、查询／重开入口；服务不可用仍能返回原任务。
- R07 记忆与追问：原追问选择器／按钮不可用并解释首期未启用；服务直接请求也拒绝。原宿主自己的任务对话不属于插件 followup，此限制不删宿主现有能力。不装配 sessionCandidates，不生成 sessionDigests；后续单独接入，不利用“缺少候选链”假装禁用了端点。
- R08 情报库完整保留：列表、筛选、检索、链接／文件登记、取得正文、原文与元数据／版本／取得限制、生命周期、更正、复用授权、删除影响确认和项目选择器保留原语义。PROJECT_ONLY、WORKSPACE_REUSABLE、RESTRICTED 不因宿主接入自动升权；需跨任务复用时继续显式授权并留依据。永久删除沿原影响预览和确认，并受宿主效果准入约束；历史研究版本／已有宿主副本不随库更正漂移。真实导入与删除未由本次 UI 准备授权。
- R09 设置：原模型／预算设置界面保留可见能力，集成后的配置写入只影响 deep-research 私有配置，不覆盖宿主主模型链，不允许浏览器明文读写凭据。宿主后端仅显式注入许可 env。配置变化不会自动开始研究；运行／状态未知时不切运行链或换包。原界面需要的主备配置保留，具体可用路由由随后任务授权确定。
- R10 来源与隔离：完整 UI 也须服从宿主任务／材料／效果准入；用户不再另装独立源码仓或全局 Node。产物是研究材料，不自动进入正式 Decision、Report Studio 或 decision-platform；这些消费者留后续接点。

## 用户审核路径与验收标准

1. 选宿主销售任务→深度研究→新建研究运行→编辑问题并确认→编辑框架并确认。分别看到两门；中途可放弃；非空约束可检查。
2. 采证时使用“审核场景”模拟预算耗尽→发布→发布为版本。查看该版本草稿、评审行、证据原文与完整限制；有限交付不得变成完整交付。
3. 在发布列表选择准确版本的“查看草稿”，检查当前版本后“保存所选版本到原任务”→返回。原任务、草稿与模式保留，并显示准确版本／有限交付。重复保存同版本不增加重复副本；切换另一宿主任务不得出现该副本。
4. 使用场景工具检查服务不可用、状态未知、取消未确认、失败、原文缺失及保存失败。场景按钮只用于审核，不进入正式产品。恢复查询不启动新研究。
5. 进入外部情报库和设置检查完整界面是否保留；追问显示不可用。原完整界面中本稿未模拟的写操作明确返回“审核稿未模拟该动作”，不据此缩小正式接入范围。

正式工程接受须覆盖上述 R01–R10 与 design C01–C12 的正反路径、真实源装配、固定包、权限拒绝、稳定副本与离仓运行；真实研究质量另需任务级 Provider／数据授权、用户产品验收。浏览器静态通过不替代 Desktop shell、安装分发、真实 Provider 或来源质量验收。
