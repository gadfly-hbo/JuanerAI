## 核心原则：统一运行护栏，按任务选择自主程度

### P1 自主决策与执行控制分离

模型可以自主分解任务、选择工具，并依据环境反馈调整路线，不要求所有步骤预先写成固定流程。系统持有实际执行、权限、资源限制、取消及结果提交的控制权；业务完成由产品验收判断。自主规划不等于无限权限，也不要求产品自己重写 Pi 的工具循环。

### P2 模式按任务选择，输出按用途校验

固定流程、机器消费的结构化变换适合 Worker；需要动态调查、工具选择或多轮探索的任务适合工具 Agent。两者是可组合的任务模式，不是必须先 Worker 再申请升级的等级。结构化数据须验证 schema 与业务含义；解释、创作和对话不一律强制 JSON。产品定义完成及停止标准，可采用自动检查、证据判断或用户评审；不能自动判定完成的任务不因此一律退回 Worker，也不能仅凭模型自称完成就提交正式成果。

### P3 任务级授权，风险触发确认

在用户确认的任务、资源、动作、外发对象、预算及有效期范围内，允许 Agent 自动执行已预授权操作，不要求每次工具调用弹窗。授权判断仍在每次效果执行前发生；越界、授权撤销或未获授权的动作须停止并请求相应决策。写入、发布、发送、花钱等效果必须有有效授权及必要的幂等/未知效果处理；模型生成的文字不能自行授予权限。具体风险级别由产品定义，共享包不臆造统一业务阈值。

### P4 资源有界，额度按任务配置

模型/工具调用数、输出 token 和墙钟上限必须明确，所有物理尝试计入同一业务任务预算；具体额度按任务需要配置，不固定很小轮数来压制合理探索。达到上限后停止并返回真实状态，不能隐藏重试、换任务 ID 或重启逃避消耗。调用/token/resourceUnits 不是货币账单；金额封顶需宿主计费或 Provider 配额策略。当前同任务配置/限制不可变，不因本原则自动增加续期、动态提额或恢复执行能力。

### P5 运行可追踪，证据按用途与风险保留

每次模型/工具调用保留安全运行记录，能关联任务、运行、实际模型/工具与输入输出引用或摘要；不统一要求所有原始入参、回复、工具结果和内部思考全文落库。正式事实性分析结论需可核查业务证据或明确说明不确定性，普通创作/对话不强制附业务证据链。内容存储、访问及保留期限按产品用途、风险和数据许可定义；引用/hash 本身不证明证据可读或可回放。当前 SDK 的 AuditSink 仍是必需接点，审计失败仍停止运行，持久化由宿主落实；本次不新增关闭审计或忽略失败的选项。

### P6 分层验证，以任务结果和运行不变量验收

回放用于确定性机制、协议兼容和已知故障回归，不是所有 Agent 行为的唯一完成定义。按受影响行为组合正/负向测试、适用的合成回放、消费者回归和任务质量评估；判断任务结果、证据、权限、成本与停止行为，而非要求自主 Agent 每次选择完全相同的合法路径。依赖或策略变化保留关键安全断言和负例。真实 Provider 验证单独授权、按实际启用用途有界进行，不用一次夹具全绿宣称任务能力或产品接入完成。

## 当前 SDK 必须统一的接点与合同

1. 产品业务代码不得 import Pi 包、读取 coding-agent 目录或复用其认证/模型/会话。只允许在本包 Pi Adapter 内直接 import `pi-ai` 与 `pi-agent-core`。插件复用同一 SDK，不复制源码再分叉。
2. SDK `0.3.0` 两包均精确 `0.86.1`。`0.86.x` 是批准系列，不是精确锁定。包内 lockfile 固定开发/验证树；产品必须自己的 lockfile 固定完整安装树。
3. 按任务使用 `runWorker`、`runText` 或 `runAgent`，不规定所有模型接入默认 Worker。`runWorker` 是无工具单次模型阶段、JSON 解析、宿主 validator；`runText` 是无工具文本入口，可选文本 validator；`runAgent` 允许工具自主选择并返回文本，宿主按任务验收。每次物理尝试都授权、计入同一任务账本；无无限循环或隐藏重试。可配置主模型和有序备用，在可分类的供应商故障时有界切换。详见 [v0.2 增量合同](RELEASE-v0.2.md)。
4. 所有模型和工具效果执行前授权，返回结果前再检查发布权限。`write/external` 的授权必须来自宿主已确认或预授权策略，模型文本和工具类别标签本身不构成授权。
5. 同任务 ID 使用同一权威 BudgetStore。模型次数、工具次数、输出 token、累计运行时间必须封顶；resourceUnits 可增加产品资源配额。每次模型请求至少计 1 unit，工具按声明 units 计。额度不是货币账单，更不是承诺 Provider 一定遵守 token 参数。
6. 审计持久化是宿主接入前提。SDK 只发安全元数据与摘要，不把原始 Pi 事件直接写审计，避免 prompt、结果和凭据泄露。事件摘要不是完整取证文件，也不能单凭 hash 重放工具副作用。
7. Agent 行为与依赖变化按 P6 验证；拟启用模型验证与用途匹配的真实交互：单次变换验单轮和输出质量，多轮对话验上下文，工具 Agent 验工具结果消费及任务可靠性。未验证相应能力的模型不能承担该自动任务或进入其主备链。既有独立评审及 MiniMax/Xiaomi 有界合成联调见 [历史记录](../artifacts/review-v0.2/final-review-and-live.md) 和 [Worker 补测](../artifacts/minimax-worker-2026-10-07/REPORT.md)；这些本机证据不包含在历史 tgz 中，也不构成真实产品采用。

## 可配置能力与剩余边界

- `toolExecution` 可选择 sequential/parallel；省略时保留串行。某个工具声明 `executionMode:sequential` 时，Pi 原生规则令整批串行。并行各自授权、计量及审计，不是全批事务；取消或同批失败不能撤销已经开始的效果。
- `thinkingLevel` 可选择 off/minimal/low/medium/high/xhigh/max；省略/off 时不请求启用。所有候选模型须显式声明已验证的 `reasoning:true`。等级的具体映射/预算按 Pi 0.86.1 与 Provider 支持，不承诺各供应商一一对应；签名续接和输出 token 封顶保留，Anthropic budget 模式需至少 2048 输出空间。不支持的候选配置拒绝，不自动关 thinking 来切备用。
- `runText` 已实现；Worker 严格 JSON 合同不变。尚未启用长会话 compaction、跨进程恢复或工具沙箱，仍按真实任务单独补齐。
- SDK 的成功表示运行合同通过，不自动证明任务质量、业务完成或用户批准。任务验收仍由产品落实。
- 本轮保留授权、配额、错误停止与主备护栏；增加能力字段、协议续接块及文本入口。显式新选项纳入同任务配置身份；省略字段保留旧形态。自定义 transport 与回放消费者应核对新增 reasoning 内容分支，不能假定回复只有 text/tool。

## 宿主保留的权威

业务任务/成果状态、工具含义、语义和证据、数据外发许可、凭据、持久化及事务、授权撤销、工具幂等/补偿、进程与网络隔离由产品持有。共享机制不能用模型的结束替代业务完成，不能用内存历史替代业务学习。

公共类型不含 Pi Model/Message/Session/AgentEvent；业务 Port 也不得因接入本包而暴露 Pi 类型。JuanerAI 的 Application/Port 仍通过自己的 Adapter 调用此 SDK；CLI、Desktop、外围插件各自从 composition root 装配。

## 停止、恢复及审计口径

取消/截止时间会立即关闭新准入并拒绝迟到成功结果，但不能强杀任意 JS 函数或撤销外部动作。未结算操作继续占用任务 lease；返回取消不是已经物理停止。`waitForIdle` 仅等待本实例的后台结算，不自动恢复执行。

未知模型请求保留全部预留 token、不自动退款。`usage.outputTokens` 是账本计入额度（含未结算预留），不是恒等于 Provider 实测 token。`usageKnown=false` 表示未取得或无法读取任务账本，零占位不能解释为免费或没有历史消耗。

首版的 memory store 不持久化，进程重启会丢失账本。因此不可用「重启/new Runtime/new taskId」逃避同一业务任务额度；真实产品需稳定任务 ID 和符合协议的持久化原子存储。存量未知副作用必须先由宿主核查，不能自动重放。跨请求写幂等由宿主承担，SDK 的重复 tool-call ID 防护只覆盖单次 run。

SDK metadata 不含原始内容，但 task/model/context 标签也不得夹带凭据或敏感业务内容。SHA-256 不是匿名化，小值可能被猜出；宿主应分类保护审计。合成 record/replay 是独立测试入口，记录完整假数据；禁止用它自动录制真实敏感内容。

thinking 续接块保留内部签名/屏蔽数据，不进入普通审计或最终文本。它们会经过自定义 transport 与授权接点；跨模型时 Pi 可将未屏蔽思考转换为文本上下文，屏蔽块/原签名则被移除。宿主需授权实际外发范围，不能把“审计无原文”误认成“思考不出境”。

## 全局参考的处理

本次同步全局 v1.4：模式按任务选择，不固定业务流程、不增加跨产品模式审批；保留有效授权、有界消耗、安全记录和相称验证。实际产品仍遵守自己的产品、安全与启用授权；不宣布存量迁移。以下具体接法保持：

- 精确版本取代系列范围；真实 Provider Gate 保留，待授权后执行。
- 预算在每次效果前准入，独立定时器负责墙钟；不能仅依赖 `shouldStopAfterTurn`。
- 审计采用中立、安全的元数据，不照搬原始 Pi 全事件；正式内容取证需宿主的授权存储与可读证据引用。
- 不发现本机认证文件，不剥离未知供应商 `<think>` 标签、不自动展开错误 JSON，不套用未经验证的供应商怪癖或长调用默认值。
- 不复写 Pi session/compaction/工具循环；首版不启用会话自动发现、compaction、skills、Shell/MCP 或沙箱。

## 升级与兼容

先固定候选精确版本，阅读该版本 changelog 和导出面，在隔离候选上运行适用的回放、正/负向检查、打包及受影响消费者验证；涉及任务能力时补任务评估。通过后交付新 SDK 版本，各产品自行采用，保留旧精确版本回滚。不得自动升级全部产品或为了包统一抹平已有业务合同。公共契约/安全边界变化说明影响并交用户决定；纯内部修正不新增跨 Controller 审批。本次制作新的 0.3.0 包，历史冻结包保持原样。
