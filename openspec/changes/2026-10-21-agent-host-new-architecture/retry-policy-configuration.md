# 可配置工具纠正与共享故障恢复（2026-10-27）

用户前向批准：工具最多五次纠正机会，第六次错误停止；Provider 故障额外请求上限三次，可配置。与此前一次恢复及一次工具纠正合同的差异仅适用于本轮新固定候选的新任务，历史值、旧任务、UNKNOWN、消费和预留不迁移、不清零。

## 合同与工程决定

- 正常入口现有 `analysis` 配置增加可选 `toolCorrectionLimit`（整数0..5，默认5）和 `modelRecoveryLimit`（整数0..3，默认3）。启动时封闭校验；首请求前经 Profile 传给同一 Adapter/SDK，并进入配置身份。主动 Runtime 和被动读回使用同一固定工具策略。
- 工具纠正保留 SDK 既有按工具、任务/用途持久归属；成功调用、重开和 Fork 不补充额度。模型自行使用错误反馈选择下一动作，宿主不改参、不重放工具。权限、撤权、取消、账本/审计失败、未结算与 UNKNOWN 的停止规则不变。
- 故障恢复仍只有 SDK 一份持久 work 账户。单链 `modelRecovery.extraAttempts` 与跨用途/运行/子 Agent 的 `work.limit` 同时生效，默认3；备用与适用恢复请求共用，正常下一步不占故障槽且照常计量。C+U+R≤limit；G 为历史。可信 not-sent 核销仅释放对应预留，原失败链仍停止，其他合法正常链按剩余额度准入。
- SDK 仅拓宽既有数值合同及校验/持久读回，不新增持久结构、宿主计数、调度器、恢复平台或兼容链。默认工具策略仍1以保留其他消费者；JuanerAI 明确选择5。既有0/1输入仍按原值执行。
- native retry 保持关闭；压缩恢复算法、修订/重审次数、模型用途/接收方、32768/16384输出、模型600秒、工具300秒、命令软120秒、控制30秒及累计不封顶/持久计量均不变。
